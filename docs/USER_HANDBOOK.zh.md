# Plethora 用户手册

**掌握渐进阅读和间隔重复的完整指南**

---

## 简介

### 什么是Plethora？

Plethora 是一款功能强大的学习应用程序，结合了两种经过验证的技术：

**增量阅读** - 随着时间的推移，以可管理的小块的形式处理大量信息。您不必从头到尾阅读文章，而是提取要点并逐渐建立理解。

**间隔重复** - 以科学优化的时间间隔复习材料，以最大程度地保留内容。 FSRS-7 可以预测您何时会忘记并及时安排复习。

### 关键概念

- **文档**：源材料（PDF、EPUB、文章、视频）
- **摘录**：您从文档中摘录的要点或部分
- **学习项目**：根据摘录创建的抽认卡或问答卡
- **队列**：计划审核的项目，按优先级组织
- **复习**：您积极回忆并评价您的知识的课程

## 开始使用

### 首次发布

当您首次启动 Plethora 时，您将看到 **仪表板** 包含四个主要部分：

1. **队列** - 您的审阅队列（一开始为空）
2. **审查** - 积极的审查会议
3. **文档** - 您的文档库
4. **分析** - 进度统计

### 初始设置

1. **选择主题** - 导航至设置 → 外观 → 主题
   - 147 个可用内置主题（26 个现代主题，121 个传统主题）
   - 尝试“Modern Dark”或“Material You”以获得现代外观

2. **配置复习设置** - 设置→学习→算法
   - **算法**：FSRS-7（生产调度程序）
   - **所需保留**：90%（默认）- 目标是您想要记住的程度
   - **每天学习**：建议初学者学习 20-50 项

3. **设置类别** - 设置 → 类别
   - 为不同主题创建类别（例如“编程”、“科学”、“语言”）
   - 类别有助于组织和过滤您的学习材料

### 你的第一个文档

让我们导入您的第一个文档：

1. 单击侧栏中的**文档**
2. 单击“**导入**”按钮（右上角）
3. 选择您的导入方式：
   - **本地文件**：选择 PDF、EPUB 或文本文件
   - **URL**：粘贴任何网址
   - **Arxiv**：粘贴研究论文 ID 或 URL
4.等待处理
   - 如果在“设置”中启用自动分割，则导入后文档将自动分割为摘录

### 导入文档

#### 方法一：本地文件

1. 点击**文档** → **导入**
2. 选择**本地文件**
3. 导航到您的文件并选择它
4. Plethora 将：
   - 提取文本内容
   - 计算阅读时间和字数
   - 提取元数据（标题、作者等）
   - 如果启用自动分段（设置 → 文档 → 导入时自动处理），自动将文档拆分为摘录

#### 方法2：URL导入

1. 复制任意网址
2. 单击**文档** → **导入** → **URL**
3. 粘贴网址
4. 单击**导入**
5. Plethora 获取并处理内容

**支持的网站：**
- 新闻文章（大多数主要网站）
- 博客文章
- 文档页面
- 介质、子堆栈等

#### 方法 3：Arxiv 论文

1. 找到一篇 Arxiv 论文（例如，`https://arxiv.org/abs/2301.07041`）
2. 复制 URL 或论文 ID (`2301.07041`)
3. 单击**文档** → **导入** → **Arxiv**
4. 粘贴 URL 或 ID
5.大量下载：
   - 完整的PDF
   - 摘要
   - 作者
   - 出版日期
   - 参考文献

#### 方法 4：JSON Deck 导入

从 JSON 文件导入抽认卡组，其中包括日程安排数据（间隔、轻松因素、复习历史记录）。

**通过文件选择器导入：**

1. 点击**文档** → **导入** → **JSON**
2. 选择您的“.json”甲板文件
3. Plethora 创建一个牌组文档并导入所有牌，保留：
   - 日程安排（间隔、轻松因素、截止日期）
   - 回顾历史（重复、失误、保留率）
   - 卡状态（新卡、正在审核或已暂停）

**通过拖放导入：**

将“.json”文件直接拖到应用程序窗口上。如果文件与预期的牌组格式匹配，则会自动导入。

**JSON 甲板格式：**

该文件应该是将问题文本映射到卡片数据的平面对象：

```json
{
  “细胞的动力源是什么？”：{
    "answer": "线粒体。",
    “主题”：“生物学”，
    "deck_name": "细胞生物学",
    “轻松系数”：2.6，
    “间隔天数”：7，
    “重复次数”：3，
    “due_at”：“2026-04-20T12:00:00Z”
  }
}
````

**注释：**
- 每个“.json”文件都会创建一副牌。卡组名称来自“deck_name”字段。
- 导入卡默认使用 Plethora Classic 算法。您可以在导入后切换算法。
- 两次删除相同的文件不会创建重复项 - 现有的卡将被跳过。
- 标记为“known_pile: true”的卡将作为暂停导入。

#### 摄入气闸和 Chapter/H2 预分块

当在 **Needs Review** 中暂存传入的浏览器剪辑或长文档时，请单击 **Airlock Triage** 在材料淹没您的活动队列之前路由材料：
- **`[1]`活动课程高优先级（`P10`）**：立即排队进行紧急学习。
- **`[2]` 常绿低优先级 (`P65`)**：安排到正常增量摄入。
- **`[3]`仅供参考的保管库（`P95`，已存档）**：存储供参考/搜索而无需输入您的到期 SRS 队列。
- **`[C]` 按章节/H2 标题进行预块**：将 Markdown (`## ` / `# `) 或 HTML (`<h2>` / `<h1>`) 文档拆分为继承所选层优先级的有序子部分。

**示例：** 导入 3 节 Markdown 文章（`## 共识基础知识`、`## 领导者选举`、`## 日志复制`），并启用 **按章节/H2 标题进行预块**，并按 `1` 在优先级 10 上创建 3 个标题部分。

## 学习系统

### 了解 FSRS-7

**FSRS-7**（自由间隔重复调度程序，版本 7）是 Plethora 的生产抽认卡调度程序。它使用**双跟踪**内存模型扩展了早期的 FSRS 版本：

1. **双轨迹内存状态**：每张卡跟踪两个稳定性轨迹 - 用于长视野保留的**慢轨迹**（`stability`）和用于短视野回忆动态的**快轨迹**（`stability_fast`）。 **可恢复性**是根据两条迹线的混合计算的，而不是单独根据单个稳定性值计算的。
2. **分数经过时间**：对评论之间的当天和部分天的间隔进行精确建模（不四舍五入到整天），因此短间隔后的间隔更准确。
3. **34参数模型**：使用FSRS-7权重向量；当您有足够的数据时，个人优化器可以将这些内容适合您的评论历史记录。
4. **四按钮评级**：再次/困难/良好/简单（评级 1-4），每个选择都有预览间隔。

**关键指标：**
- **稳定性**（慢速跟踪）：长视野记忆强度（越高=更稳定）
- **稳定性（快速）**（快速跟踪）：短视野回忆动态与慢速跟踪配对
- **难度**：该项目对您来说有多难（1-10 级）
- **可检索性**：当前召回概率 (0–100%)，源自双迹模型

### 了解 SM-18

**SM-18** 是该系列中的上一代调度器。它代表了 SM-2 的重大演变，引入了内存稳定性建模和数据驱动的区间计算方法。

SM-18：

1. **模型呈指数遗忘**：使用公式“R = 0.9^(t/S)”来计算可提取性——考虑到稳定性“S”，您在时间“t”记住一个项目的概率
2. **独立跟踪难度**：为每个项目维护一个难度值“D ∈ [0, 1]”，使用跟踪平均公式进行更新，该公式随着每次重复而变得更加敏感
3. **使用 3D SInc 矩阵**：从按分档难度、稳定性和可检索性索引的 21×21×21 矩阵中查找稳定性增加因子 - 这是 SM-18 智能的核心
4. **优雅地处理失误**：失败时，将稳定性降低 0.87 倍（进一步除以累计失误）并重置重复计数器，但保留难度估计
5. **根据稳定性计算间隔**：从所需的保留目标导出下一个审核间隔：`间隔 = S × ln(1-FI) / ln(0.9)`

**关键指标：**
- **稳定性 (S)**：记忆在衰退之前持续的时间（以天为单位）
- **难度 (D)**：从 0（最简单）到 1（最难）的值，在每次审核后通过跟踪平均混合进行更新
- **可检索性 (R)**：当前召回概率，计算方式为 `0.9^(elapsed/S)`
- **SInc**：从 9,261 个条目矩阵中查找的稳定性增加因子 - 每次成功审核后稳定性增加多少
- **失误**：失败次数，这会影响后续失误的未来稳定性

### 了解 SM-20 和算法领域

Plethora 的 **SM-20** 选项是一个 **算法竞技场** - 一种独立的集成实现，在每个抽认卡上并行运行 **五个** 间隔重复算法，并将它们的预测混合到一个时间表中（与纯单内核 SM-20 模式不同）。五名竞争对手的默认混合权重为：

|插槽|型号|默认重量 |怎样学？ |
|------|-------|---------------:|-------------|
| 1 | **SM-2** | 6% |固定|
| 2 | **SM-15** | 14% |持续不断地，在每次审查中|
| 3 | **SM-19** | 45% |持续不断地，在每次审查中|
| 4 | **SM-20**（35 参数“M4”遗忘曲线内核）| 25% |按需，通过“优化”按钮 |
| 5 | **FSRS** | 10% |按需，通过“优化”按钮 |

**混合如何工作。** 每个模型独立地生成卡的稳定性估计；竞技场采用加权平均值并从中得出下一个间隔。权重不是固定的——它们**适应你**。每次你回顾一张之前回顾至少一天前的卡片时，Arena 都会根据实际发生的事情（你记得或忘记）对每个模型的“之前”预测进行评分，并将权重推向最能预测你的模型。没有任何模型会被完全淘汰，因此启动缓慢的模型可以恢复。

**学习的两种方式：**

1. **每次审核时自动** - SM-15 优化器和 SM-19 矩阵立即更新，并且混合权重发生变化。这从您的第一次评论开始。您可以在“设置”→“学习”中观看：**Arena 权重**面板显示每个模型的当前百分比，一旦您有足够的评分评论，就会显示**R-Metric**（混合预测比单独的 SM-19 好多少）。
2. **按需，当您单击“优化”时** — 五个竞争对手中的两个（SM-20 内核和 FSRS）可以适合您的个人评论历史记录。这些拟合受到最少量的数据（大约数百天间隔的评论）和保留的验证检查的限制：只有当它真正击败了拟合尚未见过的评论的默认值时，拟合才会被接受。在此之前，“优化”按钮会报告“尚未足够的审核历史记录”，并且这两个模型将继续使用其默认参数。

**为什么它可能会说它还没有开始训练。** 只有间隔至少**一天**的评论才带有信号——首次评论和当天的重新评论不会告诉竞技场任何信息（每个模型都会正确预测你会记得），因此它们不计入总得分。如果您只有少量卡牌，则预计竞技场权重将保持在默认值附近，并且 R 度量将保持隐藏状态，直到这些卡牌开始按天间隔返回。这是预期的，不是错误。

**关键指标：**
- **稳定性（S）**：每个模型对记忆持续时间（天）的估计；竞技场融合了这些。
- **难度 (D)**：每个模型的项目难度估计。
- **竞技场权重**：每个模型的实时混合百分比，显示在学习设置中。
- **R-Metric**：混合相对于单独的 SM-19 的相对改进，根据您的评论的衰减窗口计算。

**SM-20（算法竞技场）与 FSRS-7 有何不同：**
- FSRS-7 是单一生产调度程序，也是学习设置中显示的唯一选项。
- SM-20（算法竞技场）是一个传统的实验集合，它将五种算法相互竞争，并让您自己的数据选择混合（而纯 SM-20 模式仅直接运行 M4 内核）。它保留在代码库中以供研究，但对调度程序选择器隐藏。

#### SM-20 审查后选择内存范围

在**设置→学习→算法竞技场→每次评级后**下，选择您想要的调度详细信息：

- **保持流程（推荐）** 立即提交竞技场的加权选择并移至下一张牌。这是默认设置。
- **显示竞技场**在符合条件的评级后暂停并打开**记忆地平线**，您的答案仍然可见，而五位模特将显示他们将在哪里进行下一次评论。

同样的紧凑选择出现在六个 SM-20 评级控件下方，因此下一个评级可以使用不同的模式而无需离开评论。两种模式都运行和训练相同的五个收集模型；仅当您做出最终间隔选择时，此设置才会发生变化。决策步骤仍然仅限于正常的 SM-20 抽认卡审查；文档阅读、补习模式、其他算法和**纯 SM-20 模式**保留其现有的直接调度流程。

- 默认情况下选择**竞技场选择**。这是加权推荐，通常是您希望竞技场做出决定时的最佳选择。
- **SM-2、SM-15、SM-19、SM-20 和 FSRS** 让您可以特意遵循某一型号的具体建议进行本次审查。选择一个模型并不会给该模型带来额外的投票权重；未来的权重继续仅从预测准确性中学习。
- **自定义**接受对数时间透镜上的数量和单位或位置。显示的界限可以防止无效的计划，并且在您确认之前更新确切的截止日期。
- **为什么这个间隔**扩大了提案、当前权重和竞技场范围。该范围是五个模型提出的最早到最新的区间，而不是不确定性或置信区间。

在您按下 **安排......** 之前，不会提交任何内容。如果预览变得陈旧或保存失败，该卡将保留在原位，并保留您的成绩和选择，以便您可以安全地重试。 **返回评分** 放弃待定的评分并让您重新选择。

### 文档阅读时间表（渐进阅读）

FSRS-7 是 **抽认卡** 调度程序 - 它在问答、完形填空和基本卡片上进行训练，其目标是长期回忆。 （SM-18 和 SM-20 等传统调度程序保留在代码库中，但在 UI 中隐藏。） **文档**（您通过增量阅读阅读的文章、论文和段落）由 **修改的 FSRS-7**（*Engaging* 调度程序）进行调度，以实现不同的目标：保持内容定期轮换，而不是最大限度地长期保留单个事实。它在自己的 FSRS 实例中运行，与您的抽认卡调度程序分开，因此您在 Schedule 视图中看到的文档的 **稳定性**、**稳定性（快速）** 和 **难度** 值是真正的 FSRS-7 内存参数。

**有两个调度轨道，而不是一个。** 这是造成混乱的最大来源：

- **抽认卡** → FSRS-7（学习设置中的生产调度程序）→ 写入训练 FSRS 优化器的复习历史记录。
- **文档** → **修改的 FSRS-7**（*Engaging* 调度程序，在您对应用程序中的文档进行评分的任何地方使用；固定间隔 *增量* 调度程序仅用作 API/MCP 的后备）→ 单独跟踪，并且 **根本不提供抽认卡调度程序。**

对文档进行评级使用**与抽认卡相同的四个按钮** — 再次/困难/良好/简单 — 但评分会转到 **单独的** FSRS 实例，该实例不会训练您的抽认卡算法。它产生的间隔取决于哪个调度程序处理评级：

- **参与 FSRS-7（应用程序使用的那个）。** 当您对队列或文档查看器中的文档进行评分时，Plethora 以 0.9 目标保留目标运行 FSRS-7，然后应用有界*参与*乘数 (0.25×–2.0×) 以获得新颖性、多样性和偶然性。间隔是 FSRS 计算的，因此**可变** - 它们随着文档的双迹稳定性而增长，就像卡片一样，而不是下面的固定值。对于您只阅读了部分内容的长篇内容，持续时间感知上限会根据您实际阅读的文档量将“好/简单”间隔拉回到 1-4 天。
- **增量阅读调度程序（后备）。** 普通 API/MCP 评级路径使用单独的非 FSRS 调度程序，具有较短的**固定**间隔和 30 天的硬性上限：

|评级 |增量（回退）间隔 |抽认卡间隔（因算法而异）|
|--------------------|---------------------------------|------------------------------------------------------|
| **再次** |约 4 小时 |分钟|
| **硬** | ~1 天 | 1–2 天 |
| **好** | ~3 天 |几天-几周 |
| **简单** | ~7 天 |周 |

在后备调度程序中，连续的 Good/Easy 评级会增加一个小的奖励，连续的 Again/Hard 评级会增加一个小的惩罚，并且间隔的上限约为 **30 天**，因此材料会保持轮换。 （您从队列中选择的参与 FSRS-7 路径没有固定的 30 天上限 - 它唯一的上限是上面的持续时间感知上限。）

**参与度会影响顺序和间距。** 参与度层会做两件事：它决定接下来出现的*哪个*文档（新颖性注入、多样性平衡、意外发现），并在 0.25×–2.0× 范围内缩放 FSRS-7 间隔。它位于 FSRS-7 数学之上；它不会取代它。

**实用要点。**文档审查通过其**自己的** FSRS-7 实例运行并单独跟踪 - 他们**不**训练抽认卡 FSRS 优化器，该优化器仅从抽认卡审查中学习。如果您想要个性化的 FSRS 权重，则需要按日刻度间隔查看抽认卡。

### 复习策略

#### 日常回顾

1. **上午课程**（15-30 分钟）
   - 审查隔夜到期的卡
   - 专注于较难的项目

2. **晚间课程**（15-30 分钟）
   - 白天添加的复习卡
   - 通过阅读创建新卡片

- **理解问题**：如果重复多次，卡片可能写得不好

- **移动队列人体工程学**：在手机布局上，使用**通勤音频队列**开关、单手**底部拇指弧**底座（“再次”/“困难”/“良好”/“简单”和“提升优先级（-10）”/“推迟（+10）”），并**双击任何预览段落**将其直接捕获到桌面收件箱。

### 优先系统

每个文档、摘录和卡片都位于**单排序列表**中的某个位置 - 一个队列，所有元素类型在一起。优先级是排名。对某个项目设置优先级是告诉 Plethora *它属于您的收藏中的哪个位置*，而不是为其附加分数。

**优先级是一个位置，而不是标签。**

这就是优先级队列模型，也是数字如此表现的原因。当您将某个项目设置为 70% 时，它会移动到您收藏中的 70%——高于您拥有的所有物品的大约 70%，低于前 30%。没有其他内容被重新编号；该物品只需插入即可。

对任何项目设置优先级 0-100：

- **90-100**：几乎高于一切——你首先想要的少数东西
- **70-80**：集合的上部
- **50-60**：包装的中间（新材料的默认值）
- **20-40**：下半部分——最终阅读它
- **0-10**：队列底部 - 参考、存档、有一天

**1–5 重要性评级。** 某些视图还在项目旁边显示紧凑的 **1–5** 重要性评级。该数字只是将 0–100% 滑块分为五个频段 — **5 是最高**（81–100% 范围），1 是最低。因此，设置为 100%、显示“优先级 5”的文档显示的是等级的*顶部*，而不是第五位。 1-5 评级不包含滑块之外的任何信息；滑块本身（以及实时*位置 X 的 N* 读数）始终是事实来源。

**你的百分比会自行变化，这是正确的。**

因为百分比的意思是“目前为止*在集合中*”，所以它会随着周围集合的变化而变化。导入 500 篇新文章并对其中一半给予高度评价，而未修改的旧文档将显示比上周更低的百分比 - 不是因为您将其降级，而是因为现在有更多材料位于其上方。相对于已经存在的所有内容，它在您的阅读顺序中的实际位置没有变化。

一个固定的数字会悄悄地欺骗你：在 100 项集合中设置的“70”和在 10,000 项集合中设置的“70”声称意味着相同的事情，但描述完全不同的位置。该百分比告诉您当前收藏的真实情况。

**N 的位置 X**

打开任何项目上的优先级弹出窗口，它会在滑块下方显示其实时排名 - *位置 1* 是您收藏中最重要的元素，*位置 N* 最不重要。一次大的导入后重新打开它，你会看到位置发生了变化。每次您打开该读数时，都会重新查看它。

**没有两个项目共享一个位置。**

将多个项目设置为相同的百分比不会将它们堆叠在一个点上 - 每个项目都放置在最后一个项目之后，因此队列保持严格的顺序。将 200 个文档批量设置为 60% 会将所有 200 个文档按顺序排列在 60% 附近，而不是创建 200 路平局，队列稍后必须任意中断。

**优先调度：**
优先级较高的项目在混合评论中显示的频率更高。优先级决定了“重要性”——当材料多于时间时，你首先要做的是什么。它与 FSRS 调度是分开的，FSRS 调度控制*时间*——给定项目下一次到期的时间。严重逾期的低优先级卡仍可能先于昨天审核的高优先级卡出现。

**摘录继承自其文档。** 新的摘录从其源文档的优先级开始，更改文档的优先级会影响到仍保留旧值的摘录。一旦您手动设置数据提取的优先级，它就会停止继承并保留自己的位置。

### 队列排序和重新排序行为

了解队列如何对项目进行排序以及位置变化的原因有助于您优化学习流程：

1. **FSRS 调度和动态优先级评分**：
   - 每个项目的位置是使用其 FSRS 内存参数（截止日期、间隔、稳定性、稳定性快速、可检索性衰减）结合您选择的智能队列策略或自适应排名预设（*最大化保留*、*积极追赶*、*最小化时间*、*探索*、*深度工作冲刺*、*疲倦/移动通勤*、*无情分类*或*平衡发现*）来计算的。对于文档，这些参数来自[文档阅读计划](#document-reading-schedule-incremental-reading) 下描述的 *Engaging* FSRS-7 调度程序 - 所以，FSRS 内存值适用于文档和卡片。唯一的区别是文档的 FSRS 审核是单独跟踪的，并且不会训练抽认卡调度程序。有关完整详细信息，请参阅下面的[智能队列和自适应排名 (DAQE)](#smart-queues--adaptive-ranking-daqe)。
   - 当您完成审阅、推迟项目或做笔记时，内存参数会更新，项目在返回队列时自然会重新排名。

2. **加权选择随机化**：
   - 从后端提取项目时，审核引擎应用微妙的加权衰减算法（默认情况下“随机性 = 0.3”）。这使得具有相似优先级的项目接近顶部，同时引入轻微的变化以避免排队疲劳。

3. **状态同步**：
   - 执行队列修改操作（例如归档文档、批量编辑优先级或修改标签）会在返回队列视图时触发后台刷新，以保持列表与后端数据库状态保持一致。
   - 被动视图更改或选项卡切换保持稳定的本地顺序，而不会触发意外的重新洗牌。


### 神经回顾（“走向神经”）

神经复习是一种可选的探索模式，灵感来自“学习：神经”概念。它不是按顺序处理优先级队列，而是通过从单个起点（您当前正在阅读的项目）**传播激活**并显示与之相关的所有内容来构建新的审阅序列。当你想要在你的收藏中遵循一条线索而不是苦恼于到期的事情时，可以采用这种模式。

**如何使用它。** 在滚动模式下阅读时，单击顶部栏中的 **Go Neural**。会话切换到以当前文档、卡片或摘录为种子的传播激活队列；位置药丸变成紫色并显示“神经审查·剩余 N”。单击 **退出** 以返回到您阅读时的确切位置 - 神经审查永远不会改变您的优先级队列或调度。当队列不足时，它会自动从您刚刚完成的元素中重新填充。

**抽认卡和摘录仍然需要评级才能前进**，就像在正常滚动模式下一样，因此神经会话仍然有助于安排。文件自由推进。

**它如何决定什么是“相关的”。** 激活通过五种连接从种子向外传播，顺序如下：

1. **概念组（标签）。** 与种子共享标签的项目被视为概念对等项。因此，标记具有双重用途：它对搜索项进行分组*并*提供神经审查。未标记的项目没有概念对等项。
2. **元素间引用。** 显式交叉引用链接（如果存在）。
3. **后代。** 种子在知识树中的子级 - 文档中的摘录和卡片，摘录中的卡片。
4. **语义相似性。** 当您为 RAG 索引集合时（设置 → 嵌入和 RAG → 索引集合），神经审查还会显示内容与种子嵌入相似的文档。更多类似的文档出现得更快。如果您还没有建立索引，这个来源就会保持安静 - 其他四个来源仍然有效。
5. **父级和兄弟姐妹。** 种子的父级（摘录所在的文档）及其兄弟姐妹（同一文档中的其他摘录、同一摘录中的其他卡片以及附近的文档）。

更紧密的联系——直接子项、几乎相同的文档、共享标签——在队列中较早出现。当第一波产生的项目少于二十个时，激活会通过新到达的元素的邻居向外扩展，直到队列已满或没有其他可到达的元素。

**提示：**
- 标记您想要一起探索的项目 - 标记成为神经审查将遵循的概念组。
- 为您的收藏建立索引以解锁语义发现；没有它，神经审查仅依赖于树结构和标签。
- 神经审查对于您的正常队列是只读的。自由使用；您的优先顺序或截止日期没有任何变化。


### 智能队列和自适应排名 (DAQE)

Plethora 中的智能队列结合了两个互补的系统：**保存队列**（过滤*哪些*项目属于学习会话）和**自适应排名**（由动态自适应队列引擎或 **DAQE** 提供支持，计算候选项目出现的最佳*顺序*）。

#### 保存的队列（过滤和范围）

通过按类别、元素类型、评级或优先级范围过滤集合来创建自定义重点队列：

**队列示例：**
- “今日焦点”：主要类别的应得卡
- “快速复习”：简单卡片，优先级 < 50
- “深入研究”：研究类别的硬卡
- “考试准备”：“生物”类别中的所有卡片

**创建保存的队列：**
1. 在 **队列** 视图中，单击标题中的 **已保存队列** 下拉菜单（或单击工具栏中的 **已保存队列**）。
2. 单击“**新建队列...**”（或单击“**自定义会话**”并选择“**另存为新队列**”）。
3. 设置所需的过滤器（类别、标签、项目类型、优先级阈值、会话持续时间）。
4. 输入名称并保存队列。

**切换和管理已保存的队列：**
- 使用队列标题中的 **已保存队列** 下拉选择器、**已保存队列** 工具栏按钮或命令面板（`Ctrl/Cmd+K` → 搜索您的队列）在已保存队列之间立即切换。
- 单击下拉列表中的 **管理队列...** 以重命名队列、删除队列或设置默认队列。

---

在 **设置 → 智能队列 → 队列订购模式** 中选择 **严格手动**，以按已保存的 0–100 优先级对符合条件的商品进行订购。同等优先级按到期时间排序，然后按项目类型和 ID 排序。已保存队列过滤器和最佳会话组合仍然控制可以显示哪些项目。显式优先级零是最低值。启用自动恢复后，严格手动最多可保留 50 个未完成的活动项目，并保护 70 及以上的优先级，即使超出容量也是如此。

#### 自适应排名（动态自适应队列引擎）

虽然过滤器决定*成员资格*（进入会话的内容），但自适应排名决定*顺序*（您现在应该阅读的内容）。

自适应排名不是仅根据逾期状态或静态优先级编号对项目进行排名，而是根据记忆紧迫性、与当前学习目标的一致性、认知能量适合性、主题交错和过去的阅读摩擦来实时评估候选项目。

> [!重要]
> **自适应排名仅管理顺序，从不管理安排。**
> 旋钮和预设永远不会改变 FSRS 稳定性、难度、间隔、可检索性或截止日期。调度程序仍然确定物品“何时”返回；自适应排名只是决定您当前的座位中*哪个到期项目首先出现*。

##### 5 项综合评分公式

每次队列重新排序时，DAQE 都会为每个候选项目计算确定性综合得分 $S(i)$：

$$S(i) = w_{\text{srs}} \cdot R_{\text{srs}}(i) + w_{\text{目标}} \cdot M_{\text{相关性}}(i) + w_{\text{fit}} \cdot M_{\text{energy\_fit}}(i, K_{\text{energy}}) - w_{\text{interleave}} \cdot P_{\text{交错}}(i, H_{\text{最近}}) - w_{\text{摩擦}} \cdot P_{\text{摩擦}}(i)$$

在应用其权重之前，每个项都被归一化为单位区间 $[0, 1]$，以防止任何单个因素默默地占主导地位：

1. **内存紧急度 ($R_{\text{srs}}$)** 为 $0.8T + 0.2P$，其中 $T$ 是时间紧急度，$P$ 是自适应优先级信号。桌面 DAQE 使用项目在库中的优先级（如果可用），并且可以回退到其保存的滑块或旧评级。严格手动使用保存的 0-100 值进行演示。
   - **阅读轮换**（文档和摘录）使用截止日期。新项目以中性紧急程度开始。未来项目的时间紧迫性为零。
   - **回忆**（抽认卡）还考虑调度程序的估计可检索性。对于到期卡来说，时间紧迫性要高于召回风险和逾期准备程度。
   - 逾期准备情况随着时间的流逝而平稳增长。十四天是曲线的时间常数。第 14 天没有截止日期。
2. **目标相关性 ($M_{\text{relevance}}$)**:
   衡量主题与您当前的**会话目标**的一致性（例如*“量子计算基础和纠缠证明”*）。分三级评价：
   - *第 1 层（测量）*：来自连接的 AI 决策模型的连续 0-1 分数（`evaluateScore`）。
   - *第 2 层（估计/默认）*：当没有活动的决策模型时，目标和项目文本之间的本地词汇关键字匹配。
   - *第 3 层（标签亲和力）*：未指定目标时基于标签的相关性混合。
   - 还吸收当您积极参与同一知识集群中的相关材料时获得的“集群晋升提升”。如果不存在目标或信号，则该术语明确报告“未测量”(0.0)。
3. **能量适合度 ($M_{\text{energy\_fit}}$)**:
   衡量项目的认知复杂性与目标能量水平 $K_{\text{energy}}$ ($1\text{--}5$) 之间的接近程度：
   $$M_{\text{能量\_fit}} = 1 - \frac{|\text{ItemComplexity}(i) - K_{\text{能量}}|}{4}$$
   项目复杂性按决策模型分类（*表面撇去* = 1、*中度分析* = 3、*深层基础* = 5）或按元素类型默认确定（文档 = 4、提取 = 3、抽认卡 = 2）。
   *疲劳下调*：如果您在过去 30 天内的阅读速度低于基线的 40%（超过 $\ge 5$ 会话），DAQE 会自动将有效能量目标下调至较轻的材料，以防止认知倦怠。
4. **主题多样性惩罚（$P_{\text{interleave}}$）**：
   根据最近的评论历史记录窗口 ($H_{\text{recent}}$) 计算主题和语义相似度。较高的“interleavingDiversity”会惩罚与您刚刚查看的项目共享标签或概念的项目，从而鼓励交错练习。没有主题重叠的项目将受到零处罚。
5. **阻力惩罚（$P_{\text{摩擦}}$）**：
   从记录的交互中累积阻力点：
   - 多次推迟（每次+0.10，上限为4次）
   - 快速跳过（每次+0.10，上限为4）
   - 废弃的评论（每条 +0.15，上限为 3）
   - 空闲主导（空闲停留时间超过总时间的 50%，无交互，贡献高达 +0.35）
   你一再回避的项目会被温和地降级，出现保留或分割的机会。未计量的项目零罚金。

##### 六个排名旋钮

您可以在 **设置 → 智能队列** 或通过 **自定义会话** 模式微调排名公式的每个维度：

|旋钮|范围 |默认 |目的|
|---|---|---|---|
| **内存紧迫性** (`srsDecayWeight`) | `0.00`–`1.00` | `0.40` |逾期和有风险的项目被拉到顶部的程度如何。 |
| **目标相关性** (`goalRelevance`) | `0.00`–`1.00` | `0.30` |与您的活动会话目标相匹配的项目向前推进的强度。 |
| **能源目标** (`energyTarget`) | `1`–`5`（整数）| `3` |您的目标认知深度（1 = 轻度浏览，5 = 密集的主要来源）。 |
| **主题多样性**（`interleavingDiversity`）| `0.00`–`1.00` | `0.20` |为了促进多样性而减少重复主题的程度。 |
| **修剪**（`修剪侵略性`）| `0.00`–`1.00` | `0.10` |严重跳过和推迟的项目会受到怎样的惩罚。 |
| **离开超时** (`afkIdleTimeoutMs`) | `15`–`120` 秒 | `45` s |驻留跟踪暂停之前的不活动阈值并将时间标记为空闲。 |

每个滑块调整都会立即生效，无需“应用”按钮。

##### 精选预设

预设是六个旋钮的预先配置的矢量。您可以从“队列”工具栏下拉列表或“设置”中切换预设：

- **深度工作冲刺**：能量目标“4”，目标相关性“0.50”，主题多样性“0.10”。专为集中研究密集的主要来源而量身定制，主题切换最少。
- **疲倦/移动通勤**：能量目标“2”，内存紧迫度“0.20”，主题多样性“0.40”。呈现短小、低摩擦的项目和各种主题，适合通勤阅读或低能量会议。
- **无情分类**：修剪`0.60`，内存紧迫性`0.40`。将避免和推迟的项目放在前面，迫使做出明确的决定：保留、分成较小的摘录或删除。
- **平衡发现**：内存紧迫性“0.35”，目标相关性“0.25”，主题多样性“0.25”，修剪“0.15”，能量目标“3”。平衡保留、目标和多样性的公平默认设置。

*归因诚实*：仅当您的旋钮与其定义完全匹配时，UI 才会显示预设名称。如果您轻推滑块，徽章会平滑过渡以指示自定义设置。

##### 决策模型和本地优先隐私

自适应排名可以选择连接到实现轻量级**System One**评估协议的人工智能决策模型（“evaluateScore”、“evaluateChoice”、“evaluateNoul”）：

- **无（确定性本地回退）**：默认值。无网络请求，零代币成本，100%离线。使用本地关键字匹配来实现目标和项目类型复杂性启发法。
- **Spine**：通过在“设置”→“AI”中配置的主要 AI 提供商来路由评估。
- **Laya（本地/设备上）**：Apache 2.0 开放式小型模型（Convai 的~0.4B 参数）。通过下载的权重或本地服务器（“http://127.0.0.1:8000”）完全在您的计算机上运行。数据永远不会离开您的设备。
- **Jev（托管）**：TypeSafe AI 的专业决策模型（0.042 美元/M 输入代币，免费输出代币；需要 API 密钥）。
- **Clef (Cloudflare Workers AI)**：Workers AI 上托管的 Apache 2.0 开放模型（`clef-flash` 9B、`clef` 27B；需要 Cloudflare API 令牌和帐户 ID）。
- **OpenRouter Decisions**：访问“inception/mercury-decide:free”（免费使用）、“liquid/d1”和“upstage/solar-decide”等决策模型。
- **OpenAI Decisions**：通过 Decisions API 的 OpenAI 实时决策模型。

> [!提示]
> **隐私门**：如果没有明确的选择加入，项目内容永远不会离开您的设备。即使启用远程模型，Plethora 也仅传输非识别性结构轮廓（标题骨架、项目类型、字符长度），而不会传输正文、突出显示或用户注释。所有模型判断均通过内容哈希方式缓存在 SQLite 本地。

##### Dwell 遥测和自适应学习循环

Plethora 跟踪**主动停留**而不是被动屏幕时间：
- 超过配置的超时（例如 45 秒）的不活动会将跟踪转换为“空闲”，并追溯性地排除空闲块，防止意外的窗口离开导致您的阅读指标膨胀。
- 累积交互证据，例如创建的提取、滚动遍历深度和退出操作（*提取创建*、*下一项*、*推迟*、*关闭*、*重新优先级*）。

后台学习循环使用此遥测技术进行调整，无需模型微调：
- **集群提升**：花费持续的活动时间（$\ge 1$ 分钟）创建摘录或亮点可以提升项目的集合和语义主题集群，更快地呈现相关知识。
- **抵抗建议**：跳过 $\ge 3$ 次的项目会收到 **拆分候选** 建议（提示您将其分解）。具有 $>50\%$ 空闲时间且没有交互的项目会收到 **自动降级** 建议。两者都是面向用户的建议；两者都不会自动改变您的物品。

### 标签感知调度 (TAS)

标签感知调度将语义智能添加到审阅队列中。
在“设置”中启用后，TAS 会应用两次后处理过程
您的到期项目无需更改基本 SM-20/FSRS 间隔：

- **先决条件门控**：阻止标签先决条件未满足的项目
  达到配置的成熟度阈值。  基础材料是
  在高级主题出现之前稳定下来。
- **干扰抖动**：分离共享高相干标签的项目
  通过最小时间窗口，减少审阅期间的语义干扰。

TAS 是**选择加入**且**非破坏性** - 可以随时将其关闭
返回默认队列顺序。  被阻止或延迟的项目将保留
他们原来的预产期和间隔。

#### 启用 TAS

1. 打开 **设置 → 标签感知调度**。
2. 打开**启用 TAS**。
3. 可选择启用/禁用 **干扰** 和 **先决条件**
   子系统独立。
4. 根据您的喜好调整每个滑块。

|设置|范围 |默认 |描述 |
|---|---|---|---|
|最小间隔| 0–24 小时 | 4 小时 |共享高一致性标签的项目之间的小时数 |
|一致性阈值| 0.50–1.00 | 0.75 | 0.75只有具有一致性 ≥ this 的标签才会被分隔 |
|成熟度比率| 0.50–1.00 | 0.70 | 0.70先决条件标签中必须成熟的项目比例 |

#### 设置先决条件

标记先决条件可让您控制主题出现的顺序：

1. 打开**标签管理**（从媒体面板或库工具栏）。
2. 单击顶部的**先决条件**按钮。
3. 单击标签名称以选择它进行编辑。
4.在编辑器面板中，勾选**之前**必须学习的标签
   该标签的项目可以出现在队列中。
5. 单击“**保存先决条件**”。

右侧的**依赖关系图**可视化关系 - 箭头
从先决条件指向依赖标记。  循环依赖是
在保存时检测并拒绝。

> **注意**：标签会自动从您现有的项目同步。
> 如果没有出现标签，请先标记一些项目，然后重新打开标签
> 管理 — TAS 将检测并注册它们。

#### 读取队列

当 TAS 处于活动状态时，队列标题会显示 **TAS 活动** 徽章
包含已准备和已阻止项目的计数。

|徽章|意味着|
|---|---|
| 🟡“等待‘标签’成熟度（45%）”|被阻止——先决条件标签仅成熟 45% |
| 🔵“延迟以避免干扰‘标签’” |延迟 — 最近安排了一个共享高一致性标签的项目 |

#### 强制物品

您可以覆盖单个项目的 TAS：

- 单击任何被阻止或延迟的项目旁边的 **强制显示** 链接
  立即将其添加到当前审阅会话中。
- 覆盖仅适用于会话 - 该项目将根据 TAS 重新评估
  下届会议的规则。

#### 相干性是如何计算的

一致性衡量标签项目的语义紧密程度：

1. 从队列视图使用**计算语义图**。  这需要
   配置的嵌入提供程序（OpenAI、Ollama、Cohere、OpenRouter）。
2. 每个项目的标题、内容和标签将发送至您选择的法学硕士
   提供者和嵌入向量被存储。
3.嵌入后，TAS自动计算每个标签的**质心**
   （带有该标签的所有项目的平均向量）和**连贯性**（平均
   这些项目的成对余弦相似度）。
4. 一致性值显示在标签管理中每个标签旁边。

尚未嵌入的标签被视为一致性 = 0 — 否
干扰抖动适用于这些标签。

#### 标签成熟度

当某个项目的 SM-20/FSRS 稳定性达到该项目的标签时，该标签就**成熟**
满足或超过标签的“maturityThreshold”（默认 0.8）。  的
总体成熟度比率为“matureCount / itemCount”。

- 先决条件编辑器中的进度条显示每个标签的当前状态
  成熟度比率。
- 先决条件门控使用配置的“maturityRatio”来决定
  先决条件标签是否“满足”足以解锁依赖项
  标签以供审查。

#### 尖端

- **仅从先决条件开始**。保持干扰抖动关闭，直到
  您已经运行了嵌入管道并具有一致性值。
- **使用粒度标签**。 `calculus.limits` → `calculus.derivatives` 是
  比一个广泛的“微积分”标签更有效。
- **观察区块率**。如果许多项目被阻塞，则降低成熟度
  比率或简化先决条件图。
- **力秀是你的安全阀**。如果 TAS 过于激进
  特定项目，强制显示它 - 不会损害底层调度数据。

## 语言学习

使用 Plethora 在阅读、观看和复习的同时学习语言。语言功能适用于文档、视频、队列和学习计划：您建立**语言配置文件**，在遇到单词时查看它们，向**人工智能导师**寻求帮助，练习**跟读、听写、发音和写作**，并让**学习者证据**建议下一步要做什么。

### 开启语言学习

1. 打开**设置→语言学习**并启用**语言学习**。
2. 打开**语言学习**选项卡并创建**语言配置文件**：选择您的目标语言、基本语言和估计熟练程度。
3. 在“设置”（云端或本地）中配置 AI 提供程序 - 导师、翻译和写作模式都需要一个。语音模式（跟读、听写、发音）还需要语音识别提供程序（例如 Groq）和麦克风许可。

个人资料驱动以下一切：人工智能导师适应您的词汇量，字典查看跟踪您每个单词的知识状态。

### 字典浏览

选择文档、文字记录或视频中的任何单词或短语：

- **Language Peek** 弹出窗口显示定义、翻译、发音和（如果有）句子示例。
- **Memorize** 将单词作为语言草稿发送到 **Flashcard Studio**。
- **摘录** 将其保存为学习摘录； **重播** 当存在对齐录音时重播原始音频。

### 人工智能导师

导师是一个会话助理，了解你的水平和你正在学习的文本。

**开始辅导课程：**
- 在文档中：选择一个句子，然后从选择菜单中选择“**导师**”（或“**解释**”）。
- 从字典中查看：点击单词上的**解释**。
- 在视频中：使用当前句子上的 **Tutor** 按钮。
- 在队列中：视频摘录片段显示**询问导师**芯片。

**模式：**解释、角色扮演、重写、语法、发音、搭配、翻译、最小配对、对话、纠正和练习。每个回复都会说明它是如何生成的——**接地**（来自您的源材料）、**生成**或**一般**——以及它使用的隐私路径（本地或云；云分析需要您的同意）。

**会话历史记录：** 完成的导师回复将保存到本地 **导师历史记录** 面板（最新 50 个）。从那里您可以**删除**单个会话、**清除所有**或**将历史记录导出为 JSON 文件。删除或导出只会影响您的本地历史记录 - 提供商数据永远不会被修改。

**取消和重试：**使用**取消**停止正在进行的回复；使用 **Retry** 重新运行相同的请求。

### 练习模式

**练习**区域（语言学习选项卡）提供：

- **阴影** — 在本机音频之后重复。当有可用时，会话会使用您正在学习的文本或视频中的原始音频剪辑，否则会回退到文本转语音。
- **听写** — 使用相同的原始音频范围聆听并输入您听到的内容。
- **发音** — 将您的录音与目标发音进行比较。
- **写作** — 写下答案并获得更正。
- **语音对话** — 与导师大声聊天。

尝试显示在练习中心的**最近尝试**下。

### 视频和媒体对齐

在视频中，每个句子都有自己的控制行：**重播**、**循环**、**自动暂停**、**翻译**、**我的**、**导师**和**练习**。重播更喜欢在确切句子位置处的**原始音频**；如果录音丢失、陈旧、模棱两可或可信度低，它就会退回到文本转语音。 **我的**创建了一个抽认卡草稿，保留了剪辑的**媒体范围**，因此该卡可以准确记住它在视频中的来源。练习启动会重复使用相同的范围，因此跟随和听写会播放正确的剪辑。

### 抽认卡工作室

语言草稿从 **Memorize**（字典查看）、**Mine**（视频）和语言练习到达 Flashcard Studio。草稿会保留其**出处** — 源文档或视频、确切的媒体范围和语言配置文件 — 因此您始终可以将卡片追溯到您遇到它的位置。

### 学习计划

学习计划与语言学习密切相关：

1. 创建或编辑计划时，链接**语言配置文件**（并可选择设置目标熟练程度和语言重点）。
2. 打开计划并查找 **学习者证据** 面板。它将计划的目标与您的真实学习数据进行比较，并建议后续步骤：
   - **词汇覆盖率** — 当目标的术语几乎与您已知的词汇重叠时。
   - **练习刷新** - 当您在过去两周内几乎没有接受的练习尝试时。
   - **抽认卡挖掘** — 当您与语言相关的抽认卡收藏仍然很小时。
3. 每条建议都有一个**开放语言学习**按钮，可直接跳转到语言学习选项卡。

## 学习计划和指导阅读路径

通过**学习计划**和**引导阅读路径**，将您的书籍、文章和成绩单变成结构化、客观的课程。

### 研究队列、列表和图表视图

在任何学习计划的**课程大纲**选项卡中，在三个互补视图之间切换：

- **队列**：您的逐步**学习队列**，突出显示下一个推荐的阅读作业（“继续学习”）、预计阅读时间、即将进行的作业、阻塞的先决条件和已完成的项目。
- **列表**：浏览和编辑课程节点、学习目标和链接的阅读段落。
- **图表**：在交互式课程图表中可视化跨主题的先决条件依赖关系。

### 生成和定制学习轨迹

1. 打开学习计划并选择**课程大纲**下的**队列**视图。
2. 单击**生成研究跟踪**（或编辑源或目标后**重建研究跟踪**）。
3. Plethora 分析您选择的源文档的结构 - 自动过滤目录、参考书目和附带提及的内容 - 并将每个学习目标与连贯的、按先决条件排序的阅读片段配对。
4. 单击 **预览和编辑跟踪** 以检查片段出处、交换替代段落、调整手动顺序、推迟项目或报告不相关的匹配项。

### 引导阅读模式

单击 **开始引导阅读** 直接在文档查看器中打开指定的段落，并带有专用的 **引导阅读模式** 侧边栏：

- **分配的边界和上下文**：显示开始/结束部分标记、预计持续时间以及为什么选择该部分作为学习目标。
- **进度跟踪**：跟踪您在指定范围内的阅读进度（您可以随时超出边界继续阅读）。
- **队列导航（`Prev` / `Next`）**：使用 **Prev** / **Next** 控件（或 **Next: \<Topic\>**）直接在学习计划中的阅读作业之间移动，而无需返回“学习计划”选项卡。
- **笔记、摘录和苏格拉底导师**：在阅读时捕获笔记/摘录或打开持久的**助手**面板（其对话按文档和视频保存）。

### 多项选择理解检查

完成阅读作业后，单击**完成阅读→检查理解**以打开低风险**理解检查（形成性）**：

- **默认多项选择**：提出一个基于您刚刚阅读的段落的 4 选项 (`A`–`D`) 多项选择问题（配置提供程序时人工智能生成，具有确定性离线/隐私安全后备）。
- **灵活的问题角度**：在*用自己的话解释*、*应用于新示例*、*区分相关想法*、*追踪论证*、*发现误解*和*基于来源的综合*之间切换，或单击**新问题**。
- **可选的书面模式**：如果您想输入自由格式的解释，请随时单击**写我自己的答案**。
- **立即反馈和下一个作业**：检查您的答案，突出显示正确的选项，解释推理，并提供 **下一步：\<主题\>** 按钮直接进入下一个阅读作业。形成性检查永远不会改变您的正式考试成绩或 FSRS 抽认卡间隔。

### 有针对性的修复和评估资格

- **有针对性的补救**：未满足的学习差距会自动作为学习队列中的补救项目出现，链接回先决条件概念或相关段落。
- **评估资格**：根据**指导**、**开放**或**测试**政策跟踪正式学习计划评估的准备情况。

## 睡眠跟踪和学习见解

在“学习见解”选项卡（可通过桌面工具栏或移动导航中的 HeartPulse 图标访问）中将您的睡眠历史、昼夜节律和生理遥测直接与您的学习表现联系起来。

受到 Piotr Woźniak 博士在 SuperMemo 中的经典睡眠图表的启发，Plethora 通过将客观睡眠观察与间隔重复记忆保留 (FSRS-7)、阅读课程和学习计划掌握相结合，实现了睡眠和昼夜节律跟踪的现代化。

### 仪表板和交互式睡眠图表

**睡眠图表**在统一的、多月的交互式时间轴上可视化您的睡眠和学习历史：

- **生物唤醒日期锚定**：睡眠事件锚定于生物唤醒日期（时区和夏令时安全），确保夜间睡眠和白天小睡归因于正确的认知日。
- **睡眠阶段和小睡**：显示详细的睡眠阶段（深度、快速眼动、轻度和清醒）以及白天小睡和睡眠中断。
- **学习会话叠加**：直接在时间线上叠加抽认卡复习会话、阅读会话和评估尝试，准确显示您相对于睡眠区块和昼夜节律阶段的学习时间。
- **日期检查和冲突解决**：单击任意一天即可检查详细指标、睡眠阶段细分、来源出处以及任何多设备差异。

### 昼夜节律和睡眠智能

Plethora 无需临床设备即可分析睡眠质量和时间：

- **睡眠规律指数 (SRI)**：衡量您睡眠时间表的日常一致性（计算您处于相同状态（睡眠与清醒）的概率，间隔 24 小时）。较高的规律性与稳定的认知表现密切相关。
- **Borbély 双过程模型**：显示探索性的非临床警觉性模拟，结合稳态睡眠压力（过程 S）和昼夜警觉性（过程 C），以突出您的自然峰值学习窗口和昼夜节律下降。
- **睡眠持续时间和债务**：根据您的基线跟踪滚动睡眠总量，以监测严重的睡眠不足和恢复情况。
- **生理恢复**：可视化夜间心率变异性（具有独立 RMSSD 和 SDNN 跟踪的 HRV）和静息心率 (RHR)，以反映自主恢复和准备情况。

### 学习表现与记忆的相关性

Plethora 没有假设相关性等于因果关系，而是采用保守的统计方法来评估睡眠如何影响记忆力：

- **FSRS-7 回忆残差**：对于每次抽认卡审核，Plethora 在评级之前按时间顺序计算“观察的回忆 - 预测的可检索性”。这将睡眠的生理影响与卡的年龄和固有难度隔离开来。
- **响应延迟**：分析缩尾对数延迟以测量不同睡眠状态下的回忆速度和检索工作。
- **混杂因素调整分析**：使用人内多元回归控制一天中不同时间的昼夜节律（`sin`/`cos`）、卡片难度和之前的 24 小时学习工作量。
- **证据检查器**：单击任何个人模式上的**检查证据**，以检查样本大小、日聚类块引导置信区间和 Benjamini-Hochberg 错误发现率 (FDR) 控制。 Plethora 明确标记数据不足的关联，而不是提出不成熟的结论。
- **学习计划健康洞察卡**：嵌入式健康摘要出现在学习计划进度和主页视图中，显示您的睡眠规律和持续时间如何与课程里程碑和考试表现保持一致。

### 数据源和可穿戴连接

Plethora 支持一整套数据收集选项——从零可穿戴手动跟踪到多设备可穿戴生态系统：

- **需要零可穿戴设备（手动记录）**：单击 **记录睡眠** 手动记录睡眠（就寝时间、醒来时间、质量评级和可选阶段）。
- **交互式示例数据**：单击**示例数据**，使用加载到内存库中的临时合成数据集探索完整的功能集，而无需修改您的真实记录。
- **文件导入和导出**：从 Apple Health (`export.xml`)、Plethora Health JSON 或 CSV 电子表格导入睡眠和健康记录。将数据导出为标准 JSON/CSV 或受密码保护的加密包（使用 PBKDF2 和 AES-256-GCM 的“.plethora-health.enc”）。
- **本机移动桥**：在 iOS 上，连接 **Apple HealthKit**；在 Android 上，连接 **Android Health Connect** 以实现自动增量后台同步。
- **云可穿戴设备提供商**：适用于 **Oura Ring**（云 API v2）、**WHOOP**（开发者 API v2）和 **Google Health**（v4，涵盖 Pixel Watch 和 Fitbit）的直接 OAuth 2.0 PKCE 连接器。
- **源优先级**：当多个设备记录相同的睡眠窗口（例如 Apple Watch 和 Oura Ring）时，Plethora 会根据您在“设置”中配置的首选提供商优先级来删除重复记录。

### 本地优先隐私架构

健康数据非常敏感，并且受到严格的本地优先隔离：

- **专用健康保险库**：存储在单独的设备上 SQLite 数据库 (`<app_data_dir>/health/health.db`) 中，与主库数据库 (`plethora.db`) 物理隔离。
- **零云和人工智能出口**：健康记录永远不会包含在 Plethora 云备份、E2EE 设备同步、语义块索引或 AI/LLM 提示上下文中。
- **安全保管库删除**：删除单个条目或通过**设置→集成→健康与可穿戴设备**下的数据库压缩执行完整的保管库擦除。

### 同步设置

Plethora 通过**共享同步室**在您的设备上同步您的阅读数据。没有帐户，没有服务器登录，也没有 API 密钥 - 每个知道相同同步代码的设备都会加入同一个房间并共享相同的数据。这是应用程序中唯一的同步系统。

#### 它是如何工作的

- 第一次打开同步设置时，每个设备都会生成一个**同步代码**（随机字符串）。
- 与您的其他设备共享该代码 - 复制它或扫描同步设置中显示的二维码。
- 当两个设备共享代码时，只要它们同时在线，它们的阅读数据（文档、摘录、学习项目、复习历史记录、设置）就会自动同步。附加到文档的文件通过同一房间同步。
- 同步代码是唯一授予房间访问权限的东西。保持其私密性 - 任何拥有它的人都可以读取您的同步数据。

#### 连接您的设备

1. 在您的第一台设备（例如台式机）上打开 **设置 → 同步**。请注意此处显示的同步代码，或显示其二维码。
2. 在您的第二台设备（例如您的手机）上打开 **设置 → 同步**。
3. 要么：
   - 点击**扫描**并将相机对准第一台设备上的二维码，或者
   - 将同步代码粘贴到“加入另一个代码”字段中，然后点击“**加入**”。
4. 第二台设备加入房间并立即开始同步 - 无需重新加载或重新启动。
5. 对您想要保持同步的每个设备重复此操作。

> **提示：** “新建”按钮会生成新的同步代码。仅当您想重新开始时才使用它 - 使用旧代码的设备将停止与使用新代码的设备同步。

#### 同步什么

- 文档及其元数据
- 摘录（重点和注释）
- 学习项目（抽认卡、完形填空、问答）
- 查看历史记录和调度状态
- 应用程序设置
- 文档附加文件（PDF、EPUB 等）

#### 文件自动下载

在 **文件同步** 下，选择将新文件拉到每个设备上的积极程度：

- **始终** — 自动下载房间中出现的每个文件。
- **仅限 WiFi** — 仅在 WiFi 上自动下载（对移动数据套餐有用）。
- **手动** — 从不自动下载；每个文件都会显示一个下载按钮，您可以在需要时点击该按钮。

#### 端到端加密（可选）

默认情况下，同步在“仅 TLS”模式下运行：您的数据通过网络加密传输，同步代码充当共享密钥。如果您想要更强的保护，可以启用**端到端加密**，这会在设备上的数据离开之前对其进行加密，因此同步服务器只能看到密文。

启用加密后，二维码会嵌入您的房间秘密 - 仅与您信任的设备共享。

#### 隐私

您的所有阅读数据首先存储在您的本地设备上。同步是一种可选的便利功能，可以在共享房间中跨设备镜像数据。除了您个人配置的 AI 提供商之外，不会将任何内容发送到任何服务器。

#### 备份与恢复

Plethora 提供完整的备份和恢复系统来保护您的学习数据并在设备之间迁移。

5. 预览备份中的内容：
   - 文件计数
   - 提取计数
   - 学习项目计数
   - 收藏数量
   - 是否包含文件
6. 配置导入选项（可选）：
   - **导入内容**：选择特定数据类型
   - **重复处理**：跳过、替换或合并
   - **导入文件**：是否恢复文档文件
7. 单击“**导入备份**”
8.等待导入完成（显示进度）

**重复处理策略：**
- **跳过**：跳过已经存在的项目（大多数情况下推荐）
- **替换**：用备份版本覆盖现有项目
- **合并**：创建所有项目的新副本（可能会创建重复项）

2. 设置 → 集成 → **NotebookLM**
3. 单击 **Connect** 并选择提供商（“mock”用于测试，“cli”用于实时 NotebookLM）

**创建笔记本：**
- 单击 **新建笔记本**（侧边栏或空白状态）并在应用程序内对话框中输入标题
- 标题在第一次点击时发送到 NotebookLM — 无需第二次尝试
- 创建笔记本时，该按钮会显示一个微调器并被禁用；失败只是以祝酒的形式出现，而不是默默地无所事事
- 从空状态创建会自动选择新笔记本，因此您的下一个操作将针对它运行

**你可以做什么：**
- 直接从 Plethora 在 NotebookLM 聊天中提问
- 运行研究提示（网络辅助笔记本研究）
- 生成工件：
  - 抽认卡
  - 测验
  - 报告（简报文件）
  - 学习指南
  - 思维导图
  - 数据表
  - 幻灯片（格式：详细/演示者，长度：默认/短）
  - 信息图（方向、细节级别和样式选项）
  - 音频概述
  - 视频概述
- 在应用程序内预览工件：
  - 文本/结构化工件（报告、学习指南、思维导图、数据表）在专用查看器中呈现
  - 音频和视频概述通过应用程序的媒体播放器内嵌播放
  - 信息图表显示为图像
  - 幻灯片显示为 PDF
- 将生成的抽认卡/测验项目同步到 Plethora 审阅队列中

**工件操作（在查看器中）：**
- **复制** — 将工件内容复制到剪贴板
- **复制为 Markdown** — 复制 Markdown 导出（文本和结构化工件）
- **保存到库** — 将工件作为文档导入到当前集合中；已保存的工件报告，而不是重复
- **导出** — 通过本机保存对话框将工件保存为 Markdown 文件（可从 Studio 作业详细信息导出 JSON/HTML）

**将工件导入库：**
- 报告和学习指南作为 Markdown 文档导入，准备排队和提取
- 思维导图和数据表作为结构化文档导入，以保持其交互式查看器
- 音频概述作为播客风格的项目导入；视频概述作为视频项目
- 幻灯片导入为 PDF 文档；信息图表作为图像文档导入，并且还添加到**图像注册表**（按内容删除重复项，因此重新保存不会创建重复项）
- 导入的文物位于馆藏图书馆根目录，并有资格按照与其他图书馆物品相同的条件进入队列

**添加来源：**
- 添加 **URL**、**YouTube** 链接、粘贴的 **文本**、本地 **文件**，或从您的 **库** 中选择文档
- 库文档通过相同的摄取管道附加并显示待处理状态，直到 NotebookLM 完成处理它们
- 检测已附加的文档，因此您不会添加重复项

4. Plethora 使用线程/源元数据创建 NotebookLM 链接的摘录
5. 保存的回复显示**已保存**指示符以避免重复

**文档问答 + NotebookLM 工作流程：**
1. 在 Plethora 中打开文档
2. 将 **文档问答** 与 NotebookLM 研究模式结合使用
3. 编辑/优化生成的内联答案文本
4. 从精炼的答案中创建摘录
5. 从这些摘录中生成抽认卡/完型填空/问答项目

**故障排除：**
- 如果工件预览显示媒体不可用，请等待 NotebookLM 生成完成并重新打开工件。
- 如果视频、音频、信息图表或幻灯片无法显示，请重新打开工件 — 视频/音频和信息图表会自动通过备用媒体路径重试；幻灯片未加载时会提供“使用备用查看器打开”选项。

#### 设备上 Apple Intelligence（Mac 和 iPhone）

在支持的 Apple 设备上，Plethora 可以使用 **Apple Foundation Models**（Apple 的内置设备语言模型）运行许多 AI 功能。它独立于云提供商（OpenAI、Ollama 等），并且**不需要 API 密钥**。

**它是什么：** 用于智能标记、摘要、抽认卡生成和询问图书馆答案等任务的设备上文本生成。

**它不是什么：** Apple Foundation Models **不**转录视频或音频，**不**朗读文本 (TTS)，并且**不**分析照片。使用 Plethora 的 **音频转录** 和 **TTS** 设置来执行这些作业。

**要求：**
- **Mac：** macOS 26 或更高版本、Apple Silicon、在系统设置中打开 Apple Intelligence
- **iPhone / iPad：** iOS 26 或更高版本、启用 Apple Intelligence 的兼容设备

**如何开启：**
1. 打开**设置 → AI Provider 设置**
2. 滚动到**设备上人工智能**
3. 开启**首选设备上人工智能**
4. 检查 **Foundation Models**（或 **Apple Intelligence**）是否显示 **Ready**

就绪后，Plethora 会自动使用设备上的 Apple AI 来执行支持的任务。您没有将 Apple 添加到云提供商列表中。

**您可以使用设备上的 Apple AI 做什么：**

|特色|在设备上工作吗？ |
|--------------------|--------------------|
|智能标签|是的 |
|总结/解释一段话 |是的 |
|询问图书馆（您图书馆的答案）|是的 |
|从文本生成抽认卡 |是的 |
|提取要点，研究问题|是的 |
|工作室审核提示|是的 |
|转录视频或有声读物 |否 — 使用 **设置 → 音频转录** |
|大声朗读文本 (TTS) |否 — 使用**设置 → 文本转语音** |
|描述图像/OCR |否 — 使用 OCR 或视觉功能 |

**隐私：**
- 默认情况下，处理保留在**您的设备上**
- 默认情况下，**允许云回退**处于关闭状态 - 如果设备上的 AI 无法完成任务，Plethora 将**不会**默默地将您的内容发送到付费云提供商
- 如果您希望 Plethora 在设备上的 AI 不可用时重试您配置的云提供商，您可以启用云回退

**如果状态未就绪：**

|状态 |这意味着什么 |尝试什么 |
|--------|----------------|-------------|
|准备好 |设备端人工智能可用 |开始正常使用AI功能 |
|正在下载... |系统型号还在安装|等待，然后点击设备上 AI 中的 **刷新** |
|已禁用 | Apple Intelligence 已关闭 |在系统设置中启用 Apple Intelligence |
|不符合条件 |设备或地区不支持 |使用云或本地提供商代替 |
|不支持的操作系统 | macOS/iOS 版本 26 以下 |更新您的系统，或使用其他提供商 |

**提示：** 长文档会自动处理 - Plethora 将它们分割成适合设备上上下文窗口的块，然后合并结果。您不需要配置此项。

#### 设备上的 Windows AI (Windows 11)

在 Windows 桌面上，Plethora 可以在您的 PC 上运行 AI 任务，而无需将您的库内容发送到 OpenAI、Anthropic 或您单独配置的其他云 API。 Windows 提供了两种互补的设备上路径：

1. **系统设备上人工智能** — 用于文本任务和 OCR 的内置 Windows AI API（当您的 PC 和 Windows 版本支持它们时）
2. **Foundry Local** — 您自行安装的可选 OpenAI 兼容本地服务器（适用于许多 GPU，包括没有 Copilot+ NPU 的硬件）

这些路径与云提供商分开，并且**不要使用您的 OpenAI API 密钥**，除非您启用云回退。

**它是什么：** 用于智能标记、总结段落、抽认卡想法、询问图书馆答案和工作流程快捷方式的设备上文本生成 - 以及在 **设置 → 文档 → OCR** 下启用时用于扫描 PDF 和图像的 **Windows 系统 OCR**。

**它不是什么：**系统内置设备人工智能**不**转录音频或视频（使用**设置→音频转录**），**不**朗读文本（使用**设置→文本转语音**），并且**不**在每台Windows PC上运行。 Copilot+ NPU 功能（Phi Silica 文本 AI 和 Windows 系统 OCR）需要硬件，而 Windows 构建的许多游戏 PC 都无法满足 — **Foundry Local**、**Tesseract** 或云提供商仍然是实用的选择。

**要求：**
- **Windows 11 版本 24H2 或更高版本**（内部版本 26100+）用于设备上系统 AI 状态检查
- **包标识**在安装时注册（Plethora 的 Windows 安装程序会自动注册稀疏 MSIX 标识；如果注册失败，设备上系统 AI 将保持不活动状态）
- **Copilot+ / NPU 级硬件** 适用于 Microsoft 的 Phi Silica 语言模型 — 许多独立 GPU（例如较旧的 GeForce 卡）即使在 Foundry Local 运行良好时也无法使用第 1 层文本 AI
- **Foundry Local：** 安装并启用 Foundry Local 运行时的任何 Windows PC

**如何开启：**
1. 打开**设置 → AI Provider 设置**
2. 滚动到**设备上人工智能**
3. 开启**首选设备上人工智能**
4. 查看 **System On-Device AI** 和 **Foundry Local** 状态行

当 **首选设备上 AI** 开启时，Plethora 首先在 Windows 上尝试系统设备上 AI，然后在配置的云提供商之前尝试 Foundry Local（如果已启用） — 除非 **允许云回退** 已关闭，在这种情况下，故障将保留在设备上。

**你可以做什么：**

|特色|设备上系统人工智能 |本地铸造厂 |
|--------|---------------------|------------------------|
|智能标记|准备好后 |当运行时+模型准备好时|
|总结/解释一段话 |准备好后 |准备好后 |
|询问图书馆 |准备好后 |准备好后 |
|从文本生成抽认卡 |准备好后 |准备好后 |
|导入/PDF 上的 OCR（Windows 系统 OCR）|当 OCR 准备就绪时 |否 — 使用 Tesseract 或云 OCR |
|转录音频或视频 |没有 |没有 |
|大声朗读文本 (TTS) |没有 |没有 |

**文档 → OCR：** 当 **Windows 系统 OCR** 出现在 **设置 → 文档 → OCR** 中时，直接选择它或启用 **首选 Windows 系统 OCR** 以在可用时自动使用它进行导入和 PDF OCR。它使用与上面相同的 Windows AI 堆栈，并在不可用时回退到 Tesseract 或您选择的 OCR 提供商。

**隐私：**
- **首选设备上的人工智能** 首先将支持的任务路由到设备上的后端
- 默认情况下，**允许云回退**处于关闭状态 - 当设备上的 AI 失败时，Plethora 不会**默默地将您的库内容发送到付费云 API
- Foundry Local 在您的机器上保留推理；仅联系您配置的本地端点

**如果状态未就绪：**

|状态 |这意味着什么 |尝试什么 |
|--------|----------------|-------------|
|可用/准备就绪|功能已准备就绪 |正常使用AI功能；如果仍然失败，请打开**诊断** |
|可下载/正在下载| Windows AI模型尚未安装 |等待 Windows 更新或模型安装，然后点击 **刷新** |
|包裹标识缺失 |稀疏 MSIX 未注册 |重新安装或修复Plethora；检查 **诊断** 中的稀疏 MSIX 路径 |
|有限访问被拒绝| Phi Silica 需要 Microsoft LAF 解锁 |仅高级设置； Foundry Local | 不需要
|不支持的硬件 | PC 缺乏此 Windows AI 功能所需的 NPU |启用 **Foundry Local**、使用云提供商或使用 Tesseract 进行 OCR |
|不支持的操作系统 | Windows 构建低于 24H2 |更新 Windows 或使用 Foundry 本地/云 |

在 Windows 上打开**设置 → 设备上 AI → 诊断**，了解程序包标识、桥可用性、OCR 就绪状态和 Foundry 本地端点运行状况。

**提示：**在具有强大 GPU 但没有 Copilot+ NPU 的游戏 PC 上，**Foundry Local** 通常是现实的设备上 AI 路径。设备上系统 AI 状态仍然有助于了解为什么 Phi Silica 或 Windows 系统 OCR 在您的硬件上不可用。

#### 自动生成

**卡牌生成：**
- 启用从摘录自动生成
- 每次提取的卡片数量
- 质量门槛
- 需要手动批准

**总结：**
- 自动总结长摘录
- 摘要长度（短、中、长）
- 包含在卡片内容中

#### 上下文窗口

**代币限制：**
- 每个请求的最大令牌（响应长度）
- 相关卡片的背景
- 文档片段长度

**本地模特（Ollama）：**
- **上下文窗口**是作为“num_ctx”发送的运行时 KV 缓存大小（可以容纳多少提示+响应）。从 8K–16K 开始；值越高，使用的 GPU/RAM 越多。
- **最大响应令牌**是生成长度的单独上限（`num_predict`）。它不是上下文窗口。
- 自动解析为 4K 和 16K 之间的实际值 — 绝不是模型的理论最大值。
- 云提供商仍然仅使用输出长度的最大响应设置。

### OCR（光学字符识别）

从图像中提取文本：

**支持的提供商：**
- Mirage 视觉引擎（本地）——跨文档摄取、图像遮挡、FTS5 搜索和浏览器剪辑的视觉索引
- GLM-OCR（本地）——通过 llama.cpp 或 vLLM 进行多模式 OCR
- 超正方体（本地）
- 谷歌云视觉
-AWS Textract
- Azure 计算机视觉
- 标记（本地）— PDF 到 Markdown
- Nougat（本地）——带有数学的科学文档

**使用案例：**
- 截图捕捉
- 扫描文件
- 带文字的图像
- 手写笔记

**设置（云提供商）：**
1. 设置→OCR
2. 选择提供商（Google、AWS 或 Azure）
3. 配置 API 密钥和凭据
4. 选择语言
5. 使用示例图像进行测试

**设置（带有 llama.cpp 的 GLM-OCR）：**

llama.cpp 为 GLM-OCR 提供轻量级本地 LLM 服务器，无需 GPU。它在端口 8080 上使用兼容 OpenAI 的 API。

1. **构建 llama.cpp** （如果尚未构建）：
   ````bash
   git 克隆 https://github.com/ggml-org/llama.cpp.git
   cd 骆驼.cpp
   cmake -B 构建
   cmake --build 构建 --config Release -j$(nproc)
   ````

2. **下载多模式模型**（GGUF格式）：
   ````bash
   # Qwen2.5-VL（推荐用于OCR）
   Huggingface-cli 下载 bartowski/Qwen2.5-VL-7B-Instruct-GGUF \
     Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf --local-dir 模型/
   ````

3. **启动服务器**：
   ````bash
   ./build/bin/llama-server \
     -m 型号/Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf \
     --端口 8080 --主机 0.0.0.0 -c 16384 -t $(nproc)
   ````

4. **在 Plethora 中配置**：
   - 设置 → OCR → 提供商：**GLM-OCR（本地）**
   - 后端：**vLLM (GPU)**（这是 llama.cpp/vLLM 模式 — 适用于两者）
   - 端点：`http://localhost:8080/v1`
   - 模型：您的模型文件名（例如“Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf”）

**性能提示：**
- 对于长文档使用 `-c 16384` 或更高值（默认 4096 对于大多数 OCR 任务来说太小）
- 使用 `-t $(nproc)` 使用所有 CPU 线程
- Q4_K_M 量化为 CPU 推理提供最佳质量/速度权衡
- 对于 GPU 加速，构建具有 CUDA、Metal 或 Vulkan 支持的 llama.cpp

**设置（带有 vLLM 的 GLM-OCR）：**

vLLM 为大型模型提供 GPU 加速推理。需要具有足够 VRAM 的 NVIDIA GPU。

````bash
pip安装-U vllm
vllm 服务 zai-org/GLM-OCR --allowed-local-media-path / --port 8080
````

然后以相同的方式配置 Plethora（端点“http://localhost:8080/v1”）。

**设置（GLM-OCR 与 Ollama）：**

最简单的入门选项 — Ollama 自动管理模型下载和运行时。

1. 设置 → OCR → 提供商：**GLM-OCR（本地）**
2. 后端： **Ollama (CPU)**
3. 单击**下载 Ollama**（如果未安装）
4. 单击“**启动运行时**”
5. 设置模型（例如 `llava:7b` 或 `qwen2-vl:7b`）
6. 单击**拉模型**

**数学 OCR：**
- 方程的专门处理
- 乳胶输出
- 符号识别
- 最适合：科学论文、教科书

## 提示和最佳实践

### 卡片制作

**做：**
- 使卡片具体化（每张卡片一个事实）
- 使用简单、清晰的语言
- 在答案中包含上下文
- 添加相关示例
- 使用完形填空来建立关系
- 保持问题简洁

**不要：**
- 将多个事实放入一张卡片中
- 使用含糊的措辞
- 让问题太简单或太难
- 复制大文本块
- 使用没有定义的缩写

**示例 - 坏卡：**
````
问：线粒体的功能是什么？
它与细胞呼吸中 ATP 的产生有关吗？
答：【段落解释】
````

**示例 - 好卡：**
````
卡1：
问：线粒体的主要功能是什么？
A：通过细胞呼吸产生ATP

卡2：
问：线粒体利用什么过程产生 ATP？
A：细胞呼吸（有氧）

卡3：
问：线粒体产生的能量货币是什么？
A：ATP（三磷酸腺苷）
````

### 学习常规

**每日时间表（20-30 分钟）：**
1. **上午**：查看到期卡（15 分钟）
2. **全天**：从阅读中创建摘录
3. **晚上**：根据摘录创建卡片（10-15 分钟）

**每周时间表：**
- **周一至周五**：定期审查和卡片创建
- **周六**：较长的学习课程（1-2 小时）
- **周日**：回顾分析、调整目标、组织

**管理大容量：**
- 设置每日审核限制（例如 50 张卡片）
- 按类别划分优先级（专注于一个主题）
- 使用智能队列来分解任务
- 每20-30分钟休息一次

### 保留优化

**提高保留率：**
- 诚实评分（不要夸大评分）
- 持续回顾（每天最好）
- 充足的睡眠（睡眠期间记忆会巩固）
- 主动回忆（不要偷看，先思考）
- 间隔评论（不要死记硬背）

**处理遗忘：**
- 正常遗忘 10-20%（取决于目标保留率）
- “再次”卡是学习机会
- 如果经常忘记（>30%），请考虑：
  - 降低所需的保留率 (85-90%)
  - 创建更简单的卡片
  - 添加更多上下文
  - 更频繁地复习

### 类别组织

**最佳实践：**
- 从广泛开始，然后细分
- 示例：`编程`→`编程/Python`→`编程/Python/异步`
- 使用一致的命名
- 不要创建太多（5-10 个是可以管理的）

### 优先级管理

**优先准则：**
- **100（关键）**：考试准备、紧急工作项目
- **80-90（高）**：当前课程，主动学习
- **60-70（中）**：持续的兴趣、常识
- **40-50（低）**：很高兴知道，补充
- **0-20（存档）**：仅供参考，很少回顾

**优先调度：**
- 专注于每日评论的 80+ 优先级
- 每隔几天复习60-70
- 每周回顾 40-50 次
- 每月或按需审核 0-20 次

### 使用预览间隔

**预览间隔**功能可以准确显示所有四个评级的每张卡接下来出现的时间。

**使用方法：**
1.读卡
2.检查评级按钮下方的预览间隔
3. 根据以下条件选择评级：
   - 您当前的回忆
   - 您想多久再次看到它
   - 您的日程安排（例如即将举行的考试）

**策略示例：**
- 两周后考试：对重要卡片进行评分“简单”，以便很快再次看到它们
- 忙碌的一天：评价“好”或“简单”以间隔评论
- 想要掌握：评价“难”以更频繁地复习

### 管理不堪重负

**到期卡太多？**
1. 设置审核限额（设置→审核→每日上限）
2. 关注高优先级项目
3. 暂时暂停低优先级类别
4.考虑稍微降低所需的保留率

**内容太多而无法处理？**
1. 逐步导入文件
2.只提取关键点（不是全部）
3.有选择地创建卡片
4.使用类别来组织

**倦怠？**
1.休息一下（没关系！）
2.减少每日限额
3. 暂停非关键类别
4.一次专注于一个类别

## 故障排除

### 常见问题

#### 卡片未出现在审核中

**可能的原因：**
- 今天审核的所有卡片
- 卡被暂停
- 过滤活跃的隐藏卡

**解决方案：**
1. 在“审阅”选项卡中检查“到期”计数
2. 检查队列 → 确保卡未暂停
3. 清除过滤器
4. 检查审核日期（也许是将来安排的卡片）

#### 保留率低

**症状：** 忘记很多卡片，频繁“再次”评级

**解决方案：**
1. **检查卡片质量**：卡片是否清晰？每张卡一个事实？
2. **降低所需保留率**：尝试 85% 而不是 90%
3. **更频繁地复习**：每天复习，而不是临时抱佛脚
4. **添加上下文**：答案中的更多信息
5. **简化卡片**：将复杂的卡片分解为更简单的卡片

#### 同步冲突

**症状：** 重复卡、同步后数据不匹配

**解决方案：**
1. 选择冲突解决策略（设置→同步）
   - **本地胜利**：保留您的更改
   - **远程获胜**：接受服务器更改
   - **询问**：手动解决每个冲突
2.定期同步以尽量减少冲突
3. 使用一台主要设备

#### 导入失败

**症状：** 文档导入失败或错误

**解决方案：**
1. **检查文件格式**：确保支持的格式（PDF、EPUB等）
2. **检查文件大小**：非常大的文件可能会超时
3. **检查 URL**：某些网站阻止自动访问
4. **检查互联网**：URL导入需要连接
5. **尝试替代方案**：对网页内容使用复制粘贴

#### 性能问题

**症状：** 加载缓慢、滞后、冻结

**解决方案：**
1. **大型数据库**：存档旧卡（设置→数据→存档）
2. **许多图像**：图像加载速度变慢
3. **系统资源**：关闭其他应用程序
4. **重建数据库**：设置→数据→重建（最后的手段）

#### OCR 不工作

**症状：** OCR 失败或结果不佳

**解决方案：**
1. **检查 API 密钥**：有效且有积分（云提供商）
2. **检查图像质量**：清晰、高分辨率的图像效果最佳
3. **检查语言**：选择正确的语言
4. **尝试替代提供商**：有些对于某些内容效果更好
5. **本地 OCR**：如果互联网问题，请使用 Tesseract

#### llama.cpp 没有响应

**症状：** “调用 LLM 时出错”或连接拒绝 localhost:8080

**解决方案：**
1. **检查服务器是否正在运行**: `curl http://localhost:8080/v1/models`
2. **启动服务器**：参见上面的[OCR设置](#ocr-optical-character-recognition)
3. **上下文大小太小**：使用 `-c 16384` 或更高版本重新启动
4. **端口正在使用**：另一个进程可能正在使用端口8080；检查“lsof -i :8080”
5. **内存不足**：使用较小的量化（Q3_K_M 而不是 Q4_K_M）或较小的模型

#### 奥拉马未开始

**症状：** GLM-OCR Ollama 运行时无法启动

**解决方案：**
1. **安装 Ollama**：使用“设置”→“OCR”中的“下载”按钮，或从 ollama.com 安装
2. **检查二进制路径**：如果不在默认位置，则设置 Ollama 二进制路径
3. **Linux权限**：您可能需要`sudo`来安装或运行Ollama服务

#### Windows：“应用程序无法启动，因为其并行配置不正确”

**症状：** 在 Windows 上，“plethora-tauri.exe”（或“pdf-reflow-diag.exe”）永远不会打开窗口。相反，您会看到一个对话框，显示应用程序的并行配置不正确并建议“sxstrace.exe”。 Plethora 自己的日志中不会写入任何内容，因为该进程在**任何应用程序代码运行**之前停止。

**确认：** 打开事件查看器 → Windows 日志 → 应用程序并查找“SideBySide”，事件 ID 62，其中包含如下消息：

````
“...\plethora-tauri.exe”的激活上下文生成失败。
清单或策略文件“...\plethora-tauri.exe”第 1 行出现错误。
元素“msix”中缺少必需的属性“packageName”。
````

````powershell
Get-WinEvent -LogName 应用程序 -MaxEvents 300 |
  Where-Object { $_.ProviderName -eq 'SideBySide' } |
  选择对象-前 3 个创建时间、ID、消息 |格式列表
````

**原因：**可执行文件的**嵌入式应用程序清单**不符合清单架构，因此 Windows 的并行激活上下文生成器在第 1 行拒绝整个清单并中止进程创建。这是您安装的版本中的包装缺陷，而不是您的电脑的问题。从 Plethora 3.3.1 开始，它已针对 Windows 安装程序进行修复。

**解决方案：**
1. **安装当前的 Plethora for Windows**：下载最新的安装程序并安装在现有副本上。在损坏的 3.3.0 安装中，应用程序根本无法启动，因此它无法自行更新 - 需要下载并重新安装步骤，并且您的库和设置将保留。
2. **确认您安装的内容**（可选，需要 Windows SDK 命令行工具）：提取清单并查看“<msix>”元素：
   ````
   mt.exe -inputresource:"C:\Path\To\plethora-tauri.exe";#1 -out:%TEMP%\plethora.manifest
   ````
   健康的清单包含一个空的“<msix ... />”元素，其中包含“packageName”、“publisher”和“applicationId”属性。
3. **不要**重新安装 Microsoft Visual C++ Redistributable、运行 `sfc /scannow` 或重新注册 DLL。失败发生在加载任何 DLL 之前，并且清单的唯一依赖项是属于 Windows 一部分的 Microsoft Common Controls 程序集。这些步骤不能改变结果，错误文本也不会指向这些步骤。

**注释：**
- 仅当安装程序附带的身份包可以注册时，包身份（Windows AI 功能）才可用，这要求它由您的计算机已经信任的证书进行签名。如果无法注册，Plethora 会正常运行，并且只有依赖于身份的 Windows AI 功能保持关闭 — 设置 → 设备上的 AI 显示原因。
- 在 Windows 10 2004 及更高版本上，相同的清单元素授予该身份；在较旧的系统上，应用程序无需它即可运行。

**预览间隔**：显示每个评级选项的下一次审核日期的功能

**完形填空**：填空卡类型

**暂停**：暂时隐藏评论中的项目

**类别**：组织的主题领域

**标签**：跨类别组织的自定义标签

**优先级**：用户设置的重要性（0-100）

## 常见问题解答

**问：如何向 Plethora 添加时事通讯？**
答：您可以通过两种方式添加新闻通讯：
1. **新闻通讯目录**：点击 RSS → 新闻通讯图标 (📬) → 浏览并订阅精选新闻通讯
2. **直接 URL**：复制任何时事通讯 URL（Substack、Beehiiv 等）→ RSS → 添加 Feed → 粘贴 URL。 Plethora 将自动发现 RSS 提要。

**问：为什么我的 NotebookLM 视频、音频、信息图或幻灯片不显示？**
答：媒体工件需要先生成并准备好文件，然后才能预览。等待生成完成，然后重新打开工件 - 视频/音频和信息图表自动通过备用媒体路径重试，并且幻灯片在未加载时提供“使用备用查看器打开”选项。如果仍然失败，请在“设置”→“集成”中重新连接 NotebookLM 并重新生成工件。

**问：支持哪些新闻通讯平台？**
答：Plethora 支持来自 Substack、Beehiiv、Ghost blogs、Buttondown、ConvertKit、Revue、Medium 和 WordPress 网站的 RSS 源。大多数时事通讯都会发布 RSS 源 - 检查时事通讯网站上的 RSS 链接或尝试将“/feed”添加到 URL。

**问：我每天应该复习多少张卡片？**
答：从每天 20-50 个开始。根据您的日程安排和目标进行调整。一致性比数量更重要。

**问：我每天可以创建多少张卡片？**
答：想要多少就多少，但注重质量而不是数量。 10-20 张制作精良的卡片比 50 张劣质卡片要好。

**问：我的目标留存率应该是多少？**
答：90% 是建议的默认值。如果您的评论过多，则调整为 85%；对于关键材料，则调整为 95%。

**问：我可以使用 Plethora 来处理语言吗？**
答：当然！请参阅[语言学习](#language-learning)部分，了解完整的工作流程——配置文件、词典查看、人工智能导师、跟读/听写/发音/写作练习、媒体对齐重播和学习计划差距建议。它也非常适合词汇、语法和句子卡——使用完形填空卡来表示语法模式。

**问：如何处理数学方程？**
答：在卡片中使用 LaTeX 语法。对于 OCR，请使用 Mathpix 提供程序以获得数学内容的最佳结果。

**问：我可以与 Anki 同步吗？**
答：是的！在设置 → 集成 → Anki 中配置 AnkiConnect 进行双向同步。

**问：暂停和删除有什么区别？**
A：暂停会暂时隐藏卡牌（可以取消暂停）。删除将永久删除（可以从备份中恢复）。

**问：我应该多久复习一次？**
答：每天是理想的选择。如果你错过了几天，卡片会累积，但不会“丢失”——只要有机会就补上。

**问：我可以在多个设备上使用 Plethora 吗？**
答：还不能直接同步，但您可以通过 Dropbox/Google Drive 同步数据，或使用浏览器扩展程序。

**问：我的数据是私密的吗？**
答：是的！所有数据都存储在本地。云同步已加密。除配置的 AI 提供程序外，不会向服务器发送任何数据。

**问：如何导出我的卡？**
A：设置 → 备份 → 导出，或使用 Anki 同步导出为 .apkg 格式。
