# Plethora 用户手册

**掌握渐进阅读和间隔重复的完整指南**

---

## 简介

### 什么是 Plethora？

Plethora 是一款功能强大的学习应用程序，它结合了两种经过验证的技术：

**增量阅读** - 随着时间的推移，以可管理的小块的形式处理大量信息。您不必从头到尾阅读文章，而是提取要点并逐渐建立理解。

**间隔重复** - 以科学优化的时间间隔复习材料，以最大程度地保留内容。 FSRS-6 和 Plethora Adaptive 等算法可以预测您何时会忘记并及时安排复习。

### 关键概念

- **文档**：源材料（PDF、EPUB、文章、视频）
- **摘录**：您从文档中摘录的要点或部分
- **学习项目**：根据摘录创建的抽认卡或问答卡
- **队列**：计划审核的项目，按优先级组织
- **复习**：您积极回忆并评价您的知识的课程

## 开始使用

### 首次发布

当您首次启动 Plethora 时，您将看到包含四个主要部分的 **仪表板**：

1. **队列** - 您的审阅队列（一开始为空）
2. **审查** - 积极的审查会议
3. **文档** - 您的文档库
4. **分析** - 进度统计

### 初始设置

1. **选择主题** - 导航至设置 → 外观 → 主题
   - 147 个可用内置主题（26 个现代主题，121 个传统主题）
   - 尝试“Modern Dark”或“Material You”以获得现代外观

2. **配置复习设置** - 设置→学习→算法
   - **算法**：FSRS-6（推荐）、Plethora Adaptive 或 Plethora Classic
   - **所需保留**：90%（默认）- 目标是您想要记住的程度
   - **每天学习**：建议初学者学习 20-50 项

3. **设置类别** - 设置 → 类别
   - 为不同主题创建类别（例如“编程”、“科学”、“语言”）
   - 类别有助于组织和过滤您的学习材料

### 你的第一个文档

让我们导入您的第一个文档：

1. 单击侧栏中的**文档**
2. 单击“**导入**”按钮（右上角）
3. 选择您的导入方式：
   - **本地文件**：选择 PDF、EPUB 或文本文件
   - **URL**：粘贴任何网址
   - **Arxiv**：粘贴研究论文 ID 或 URL
4.等待处理
   - 如果在“设置”中启用自动分割，则导入后文档将自动分割为摘录

### 导入文档

#### 方法一：本地文件

1. 点击**文档** → **导入**
2. 选择**本地文件**
3. 导航到您的文件并选择它
4. Plethora 将：
   - 提取文本内容
   - 计算阅读时间和字数
   - 提取元数据（标题、作者等）
   - 如果启用自动分段（设置 → 文档 → 导入时自动处理），自动将文档拆分为摘录

#### 方法2：URL导入

1. 复制任意网址
2. 单击**文档** → **导入** → **URL**
3. 粘贴网址
4. 单击**导入**
5. Plethora获取并处理内容

**支持的网站：**
- 新闻文章（大多数主要网站）
- 博客文章
- 文档页面
- 介质、子堆栈等

#### 方法 3：Arxiv 论文

1. 找到一篇 Arxiv 论文（例如，`https://arxiv.org/abs/2301.07041`）
2. 复制 URL 或论文 ID (`2301.07041`)
3. 单击**文档** → **导入** → **Arxiv**
4. 粘贴 URL 或 ID
5.增量下载：
   - 完整的PDF
   - 摘要
   - 作者
   - 出版日期
   - 参考文献

#### 方法 4：JSON Deck 导入

从 JSON 文件导入抽认卡组，其中包括日程安排数据（间隔、轻松因素、复习历史记录）。

**通过文件选择器导入：**

1. 点击**文档** → **导入** → **JSON**
2. 选择您的“.json”甲板文件
3. Plethora 创建一个牌组文档并导入所有卡牌，保留：
   - 日程安排（间隔、轻松因素、截止日期）
   - 回顾历史（重复、失误、保留率）
   - 卡状态（新卡、正在审核或已暂停）

**通过拖放导入：**

将“.json”文件直接拖到应用程序窗口上。如果文件与预期的牌组格式匹配，则会自动导入。

**JSON 甲板格式：**

该文件应该是将问题文本映射到卡片数据的平面对象：

```json
{
  “细胞的动力源是什么？”：{
    "answer": "线粒体。",
    “主题”：“生物学”，
    "deck_name": "细胞生物学",
    “轻松系数”：2.6，
    “间隔天数”：7，
    “重复次数”：3，
    “due_at”：“2026-04-20T12:00:00Z”
  }
}
````

**注释：**
- 每个“.json”文件都会创建一副牌。卡组名称来自“deck_name”字段。
- 进口卡默认使用Plethora Classic算法。您可以在导入后切换算法。
- 两次删除相同的文件不会创建重复项 - 现有的卡将被跳过。
- 标记为“known_pile: true”的卡将作为暂停导入。

## 学习系统

### 了解 FSRS-6

**FSRS-6**（自由间隔重复调度程序）是一种现代算法，它：

1. **跟踪内存状态**：对每张卡的内存强度进行建模
2. **预测遗忘**：估计您何时会忘记每件物品
3. **优化安排**：在最佳时间安排审核
4. **适应您**：从您的表现模式中学习

**关键指标：**
- **稳定性**：记忆能持续多久（越高=越稳定）
- **难度**：该项目对您来说有多难（1-10 级）
- **可检索性**：当前召回概率 (0-100%)

### 了解 Plethora Adaptive

**Plethora Adaptive** 是该系列上一代的调度器，它代表了 Plethora Classic 的重大演变，引入了内存稳定性建模和数据驱动的区间计算方法。

Plethora Adaptive：

1. **模型呈指数遗忘**：使用公式“R = 0.9^(t/S)”来计算可提取性——考虑到稳定性“S”，您在时间“t”记住一个项目的概率
2. **独立跟踪难度**：为每个项目维护一个难度值“D ∈ [0, 1]”，使用跟踪平均公式进行更新，该公式随着每次重复而变得更加敏感
3. **使用 3D SInc 矩阵**：从按分档难度、稳定性和可检索性索引的 21×21×21 矩阵中查找稳定性增加因子 - 这是 Plethora Adaptive 智能的核心
4. **优雅地处理失误**：失败时，将稳定性降低 0.87 倍（进一步除以累计失误）并重置重复计数器，但保留难度估计
5. **根据稳定性计算间隔**：从所需的保留目标导出下一个审核间隔：`间隔 = S × ln(1-FI) / ln(0.9)`

**关键指标：**
- **稳定性 (S)**：记忆在衰退之前持续的时间（以天为单位）
- **难度 (D)**：从 0（最简单）到 1（最难）的值，在每次审核后通过跟踪平均混合进行更新
- **可检索性 (R)**：当前召回概率，计算方式为 `0.9^(elapsed/S)`
- **SInc**：从 9,261 个条目矩阵中查找的稳定性增加因子 - 每次成功审核后稳定性增加多少
- **失误**：失败次数，这会影响后续失误的未来稳定性

### 了解 Plethora Precision

Plethora 的 **Plethora Precision** 选项是 **Algorithm Arena** - 对原始调度器的忠实重新实现，它在每个抽认卡上并行运行 **五个** 间隔重复算法，并将它们的预测混合到一个时间表中。五名竞争对手的默认混合权重为：

|插槽|型号|默认重量 |怎样学？ |
|------|---------|----------------:|------------|
| 1 | **Plethora Classic** | 6% |固定|
| 2 | **Plethora Classic 15** | 14% |持续不断地，在每次审查中|
| 3 | **Classic 19** | 45% |持续不断地，在每次审查中|
| 4 | **Plethora Precision**（35 参数“M4”遗忘曲线内核）| 25% |按需，通过“优化”按钮 |
| 5 | **FSRS** | 10% |按需，通过“优化”按钮 |

**混合如何工作。** 每个模型独立地生成卡的稳定性估计；竞技场采用加权平均值并从中得出下一个间隔。权重不是固定的——它们**适应你**。每次你回顾一张之前回顾至少一天前的卡片时，Arena 都会根据实际发生的事情（你记得或忘记）对每个模型的“先前”预测进行评分，并将权重推向最能预测你的模型。没有任何模型会被完全淘汰，因此启动缓慢的模型可以恢复。

**学习的两种方式：**

1. **每次审核时自动** - Plethora Classic 15 优化器和 Classic 19 矩阵立即更新，并且混合权重发生变化。这从您的第一次评论开始。您可以在“设置”→“学习”中观看：**竞技场权重**面板显示每个模型的当前百分比，一旦您有足够的评分评论，就会显示**R-Metric**（混合预测比单独的 Classic 19 好多少）。
2. **按需，当您单击“优化”时** — 五个竞争对手中的两个（Plethora Precision 内核和 FSRS）可以适合您的个人评论历史记录。这些拟合受到最少量的数据（大约数百天间隔的评论）和保留的验证检查的限制：只有当它真正击败了拟合尚未见过的评论的默认值时，拟合才会被接受。在此之前，“优化”按钮会报告“尚未足够的审核历史记录”，并且这两个模型将继续使用其默认参数。

**为什么它可能会说它还没有开始训练。** 只有间隔至少**一天**的评论才带有信号——首次评论和当天的重新评论不会告诉竞技场任何信息（每个模型都会正确预测你会记得），因此它们不计入总得分。如果您只有少量卡牌，则预计竞技场权重将保持在默认值附近，并且 R 度量将保持隐藏状态，直到这些卡牌开始按天间隔返回。这是预期的，不是错误。

**关键指标：**
- **稳定性（S）**：每个模型对记忆持续时间（天）的估计；竞技场融合了这些。
- **难度 (D)**：每个模型的项目难度估计。
- **竞技场权重**：每个模型的实时混合百分比，显示在学习设置中。
- **R-Metric**：混合相对于单独的 Classic 19 的相对改进，根据您的评论的衰减窗口计算。

**Plethora Precision 与 FSRS-6 有何不同：**
- FSRS-6 是一个单一的、成熟的生产调度程序，并且仍然是建议的默认值。
- Plethora Precision 是一个实验性集成，它将五种算法相互竞争，并让您自己的数据选择混合。它更复杂，需要更多的评论来个性化，但一旦它有足够的历史可供学习，它就可以超越任何单一模型。

#### Plethora Precision 审查后选择内存范围

在**设置→学习→算法竞技场→每次评级后**下，选择您想要的调度详细信息：

- **保持流程（推荐）** 立即提交竞技场的加权选择并移至下一张牌。这是默认设置。
- **显示竞技场**在符合条件的评分后暂停并打开**记忆地平线**，您的答案仍然可见，而五位模特将显示他们将在哪里进行下一次评论。

同样的紧凑选择出现在六个 Plethora Precision 评级控件下方，因此下一个评级可以使用不同的模式而无需离开评论。两种模式都运行和训练相同的五个收集模型；仅当您做出最终间隔选择时，此设置才会发生变化。决策步骤仍然仅限于正常的 Plethora Precision 抽认卡审查；文档阅读、补习模式、其他算法和**纯 Plethora Precision 模式**保留其现有的直接调度流程。

- 默认情况下选择**竞技场选择**。这是加权推荐，通常是您希望竞技场做出决定时的最佳选择。
- **Plethora Classic、Plethora Classic 15、Classic 19、Plethora Precision 和 FSRS** 让您可以特意遵循某一型号的具体建议进行本次审查。选择一个模型并不会给该模型带来额外的投票权重；未来的权重继续仅从预测准确性中学习。
- **自定义**接受对数时间透镜上的数量和单位或位置。显示的界限可以防止无效的计划，并且在您确认之前更新确切的截止日期。
- **为什么这个间隔**扩大了提案、当前权重和竞技场范围。该范围是五个模型提出的最早到最新的区间，而不是不确定性或置信区间。

在您按下 **安排......** 之前，不会提交任何内容。如果预览变得陈旧或保存失败，该卡将保留在原位，并保留您的成绩和选择，以便您可以安全地重试。 **返回评分** 放弃待定的评分并让您重新选择。

内存地平线打开时键盘控制：

|关键|行动|
|-----|--------|
| `←` / `→` |按时间顺序探索提案 |
| `1`–`5` |选择 Plethora Classic、Plethora Classic 15、Classic 19、Plethora Precision 或 FSRS |
| `A` |选择竞技场选择 |
| 'M' |选择自定义 |
| `Enter` 或 `Space` |确认显示的日程 |
| '逃脱' |返回评分 |

在免提音频审阅中，Plethora 会自动确认竞技场选择，因此即使选择 **显示竞技场** 进行视觉审阅，也可以继续播放。如果自动提交失败，审核仍然可以恢复。

### 文档阅读时间表（渐进阅读）

上面的算法（FSRS-6、Plethora Adaptive、Plethora Precision）是**抽认卡**调度程序——它们在问答、完型填空和基本卡片上进行训练，其目标是长期回忆。 **文档**（您通过增量阅读阅读的文章、论文和段落）由**单独的**调度程序调度，其目标不同：保持内容定期轮换，而不是最大限度地长期保留单个事实。

**两个调度程序，而不是一个。** 这是最大的混乱来源：

- **抽认卡** → FSRS-6 / Plethora Adaptive / Plethora Precision（您在学习设置中的选择）→ 写入训练这些算法的复习历史记录。
- **文档** → **增量阅读调度程序**（或其 **Engaging** 变体）→ 单独跟踪，并且 **根本不提供抽认卡算法。**

使用“再次/困难/良好/简单”对文档进行评级看起来与对抽认卡进行评级相同 - 出现相同的四个按钮 - 但等级会转到不同的位置并产生较短的、可预测的间隔：

|评级 |文档间隔 |抽认卡间隔（因算法而异）|
|--------------------|--------------------|------------------------------------------|
| **再次** |约 4 小时 |分钟|
| **硬** | ~1 天 | 1–2 天 |
| **好** | ~3 天 |几天-几周 |
| **简单** | ~7 天 |周 |

文档间隔的上限大约为 **30 天**，因此材料会保持轮换，连续的良好/简单评级会增加一个小的奖励，而连续的再次/困难评级会增加一个小的惩罚。

**引人入胜的调度程序。** 当您从队列中阅读文档时，Plethora 使用*引人入胜* 变体，它将新颖性注入、多样性平衡和机缘巧合叠加在基本间隔之上，使您的阅读会话保持多样化和有趣。这些参与功能会影响接下来出现的*哪个*文档，而不是基础的间隔数学。

**实用要点。**进行大量渐进阅读**不会**计入“训练”Plethora Precision 或 FSRS - 这些算法只会看到抽认卡评论。如果您希望它们个性化，您需要按日间隔查看抽认卡。 （这就是为什么即使您整周都在阅读文档，学习设置中的 Plethora Precision 面板也会显示“0 分”。）请参阅[了解 Plethora Precision](#understanding-sm-20) 了解哪些内容重要，哪些内容不重要。

### 评级系统

在审核期间，根据您的回忆对每个项目进行评分：

|评级 |标签|描述 |典型间隔 |
|--------|--------|-------------|--------------------|
| **1** |再次 |完全停电|约 10 分钟 |
| **2** |硬|付出巨大努力才记住| 1-2 天 |
| **3** |好 |想起来了| 5-7 天 |
| **4** |简单|回忆起来毫不费力| 10-14 天 |

**预览间隔：**

### 优先系统

每个文档、摘录和卡片都位于**单排序列表**中的某个位置 - 一个队列，所有元素类型在一起。优先级是排名。设置项目的优先级是告诉 Plethora *它属于您的集合中的哪个位置*，而不是为其附加分数。

**优先级是一个位置，而不是标签。**

这就是优先队列模型，这也是数字表现出其行为方式的原因。当您将某个项目设置为 70% 时，它会移动到您收藏中的 70%——高于您拥有的所有物品的大约 70%，低于前 30%。没有其他内容被重新编号；该物品只需插入即可。

对任何项目设置优先级 0-100：

- **90-100**：几乎高于一切——你首先想要的少数东西
- **70-80**：集合的上部
- **50-60**：包装的中间（新材料的默认值）
- **20-40**：下半部分——最终阅读它
- **0-10**：队列底部 - 参考、存档、有一天

**你的百分比会自行变化，这是正确的。**

因为百分比的意思是“目前为止*在集合中*”，所以它会随着周围集合的变化而变化。导入 500 篇新文章并对其中一半给予高度评价，而未受影响的旧文档将显示比上周更低的百分比 - 不是因为您将其降级，而是因为现在有更多材料位于其上方。相对于已经存在的所有内容，它在您的阅读顺序中的实际位置没有变化。

一个固定的数字会悄悄地欺骗你：在 100 项集合中设置的“70”和在 10,000 项集合中设置的“70”声称意味着相同的事情，但描述完全不同的位置。该百分比告诉您当前收藏的真实情况。

**N 的位置 X**

打开任何项目上的优先级弹出窗口，它会在滑块下方显示其实时排名 - *位置 1* 是您收藏中最重要的元素，*位置 N* 最不重要。一次大的导入后重新打开它，你会看到位置发生了变化。每次您打开该读数时，都会重新查看它。

**没有两个项目共享一个位置。**

将多个项目设置为相同的百分比不会将它们堆叠在一个点上 - 每个项目都放置在最后一个项目之后，因此队列保持严格的顺序。将 200 个文档批量设置为 60% 会将所有 200 个文档按顺序排列在 60% 附近，而不是创建 200 路平局，队列稍后必须任意中断。

**优先调度：**
优先级较高的项目在混合评论中显示的频率更高。优先级决定了“重要性”——当材料多于时间时，你首先要做的是什么。它与 FSRS 调度不同，FSRS 调度控制“时间”——给定项目下一次到期的时间。严重逾期的低优先级卡仍可能先于昨天审核的高优先级卡出现。

**摘录继承自其文档。** 新摘录从其源文档的优先级开始，更改文档的优先级会影响到仍保留旧值的摘录。一旦您手动设置数据提取的优先级，它就会停止继承并保留自己的位置。

### 队列排序和重新排序行为

了解队列如何对项目进行排序以及位置变化的原因有助于您优化学习流程：

1. **FSRS 调度和动态优先级评分**：
   - 每个项目的位置是使用其 FSRS 内存参数（截止日期、间隔、稳定性、可检索性衰减）结合您选择的智能队列策略预设（*最大化保留*、*积极追赶*、*最小化时间*或*探索性*）来计算的。
   - 当您完成审阅、推迟项目或做笔记时，内存参数会更新，项目在返回队列时自然会重新排名。

2. **加权选择随机化**：
   - 从后端提取项目时，审核引擎应用微妙的加权衰减算法（默认情况下“随机性 = 0.3”）。这使得具有相似优先级的项目接近顶部，同时引入轻微的变化以避免排队疲劳。

3. **状态同步**：
   - 执行队列修改操作（例如归档文档、批量编辑优先级或修改标签）会在返回队列视图时触发后台刷新，以保持列表与后端数据库状态保持一致。
   - 被动视图更改或选项卡切换保持稳定的本地顺序，而不会触发意外的重新洗牌。


### 神经回顾（“走向神经”）

神经复习是一种可选的探索模式，受 *Learn : Go Neural* 概念启发。它不是按顺序处理优先级队列，而是通过从单个起点（您当前正在阅读的项目）**传播激活**并显示与之相关的所有内容来构建新的审阅序列。当你想要在你的收藏中遵循一条线索而不是苦恼于到期的事情时，可以采用这种模式。

**如何使用它。** 在滚动模式下阅读时，单击顶部栏中的 **Go Neural**。会话切换到以当前文档、卡片或摘录为种子的传播激活队列；位置药丸变成紫色并显示“神经审查·剩余 N”。单击 **退出** 以返回到您阅读时的确切位置 - 神经审查永远不会改变您的优先级队列或调度。当队列不足时，它会自动从您刚刚完成的元素中重新填充。

**抽认卡和摘录仍然需要评级才能前进**，就像在正常滚动模式下一样，因此神经会话仍然有助于调度。文件自由推进。

**它如何决定什么是“相关的”。** 激活通过五种连接从种子向外传播，顺序如下：

1. **概念组（标签）。** 与种子共享标签的项目被视为概念对等项。因此，标记具有双重用途：它对搜索项进行分组*并*提供神经审查。未标记的项目没有概念对等项。
2. **元素间引用。** 显式交叉引用链接（如果存在）。
3. **后代。** 种子在知识树中的子级 - 文档中的摘录和卡片，摘录中的卡片。
4. **语义相似性。** 当您为 RAG 索引集合时（设置 → 嵌入和 RAG → 索引集合），神经审查还会显示内容与种子嵌入相似的文档。更多类似的文档出现得更快。如果您还没有建立索引，这个来源就会保持安静 - 其他四个来源仍然有效。
5. **父级和兄弟姐妹。** 种子的父级（摘录所在的文档）及其兄弟姐妹（同一文档中的其他摘录、同一摘录中的其他卡片以及附近的文档）。

更紧密的联系——直接子项、几乎相同的文档、共享标签——在队列中较早出现。当第一波产生的项目少于二十个时，激活会通过新到达的元素的邻居向外扩展，直到队列已满或没有其他可到达的元素。

**提示：**
- 标记您想要一起探索的项目 - 标记成为神经审查将遵循的概念组。
- 为您的收藏建立索引以解锁语义发现；没有它，神经审查仅依赖于树结构和标签。
- 神经审查对于您的正常队列是只读的。自由使用；您的优先顺序或截止日期没有任何变化。


### 智能队列

使用过滤器创建自定义队列：

**队列示例：**

2. 单击**新建队列**
3. 设置过滤器和排序顺序
4.命名并保存

### 标签感知调度 (TAS)

标签感知调度将语义智能添加到审阅队列中。
在“设置”中启用后，TAS 会应用两次后处理过程
您的到期项目无需更改基本 Plethora Precision/FSRS 间隔：

- **先决条件门控**：阻止标签先决条件尚未满足的项目
  达到配置的成熟度阈值。  基础材料是
  在高级主题出现之前稳定下来。
- **干扰抖动**：分离共享高相干标签的项目
  通过最小时间窗口，减少审阅期间的语义干扰。

TAS 是**选择加入**且**非破坏性** - 可以随时将其关闭
返回默认队列顺序。  被阻止或延迟的项目将保留
他们原来的预产期和间隔。

#### 启用 TAS

1. 打开 **设置 → 标签感知调度**。
2. 打开**启用 TAS**。
3. 可选择启用/禁用 **干扰** 和 **先决条件**
   子系统独立。
4. 根据您的喜好调整每个滑块。

|设置|范围 |默认|描述 |
|---|---|---|---|
|最小间隔 | 0–24 小时 | 4 小时 |共享高一致性标签的项目之间的小时数 |
|一致性阈值| 0.50–1.00 | 0.75 | 0.75只有具有一致性 ≥ this 的标签才会被分隔 |
|成熟度比率| 0.50–1.00 | 0.70 | 0.70先决条件标签中必须成熟的项目比例 |

#### 设置先决条件

标记先决条件可让您控制主题出现的顺序：

1. 打开**标签管理**（从媒体面板或库工具栏）。
2. 单击顶部的**先决条件**按钮。
3. 单击标签名称以选择它进行编辑。
4.在编辑器面板中，勾选**之前**必须学习的标签
   该标签的项目可以出现在队列中。
5. 单击“**保存先决条件**”。

右侧的**依赖关系图**可视化关系 - 箭头
从先决条件指向依赖标记。  循环依赖是
在保存时检测并拒绝。

> **注意**：标签会自动从您现有的项目同步。
> 如果没有出现标签，请先标记一些项目，然后重新打开标签
> 管理 — TAS 将检测并注册它们。

#### 读取队列

当 TAS 处于活动状态时，队列标题会显示 **TAS 活动** 徽章
包含已准备和已阻止项目的计数。

|徽章|意味着|
|---|---|
| 🟡“等待‘标签’成熟度（45%）”|被阻止——先决条件标签仅成熟 45% |
| 🔵“延迟以避免干扰‘标签’”|延迟 — 最近安排了一个共享高一致性标签的项目 |

#### 强制物品

您可以覆盖单个项目的 TAS：

- 单击任何被阻止或延迟的项目旁边的 **强制显示** 链接
  立即将其添加到当前审阅会话中。
- 覆盖仅适用于会话 - 该项目将根据 TAS 重新评估
  下届会议的规则。

#### 相干性是如何计算的

一致性衡量标签项目的语义紧密程度：

1. 从队列视图使用**计算语义图**。  这需要
   配置的嵌入提供程序（OpenAI、Ollama、Cohere、OpenRouter）。
2. 每个项目的标题、内容和标签将发送至您选择的法学硕士
   提供者和嵌入向量被存储。
3.嵌入后，TAS自动计算每个标签的**质心**
   （带有该标签的所有项目的平均向量）和**连贯性**（平均
   这些项目的成对余弦相似度）。
4. 一致性值显示在标签管理中每个标签旁边。

尚未嵌入的标签被视为一致性 = 0 — 否
干扰抖动适用于这些标签。

#### 标签成熟度

当某个项目的 Plethora Precision/FSRS 稳定性达到该项目的标签时，该标签就**成熟**
满足或超过标签的“maturityThreshold”（默认 0.8）。  的
总体成熟度比率为“matureCount / itemCount”。

- 先决条件编辑器中的进度条显示每个标签的当前状态
  成熟度比率。
- 先决条件门控使用配置的“maturityRatio”来决定
  先决条件标签是否“满足”足以解锁依赖项
  标签以供审查。

#### 尖端

- **仅从先决条件开始**。保持干扰抖动关闭，直到
  您已经运行了嵌入管道并具有一致性值。
- **使用粒度标签**。 `calculus.limits` → `calculus.derivatives` 是
  比一个广泛的“微积分”标签更有效。
- **观察区块率**。如果许多项目被阻塞，则降低成熟度
  比率或简化先决条件图。
- **力秀是你的安全阀**。如果 TAS 过于激进
  特定项目，强制显示它 - 不会损害底层调度数据。

### 同步设置

Plethora 通过**共享同步室**在您的设备上同步您的阅读数据。没有帐户，没有服务器登录，也没有 API 密钥 - 每个知道相同同步代码的设备都会加入同一个房间并共享相同的数据。这是应用程序中唯一的同步系统。

#### 它是如何工作的

- 第一次打开同步设置时，每个设备都会生成一个**同步代码**（随机字符串）。
- 与您的其他设备共享该代码 - 复制它或扫描同步设置中显示的二维码。
- 当两个设备共享代码时，只要它们同时在线，它们的阅读数据（文档、摘录、学习项目、复习历史记录、设置）就会自动同步。附加到文档的文件通过同一房间同步。
- 同步代码是唯一授予房间访问权限的东西。保持其私密性 - 任何拥有它的人都可以读取您的同步数据。

#### 连接您的设备

1. 在您的第一台设备（例如台式机）上打开 **设置 → 同步**。请注意此处显示的同步代码，或显示其二维码。
2. 在您的第二台设备（例如您的手机）上打开 **设置 → 同步**。
3. 要么：
   - 点击**扫描**并将相机对准第一台设备上的二维码，或者
   - 将同步代码粘贴到“加入另一个代码”字段中，然后点击“**加入**”。
4. 第二台设备加入房间并立即开始同步 - 无需重新加载或重新启动。
5. 对您想要保持同步的每个设备重复此操作。

> **提示：** “新建”按钮会生成新的同步代码。仅当您想重新开始时才使用它 - 使用旧代码的设备将停止与使用新代码的设备同步。

#### 同步什么

- 文档及其元数据
- 摘录（重点和注释）
- 学习项目（抽认卡、完形填空、问答）
- 查看历史记录和调度状态
- 应用程序设置
- 文档附加文件（PDF、EPUB 等）

#### 文件自动下载

在 **文件同步** 下，选择将新文件拉到每个设备上的积极程度：

- **始终** — 自动下载房间中出现的每个文件。
- **仅限 WiFi** — 仅在 WiFi 上自动下载（对移动数据套餐有用）。
- **手动** — 从不自动下载；每个文件都会显示一个下载按钮，您可以在需要时点击该按钮。

#### 端到端加密（可选）

默认情况下，同步在“仅 TLS”模式下运行：您的数据通过网络加密传输，同步代码充当共享密钥。如果您想要更强的保护，可以启用**端到端加密**，这会在设备上的数据离开之前对其进行加密，因此同步服务器只能看到密文。

启用加密后，二维码会嵌入您的房间秘密 - 仅与您信任的设备共享。

#### 隐私

您的所有阅读数据首先存储在您的本地设备上。同步是一种可选的便利功能，可以在共享房间中跨设备镜像数据。除了您个人配置的 AI 提供商之外，不会将任何内容发送到任何服务器。

#### 备份与恢复

Plethora 提供完整的备份和恢复系统来保护您的学习数据并在设备之间迁移。

#### 完整的应用程序备份

**备份什么：**
- **设置**：所有首选项、主题、学习参数
- **文档**：所有带有元数据的导入文档
- **摘录**：所有亮点和摘录内容
- **学习项目**：所有抽认卡、完形填空、问答卡
- **调度数据**：算法记忆状态（稳定性、难度、间隔）、截止日期
- **集合**：所有集合和文档分配
- **UI状态**：侧边栏状态，主题首选项
- **可选**：实际文档文件（PDF、EPUB 等）

**创建备份：**

1. 转到 **设置 → 导入/导出 → 完整应用程序备份**
2. 单击“**打开备份和还原**”
3. 选择**导出备份**
4. 添加可选标签（例如“重新格式化 PC 之前”）
5. 选择是否包含文档文件：
   - **仅元数据**：较小的文件 (~KB-MB)，单独重新导入文件
   - **包含文件**：更大的文件（~MB-GB），完整的独立备份
6. 单击 **导出备份** 并保存 `.incrementum` 文件

**文件格式：**
- 扩展名：`.incrementum`
- 格式：带标题注释的 JSON
- 命名：`incrementum-backup-[标签]-[日期]-[时间].incrementum`

**从备份恢复：**

1. 转到 **设置 → 导入/导出 → 完整应用程序备份**
2. 单击“**打开备份和还原**”
3. 选择**导入备份**
4. 选择您的“.incrementum”文件
5. 预览备份中的内容：
   - 文件计数
   - 提取计数
   - 学习项目计数
   - 收藏数量
   - 是否包含文件
6. 配置导入选项（可选）：
   - **导入内容**：选择特定数据类型
   - **重复处理**：跳过、替换或合并
   - **导入文件**：是否恢复文档文件
7. 单击“**导入备份**”
8.等待导入完成（显示进度）

**重复处理策略：**
- **跳过**：跳过已经存在的项目（大多数情况下推荐）
- **替换**：用备份版本覆盖现有项目
- **合并**：创建所有项目的新副本（可能会创建重复项）

**使用案例：**

|场景|推荐方法 |
|----------|---------------------|
| **迁移到新计算机** |使用文件导出，在新机器上导入 |
| **重大更改前的备份** |快速仅元数据备份 |
| **设备之间同步** |导出/导入工作流程 |
| **分享收藏** |导出特定集合 |
| **归档旧数据** |出口并长期储存|
| **重新格式化后恢复** |导入带有文件的完整备份 |

**重要说明：**
- **调度保留**：所有算法类型的所有调度数据（稳定性、难度、到期日期）都被准确保留
- **文件路径**：在没有文件的情况下导入时，您需要重新导入原始文档。 Plethora将通过内容哈希匹配它们并恢复元数据
- **版本兼容性**：备份向前兼容，但可能不适用于较旧的应用程序版本
- **存储**：确保备份安全 - 它们包含您的个人学习数据

- 备份频率（每日、每周）
- 保留的最大备份数 (5-50)
- 备份位置

#### 设备端 Apple Intelligence（Mac 与 iPhone）

在支持的 Apple 设备上，Plethora 可以使用 **Apple 基础模型**（Apple Foundation Models）——Apple 内置的设备端语言模型——运行多项 AI 功能。这与云端提供商（OpenAI、Ollama 等）**相互独立**，**无需 API 密钥**。

**它可以做什么：** 在设备端生成文本，用于智能标签、摘要、闪卡生成、询问资料库回答等任务。

**它不能做什么：** Apple 基础模型**不会**转写视频或音频、**不会**朗读文本（TTS）、**不会**分析照片。转写和朗读请使用 Plethora 的**音频转写**和**文本转语音**设置。

**系统要求：**
- **Mac：** macOS 26 或更高版本、Apple 芯片、已在系统设置中开启 Apple 智能
- **iPhone / iPad：** iOS 26 或更高版本、已启用 Apple 智能、兼容设备

**如何开启：**
1. 打开 **设置 → AI 提供商设置**
2. 向下滚动到 **设备端 AI**
3. 开启 **优先使用设备端 AI**
4. 确认 **Foundation Models**（或 **Apple Intelligence**）显示为 **就绪**

当状态为「就绪」时，Plethora 会自动为支持的任务使用设备端 Apple AI。您无需将 Apple 添加到云端提供商列表。

**设备端 Apple AI 可以做什么：**

| 功能 | 支持设备端？ |
|---------|------------------|
| 智能标签 | 是 |
| 摘要 / 解释段落 | 是 |
| 询问资料库（基于资料库内容回答） | 是 |
| 从文本生成闪卡 | 是 |
| 提取要点、学习问题 | 是 |
| Studio 复习提示 | 是 |
| 转写视频或有声书 | 否 — 请使用 **设置 → 音频转写** |
| 朗读文本（TTS） | 否 — 请使用 **设置 → 文本转语音** |
| 描述图片 / OCR | 否 — 请使用 OCR 或视觉相关功能 |

**隐私：**
- 处理默认**完全在您的设备上进行**
- **允许云端回退**默认关闭 — 若设备端 AI 无法完成任务，Plethora **不会**在未经您同意的情况下将内容发送到付费云端提供商
- 若希望设备端 AI 不可用时自动改用已配置的云端提供商，可以手动开启云端回退

**如果状态不是「就绪」：**

| 状态 | 含义 | 建议操作 |
|--------|---------------|-------------|
| 就绪 | 设备端 AI 可用 | 正常使用 AI 功能即可 |
| 正在下载… | 系统模型仍在安装 | 请等待，然后在设备端 AI 中点击 **刷新** |
| 已关闭 | Apple 智能未开启 | 在系统设置中开启 Apple 智能 |
| 不符合条件 | 设备或地区不支持 | 请改用云端或本地提供商 |
| 系统版本不支持 | macOS/iOS 低于 26 版 | 请更新系统，或改用其他提供商 |

**提示：** 长文档会自动处理 — Plethora 会将其拆分为适合设备端上下文窗口的片段，然后合并结果。您无需手动配置此项。

**设置（带有 llama.cpp 的 GLM-OCR）：**

llama.cpp 为 GLM-OCR 提供轻量级本地 LLM 服务器，无需 GPU。它在端口 8080 上使用兼容 OpenAI 的 API。

1. **构建 llama.cpp** （如果尚未构建）：
   ````bash
   git 克隆 https://github.com/ggml-org/llama.cpp.git
   cd 骆驼.cpp
   cmake -B 构建
   cmake --build 构建 --config Release -j$(nproc)
   ````

2. **下载多模式模型**（GGUF格式）：
   ````bash
   # Qwen2.5-VL（推荐用于OCR）
   Huggingface-cli 下载 bartowski/Qwen2.5-VL-7B-Instruct-GGUF \
     Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf --local-dir 模型/
   ````

3. **启动服务器**：
   ````bash
   ./build/bin/llama-server \
     -m 型号/Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf \
     --端口 8080 --主机 0.0.0.0 -c 16384 -t $(nproc)
   ````

4. **Plethora 配置**：
   - 设置 → OCR → 提供商：**GLM-OCR（本地）**
   - 后端：**vLLM (GPU)**（这是 llama.cpp/vLLM 模式 — 适用于两者）
   - 端点：`http://localhost:8080/v1`
   - 模型：您的模型文件名（例如“Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf”）

**性能提示：**
- 对于长文档使用 `-c 16384` 或更高值（默认 4096 对于大多数 OCR 任务来说太小）
- 使用 `-t $(nproc)` 使用所有 CPU 线程
- Q4_K_M 量化为 CPU 推理提供最佳质量/速度权衡
- 对于 GPU 加速，构建具有 CUDA、Metal 或 Vulkan 支持的 llama.cpp

**设置（带有 vLLM 的 GLM-OCR）：**

vLLM 为大型模型提供 GPU 加速推理。需要具有足够 VRAM 的 NVIDIA GPU。

````bash
pip安装-U vllm
vllm 服务 zai-org/GLM-OCR --allowed-local-media-path / --port 8080
````

然后以相同的方式配置 Plethora（端点“http://localhost:8080/v1”）。

**设置（GLM-OCR 与 Ollama）：**

最简单的入门选项 — Ollama 自动管理模型下载和运行时。

1. 设置 → OCR → 提供商：**GLM-OCR（本地）**
2. 后端： **Ollama (CPU)**
3. 单击**下载 Ollama**（如果未安装）
4. 单击“**启动运行时**”
5. 设置模型（例如 `llava:7b` 或 `qwen2-vl:7b`）
6. 单击**拉模型**

**数学 OCR：**
- 方程的专门处理
- 乳胶输出
- 符号识别
- 最适合：科学论文、教科书

## 提示和最佳实践

### 卡片制作

**做：**
- 使卡片具体化（每张卡片一个事实）
- 使用简单、清晰的语言
- 在答案中包含上下文
- 添加相关示例
- 使用完形填空来建立关系
- 保持问题简洁

**不要：**
- 将多个事实放入一张卡片中
- 使用含糊的措辞
- 让问题太简单或太难
- 复制大文本块
- 使用没有定义的缩写

**示例 - 坏卡：**
````
问：线粒体的功能是什么？
它与细胞呼吸中 ATP 的产生有关吗？
答：【段落解释】
````

**示例 - 好卡：**
````
卡1：
问：线粒体的主要功能是什么？
A：通过细胞呼吸产生ATP

卡2：
问：线粒体利用什么过程产生 ATP？
A：细胞呼吸（有氧）

卡3：
问：线粒体产生的能量货币是什么？
A：ATP（三磷酸腺苷）
````

### 学习常规

**每日时间表（20-30 分钟）：**
1. **上午**：查看到期卡（15 分钟）
2. **全天**：从阅读中创建摘录
3. **晚上**：根据摘录创建卡片（10-15 分钟）

**每周时间表：**
- **周一至周五**：定期审查和卡片创建
- **周六**：较长的学习课程（1-2 小时）
- **周日**：回顾分析、调整目标、组织

**管理大容量：**
- 设置每日审核限制（例如 50 张卡片）
- 按类别划分优先级（专注于一个主题）
- 使用智能队列来分解任务
- 每20-30分钟休息一次

### 保留优化

**提高保留率：**
- 诚实评分（不要夸大评分）
- 持续回顾（每天最好）
- 充足的睡眠（睡眠期间记忆会巩固）
- 主动回忆（不要偷看，先思考）
- 间隔评论（不要死记硬背）

**处理遗忘：**
- 正常遗忘 10-20%（取决于目标保留率）
- “再次”卡是学习机会
- 如果经常忘记（>30%），请考虑：
  - 降低所需的保留率 (85-90%)
  - 创建更简单的卡片
  - 添加更多上下文
  - 更频繁地复习

### 类别组织

**最佳实践：**
- 从广泛开始，然后细分
- 示例：`编程`→`编程/Python`→`编程/Python/异步`
- 使用一致的命名
- 不要创建太多（5-10 个是可以管理的）
- 合并未使用的类别

**类别结构示例：**
````
├── 编程
│ ├── Python
│ ├── 铁锈
│ └── 算法
├── 语言
│ ├── 西班牙语
│ └── 日语
├── 科学
│ ├── 物理
│ └── 生物学
└── 专业
    ├── 项目管理
    └── 系统设计
````

### 优先级管理

**优先准则：**
- **100（关键）**：考试准备、紧急工作项目
- **80-90（高）**：当前课程，主动学习
- **60-70（中）**：持续的兴趣、常识
- **40-50（低）**：很高兴知道，补充
- **0-20（存档）**：仅供参考，很少回顾

**优先调度：**
- 专注于每日评论的 80+ 优先级
- 每隔几天复习60-70
- 每周回顾 40-50 次
- 每月或按需审核 0-20 次

### 使用预览间隔

**预览间隔**功能可以准确显示所有四个评级的每张卡接下来出现的时间。

**使用方法：**
1.读卡
2.检查评级按钮下方的预览间隔
3. 根据以下条件选择评级：
   - 您当前的回忆
   - 您想多久再次看到它
   - 您的日程安排（例如即将举行的考试）

**策略示例：**
- 两周内考试：对重要卡片进行评分“简单”，以便很快再次看到它们
- 忙碌的一天：评价“好”或“简单”以间隔评论
- 想要掌握：评价“难”以更频繁地复习

### 管理不堪重负

**到期卡太多？**
1. 设置审核限额（设置→审核→每日上限）
2. 关注高优先级项目
3. 暂时暂停低优先级类别
4.考虑稍微降低所需的保留率

**内容太多而无法处理？**
1. 逐步导入文件
2.只提取关键点（不是全部）
3.有选择地创建卡片
4.使用类别来组织

**倦怠？**
1.休息一下（没关系！）
2.减少每日限额
3. 暂停非关键类别
4.一次专注于一个类别

## 故障排除

### 常见问题

#### 卡片未出现在审核中

**可能的原因：**
- 今天审核的所有卡片
- 卡被暂停
- 过滤活跃的隐藏卡

**解决方案：**
1. 在“审阅”选项卡中检查“到期”计数
2. 检查队列 → 确保卡未暂停
3. 清除过滤器
4. 检查审核日期（也许是将来安排的卡片）

#### 保留率低

**症状：** 忘记很多卡片，频繁“再次”评级

**解决方案：**
1. **检查卡片质量**：卡片是否清晰？每张卡一个事实？
2. **降低所需保留率**：尝试 85% 而不是 90%
3. **更频繁地复习**：每天复习，而不是临时抱佛脚
4. **添加上下文**：答案中的更多信息
5. **简化卡片**：将复杂的卡片分解为更简单的卡片

#### 同步冲突

**症状：** 重复卡、同步后数据不匹配

**解决方案：**
1. 选择冲突解决策略（设置→同步）
   - **本地胜利**：保留您的更改
   - **远程获胜**：接受服务器更改
   - **询问**：手动解决每个冲突
2.定期同步以尽量减少冲突
3. 使用一台主要设备

#### 导入失败

**症状：** 文档导入失败或错误

**解决方案：**
1. **检查文件格式**：确保支持的格式（PDF、EPUB等）
2. **检查文件大小**：非常大的文件可能会超时
3. **检查 URL**：某些网站阻止自动访问
4. **检查互联网**：URL导入需要连接
5. **尝试替代方案**：对网页内容使用复制粘贴

#### 性能问题

**症状：** 加载缓慢、滞后、冻结

**解决方案：**
1. **大型数据库**：存档旧卡（设置→数据→存档）
2. **许多图像**：图像加载速度变慢
3. **系统资源**：关闭其他应用程序
4. **重建数据库**：设置→数据→重建（最后的手段）

#### OCR 不工作

**症状：** OCR 失败或结果不佳

**解决方案：**
1. **检查 API 密钥**：有效且有积分（云提供商）
2. **检查图像质量**：清晰、高分辨率的图像效果最佳
3. **检查语言**：选择正确的语言
4. **尝试替代提供商**：有些对于某些内容效果更好
5. **本地 OCR**：如果互联网问题，请使用 Tesseract

#### llama.cpp 没有响应

**症状：** “调用 LLM 时出错”或连接拒绝 localhost:8080

**解决方案：**
1. **检查服务器是否正在运行**: `curl http://localhost:8080/v1/models`
2. **启动服务器**：参见上面的[OCR设置](#ocr-optical-character-recognition)
3. **上下文大小太小**：使用 `-c 16384` 或更高版本重新启动
4. **端口正在使用**：另一个进程可能正在使用端口8080；检查“lsof -i :8080”
5. **内存不足**：使用较小的量化（Q3_K_M 而不是 Q4_K_M）或较小的模型

#### 奥拉马未开始

**症状：** GLM-OCR Ollama 运行时无法启动

**解决方案：**
1. **安装 Ollama**：使用“设置”→“OCR”中的“下载”按钮，或从 ollama.com 安装
2. **检查二进制路径**：如果不在默认位置，则设置 Ollama 二进制路径
3. **Linux权限**：您可能需要`sudo`来安装或运行Ollama服务

### 获取帮助

**资源：**
- **文档**：检查“docs/”文件夹以获取详细指南
- **GitHub 问题**：报告错误和功能请求

## 常见问题解答

**问：如何将新闻通讯添加到 Plethora？**
答：您可以通过两种方式添加新闻通讯：
1. **新闻通讯目录**：点击 RSS → 新闻通讯图标 (📬) → 浏览并订阅精选新闻通讯
2. **直接 URL**：复制任何时事通讯 URL（Substack、Beehiiv 等）→ RSS → 添加 Feed → 粘贴 URL。 Plethora 将自动发现 RSS 提要。

**问：为什么我的 NotebookLM 视频、音频、信息图或幻灯片不显示？**
答：媒体工件需要先生成并准备好文件，然后才能预览。等待生成完成，然后重新打开工件 - 视频/音频和信息图表自动通过备用媒体路径重试，并且幻灯片在未加载时提供“使用备用查看器打开”选项。如果仍然失败，请在“设置”→“集成”中重新连接 NotebookLM 并重新生成工件。

**问：支持哪些新闻通讯平台？**
答：Plethora 支持来自 Substack、Beehiiv、Ghost blogs、Buttondown、ConvertKit、Revue、Medium 和 WordPress 网站的 RSS 源。大多数时事通讯都会发布 RSS 源 - 检查时事通讯网站上的 RSS 链接或尝试将“/feed”添加到 URL。

**问：我每天应该复习多少张卡片？**
答：从每天 20-50 个开始。根据您的日程安排和目标进行调整。一致性比数量更重要。

**问：我每天可以创建多少张卡片？**
答：想要多少就多少，但注重质量而不是数量。 10-20 张制作精良的卡片比 50 张劣质卡片要好。

**问：我的目标留存率应该是多少？**
答：90% 是建议的默认值。如果您的评论过多，则调整为 85%；对于关键材料，则调整为 95%。

**问：我可以对语言使用 Plethora 吗？**
答：当然！它非常适合词汇、语法和句子卡。使用完形填空卡来了解语法模式。

**问：如何处理数学方程？**
答：在卡片中使用 LaTeX 语法。对于 OCR，请使用 Mathpix 提供程序以获得数学内容的最佳结果。

**问：我可以与 Anki 同步吗？**
答：是的！在设置 → 集成 → Anki 中配置 AnkiConnect 进行双向同步。

**问：暂停和删除有什么区别？**
A：暂停会暂时隐藏卡牌（可以取消暂停）。删除将永久删除（可以从备份中恢复）。

**问：我应该多久复习一次？**
答：每天是理想的选择。如果你错过了几天，卡片会累积，但不会“丢失”——只要有机会就补上。

**问：我可以在多个设备上使用 Plethora 吗？**
答：还不能直接同步，但您可以通过 Dropbox/Google Drive 同步数据，或使用浏览器扩展程序。

**问：我的数据是私密的吗？**
答：是的！所有数据都存储在本地。云同步已加密。除配置的 AI 提供程序外，不会向服务器发送任何数据。

**问：如何导出我的卡？**
A：设置 → 备份 → 导出，或使用 Anki 同步导出为 .apkg 格式。
