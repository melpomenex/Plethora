# Android build notes

`src-tauri/gen/android/` is generated by `tauri android init`. Re-running it
overwrites hand edits. Everything hand-edited in that tree is listed here so it
can be re-applied.

## Hand edits in `gen/android`

| File | Edit | Why |
| --- | --- | --- |
| `app/build.gradle.kts` | `ndkVersion = "27.2.12479018"` | AGP otherwise picks a patch that is not installed locally and the build fails with `[CXX1104]`. |
| `build.gradle.kts` | `kotlin-gradle-plugin` pinned to **2.2.21** and KSP to **2.3.11** (Tauri generates Kotlin 1.9.25) | Prompt beta4 carries Kotlin 2.3 metadata and structured output requires KSP 2.3.6+. Kotlin 2.2 can read the next metadata version while retaining compatibility with Tauri's generated legacy `kotlinOptions.jvmTarget` DSL. Kotlin 2.3.21 and 2.4.10 were rejected because both make that generated app assignment a build-script error, which would require an additional generated-file edit. |

Everything else for the on-device AI feature lives in
`src-tauri/plugins/android-genai/` — dependencies, R8 keep rules, manifest
override, Kotlin sources — which `tauri android init` does not touch. An
`implementation` dependency in the plugin module already reaches the APK, and
its `consumer-rules.pro` is applied by the app's own R8 pass, so duplicating
either in `app/` would only create something to lose.

### Kotlin 2.x notes

`android-tts` and `folder-import` both compiled clean under the previous 2.2.20
pin (only the pre-existing deprecation warnings). The coordinated 2.4.10 spike
must re-verify all three plugin modules. `kotlinOptions { jvmTarget = "1.8" }`
is deprecated — if a future Kotlin bump removes it, switch the
three plugin modules to `compilerOptions { jvmTarget.set(JvmTarget.JVM_1_8) }`.

## ML Kit GenAI version pinning

- `genai-summarization` has exactly one published version, `1.0.0-beta1`. It is
  pure Java — no Kotlin metadata constraint.
- `genai-prompt` is pinned to `1.0.0-beta4`, with Kotlin **2.2.21**, KSP
  **2.3.11**, and `genai-schema-compiler:1.0.0-alpha1`. Prompt beta4 carries
  Kotlin **2.3** metadata, which the Kotlin 2.2 compiler can read. This exact
  matrix compiled all three Incrementum Android plugins and passed the signed
  universal release/R8 build on 2026-08-13.
- The artifacts are **not** `com.google.android.gms:play-services-mlkit-genai-*`;
  no such coordinates exist on Google's Maven repo.

## minSdk override

All three genai AARs declare `minSdkVersion 26`; the app is `minSdk 24`. The
plugin's `AndroidManifest.xml` merges them with
`tools:overrideLibrary="com.google.mlkit.genai.summarization,com.google.mlkit.genai.prompt,com.google.mlkit.genai.common"`
rather than raising the app's floor, which would drop Android 7.x users for a
feature they could never use (AICore does not exist before Android 8).

This is safe because no ML Kit class is touched eagerly: the clients are built
lazily inside `checkStatus`, whose `catch (e: Throwable)` covers the
`NoClassDefFoundError` an API 24-25 device would raise and reports
`device_unsupported`. If the override ever proves fragile, raising `minSdk` to
26 is the alternative.

## Re-applying after `tauri android init`

1. Restore the `ndkVersion` line in `app/build.gradle.kts`.
2. Restore the Kotlin 2.2.21 and KSP 2.3.11 classpath lines in `build.gradle.kts`.
3. `npm run tauri:android:build` to confirm.
