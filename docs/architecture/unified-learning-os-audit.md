## 1. Executive Summary

Plethora already possesses a deep, high-quality local-first engineering foundation: a Tauri 2.0 / Rust (`sqlx` SQLite with 170 sequential migrations) + React 19 / TypeScript desktop/mobile/PWA stack, a production dual-trace FSRS-7 scheduler, a pure deterministic DAQE ranker, an E2EE Sync v2 transactional outbox, a physically isolated Health Vault (`health/health.db`), strict `isLocalOnly`/`isAiExcluded` privacy enforcement, a single-instance canonical reader wrapper for Study Mode, versioned Study Plans with prerequisite DAGs and Guided Reading Trails, resumable Examinations with rubric grading, and a SQLite-backed `learning_evidence` / `learning_gaps` / `learning_remediations` pipeline.

However, these capabilities were built as distinct vertical waves and do not yet operate as **one cohesive personal learning operating system**:

1. **Fragmented learning state and events:** Review and study activity are split across 4 SQLite tables (`review_results`, `review_log`, `item_activity_log`, `video_extract_review_events`) plus an in-memory `reviewSync.ts` bus, while `reading_goals.rs` is unimplemented `TODO` stubs and `knowledgeGraphStore.ts` / `knowledgeHealthStore.ts` persist competing state in `localStorage`.
2. **Exam-only learner model:** `learning_evidence_repository.rs` currently ingests only `exam_grades` (excluding reading exposure, delayed FSRS retention, Socratic/formative practice, application/transfer dimensions, manual declarations, and evidence invalidation).
3. **Rigid goal representation:** Structured `study_plans` are disconnected from casual exploration, retention goals, language learning, and Smart Feeds continuous learning.
4. **No unified session/activity runtime:** Reading, reviewing, practicing, guided trails, and exams launch as separate tabs/surfaces rather than participating in a shared, persisted, resumable heterogeneous `LearningSession`.
5. **Narrow DAQE scope:** DAQE currently ranks only `due_candidate_pool` (documents, extracts, flashcards) rather than orchestrating heterogeneous learning activities across goals, curricula, remediation, and session focus profiles.
6. **Widget-centric dashboard and fragmented navigation:** `DashboardTab.tsx` (2,102 LOC) presents disconnected widgets rather than an actionable **Today** workspace with a one-click personalized `Start learning` launcher; 8 legacy React Router files in `src/routes/` and several superseded graph/pane components remain dead or duplicated.
7. **Missing personal coach & optional motivation persistence:** No deterministic coaching opportunity detector exists, and `reading_goals.rs` (targets, streaks, achievements) is stubbed out.

## 4. Key Architectural Findings & Reusable Infrastructure

### 4.1 Competing Sources of Truth to Reconcile
1. **Knowledge Graph & Health:** `src/stores/knowledgeGraphStore.ts` & `src/stores/knowledgeHealthStore.ts` (`localStorage`) vs SQLite `concepts`/`concept_links`/`learning_concept_summaries`. Canonical source of truth MUST be SQLite; frontend stores become read-through projections/caches.
2. **Review & Activity History:** `review_results`, `review_log`, `item_activity_log`, `video_extract_review_events` + in-memory `reviewSync.ts`. Keep FSRS/SM20 tables intact for compatibility, and add a transactional `learning_events` log + unified frontend event bus so every completion is idempotently observed across all views.
3. **Reading Goals vs Study Plans:** `reading_goals.rs` (stub) vs `study_plans`. Unify under `learning_goals` (with `study_plans` as optional structured curriculum) and `motivation_preferences` (for daily/weekly targets).

### 4.2 Duplicate / Dead Code Identified (Do Not Extend)
- 8 unused React Router files in `src/routes/` (`index.tsx`, `dashboard.tsx`, `documents.tsx`, `queue.tsx`, `review.tsx`, `settings.tsx`, `analytics.tsx`, `study-plans.tsx`).
- Legacy `src/components/common/CommandPalette.tsx` (only types imported), `src/components/viewer/study-mode/OriginalSourcePane.tsx` (unmounted), `src/components/tabs/ScreenshotTab.tsx` (unregistered), `KnowledgeGraph.tsx`/`KnowledgeSphere.tsx` legacy JSX, `NewsletterDirectoryEnhanced.tsx`.

### 4.3 Canonical Infrastructure to Reuse (Never Duplicate)
- **Scheduler:** `src-tauri/src/algorithms/fsrs7/` & `src/algorithms/fsrs7/` (sole authoritative item-level SRS).
- **Queue Ranker:** `src-tauri/src/algorithms/daqe/ranker.rs` & `src-tauri/src/commands/queue_daqe.rs`.

- **Privacy & Isolation:** `src-tauri/src/database/document_privacy.rs`, `src/lib/ai/assistant/privacyGate.ts`, `src-tauri/src/health/db.rs`.
- **Sync:** `src-tauri/src/sync/journal.rs` (`journal_entity`).
