# Plethora ユーザーハンドブック

**増分読み取りと間隔をあけた繰り返しをマスターするための完全ガイド**

---

## はじめに

### プレソラとは何ですか?

Plethora は、実証済みの 2 つの技術を組み合わせた強力な学習アプリケーションです。

**増分読み取り** - 大量の情報を、時間をかけて管理しやすい小さな塊に分けて処理します。記事を最初から最後まで読むのではなく、重要なポイントを抽出し、徐々に理解を深めていきます。

**間隔をあけた繰り返し** - 科学的に最適化された間隔で教材を見直し、記憶力を最大限に高めます。 FSRS-7 は、いつ忘れそうになるかを予測し、ちょうどいいタイミングでレビューをスケジュールします。

### 主要な概念

- **ドキュメント**: ソース資料 (PDF、EPUB、記事、ビデオ)
- **抜粋**: 文書から抽出した重要なポイントまたはセクション
- **学習アイテム**: 抜粋から作成されたフラッシュカードまたは Q&A カード
- **キュー**: レビューが予定されている項目。優先度別に整理されています。
- **レビュー**: 知識を積極的に思い出して評価するセッション

## はじめに

### 最初の起動

Plethora を初めて起動すると、**ダッシュボード** (**今日**) が 7 つの主な学習目的地に沿って編成されていることが表示されます。

1. **今日** (「ダッシュボード」) - 毎日の学習概要、パーソナライズされたセッション ランチャー、アクティブなセッション ランナー、続きを読むカード
2. **ライブラリ** (「ドキュメント」) - ドキュメント、抜粋、オーディオブック、イメージ レジストリ、インポート
3. **学習** (「学習計画」) - 構造化された学習計画、ガイド付き読書セッション、言語学習
4. **復習** (「復習」) - 一定間隔で繰り返すフラッシュカード、読み上げキュー、およびスクロール モード
5. **Discover** (「RSS」) - スマート フィード、ポッドキャスト、ニュースレター、内蔵 Web ブラウザー
6. **知識** (「Knowledge Sphere」) - Knowledge Atlas、2D ネットワーク グラフ、ドキュメント Q&A、および NotebookLM
7. **洞察** (「学習洞察」) - 学習洞察、コンピテンシーの進捗状況、および分析

### 今日のワークスペースとパーソナライズされた学習セッション

**ダッシュボード**の上部で、**学習開始**のヒーローは、目標、期日のレビュー、または AI セットアップを必要とせずに、パーソナライズされたローカルでランク付けされたセッションを構築します。

- **集中プロファイル**: **バランス** (期日までのレビュー、目標、読書を組み合わせる)、**自由探索** (プレッシャーなく好奇心に従う)、**記憶保持** (一定の間隔で繰り返すカードを優先)、**試験準備** (締め切りと知識のギャップに焦点を当てる)、**詳細な学習** (より長く中断されない集中ブロック) から選択します。
- **時間の予算**: **セッションのカスタマイズ** から、「5 分」、「15 分」、「30 分」、「60 分」、「120 分」、または「無制限」を選択します (セッション中にランナー バーから予算を調整します)。
- **アクティブ セッション ランナー**: 開始すると、**アクティブ セッション** バーが現在のステップと進行状況を追跡します。
  - 主なアクション ボタン (**レビューの開始**、**読書を開く**、**学習計画を開く**、**ライブラリの参照**) をクリックして、そのアクティビティに直接ジャンプします (たとえば、アクティブなフラッシュカードのレビュー セッションを直接開きます)。
  - [**なぜこれが表示されるのですか?**] をクリックして、推奨の背後にある決定的なローカル ランキング要素を検査します。
  - **完了**、**スキップ**、**延期**を使用してステップを管理するか、**一時停止**、**終了**、**終了**を使用してセッションを制御します(一時停止したセッションは**前のセッションを続行**で再開できます)。
- **学習目標**: 軽量の**探索**目標(タイトルのみ)または**締切**目標(目標日、1日の分単位の予算、オプションの診断)を作成し、一時停止または再開し、準備ができたらいつでも**構造化された**学習計画に進化させます。

### 初期セットアップ

1. **テーマの選択** - [設定] → [外観] → [テーマ] に移動します。
   - 147 個の組み込みテーマが利用可能 (モダン 26 個、レガシー 121 個)
   - モダンな外観には「モダン ダーク」または「マテリアル ユー」をお試しください

2. **レビュー設定を構成する** - 設定 → 学習 → アルゴリズム
   - **アルゴリズム**: FSRS-7 (生産スケジューラ)
   - **希望の記憶力**: 90% (デフォルト) - どの程度記憶に留めたいかを目標とします。
   - **1 日あたりの学習**: 初心者に推奨される 20 ～ 50 項目

3. **カテゴリの設定** - [設定] → [カテゴリ]
   - さまざまな主題のカテゴリを作成します (例: 「プログラミング」、「科学」、「言語」)
   - カテゴリは学習教材の整理とフィルタリングに役立ちます

### 最初のドキュメント

最初のドキュメントをインポートしましょう。

1. サイドバーの **ドキュメント** をクリックします
2. [**インポート**] ボタン (右上) をクリックします。
3. インポート方法を選択します。
   - **ローカル ファイル**: PDF、EPUB、またはテキスト ファイルを選択します
   - **URL**: 任意の Web URL を貼り付けます
   - **Arxiv**: 研究論文 ID または URL を貼り付けます
4. 処理を待つ
   - 設定で自動分割が有効になっている場合、ドキュメントはインポート後に自動的に抽出に分割されます。

### インポート形式

|フォーマット |説明 |使用例 |
|----------|---------------|----------|
| **PDF** |ポータブルドキュメントフォーマット |研究論文、電子ブック、ドキュメント |
| **EPUB** |電子出版 |リフロー可能なテキストを含む書籍、記事 |

| **Arxiv** |学術論文 |研究文献 |

### ドキュメントのインポート

#### 方法 1: ローカル ファイル

1. [**ドキュメント**] → [**インポート**] をクリックします。
2. **ローカル ファイル** を選択します
3. ファイルに移動して選択します
4. Plethora は次のことを行います。
   - テキストコンテンツの抽出
   - 読書時間と単語数を計算します
   - メタデータ（タイトル、著者など）を抽出します。
   - 自動分割が有効になっている場合 ([設定] → [ドキュメント] → [インポート時に自動処理])、ドキュメントが自動的に抽出に分割されます。

#### 方法 2: URL インポート

1. 任意の Web URL をコピーします
2. [**ドキュメント**] → [**インポート**] → [**URL**] をクリックします。
3. URLを貼り付けます
4. [**インポート**] をクリックします。
5. Plethora がコンテンツを取得して処理します

**サポートされているサイト:**
- ニュース記事 (ほとんどの主要サイト)
- ブログ投稿
- ドキュメントページ
- ミディアム、サブスタックなど

#### 方法 3: Arxiv 論文

1. Arxiv の論文を見つけます (例: `https://arxiv.org/abs/2301.07041`)
2. URL または用紙 ID (`2301.07041`) をコピーします。
3. **ドキュメント** → **インポート** → **Arxiv** をクリックします
4. URLまたはIDを貼り付けます
5. 大量のダウンロード:
   - 完全なPDF
   - 要約
   - 著者
   - 発行日
   - 参考文献

#### 方法 4: JSON デッキのインポート

スケジュール データ (間隔、緩和係数、復習履歴) を含む JSON ファイルからフラッシュカード デッキをインポートします。

**ファイルピッカーを介したインポート:**

1. [**ドキュメント**] → [**インポート**] → [**JSON**] をクリックします。
2.「.json」デッキファイルを選択します
3. Plethora はデッキドキュメントを作成し、すべてのカードをインポートして、以下を保持します。
   - スケジュール設定 (間隔、緩和要因、期日)
   - レビュー履歴（繰り返し、失効、維持率）
   - カードの状態 (新規、審査中、または一時停止)

**ドラッグ アンド ドロップによるインポート:**

「.json」ファイルをアプリ ウィンドウに直接ドラッグします。ファイルが予想されるデッキ形式と一致する場合、自動的にインポートされます。

**JSON デッキ形式:**

ファイルは、質問テキストをカード データにマッピングするフラット オブジェクトである必要があります。

```json
{
  「細胞の動力源は何ですか?」: {
    "答え": "ミトコンドリア。",
    "件名": "生物学",
    "deck_name": "細胞生物学",
    「イーズファクター」: 2.6、
    「間隔日」: 7、
    「繰り返し」: 3、
    "due_at": "2026-04-20T12:00:00Z"
  }
}
「」

**注:**
- 各 `.json` ファイルは 1 つのデッキを作成します。デッキ名は「deck_name」フィールドから取得されます。
- インポートされたカードは、デフォルトで Plethora Classic アルゴリズムを使用します。インポート後にアルゴリズムを切り替えることができます。
- 同じファイルを 2 回ドロップしても重複は作成されません。既存のカードはスキップされます。
- `known_pile: true` とマークされたカードは保留状態としてインポートされます。

#### インジェスト エアロックとチャプター/H2 事前チャンク化

受信したブラウザ クリップまたは長いドキュメントを **要レビュー** にステージングする場合は、**エアロック トリアージ** をクリックして、アクティブ キューがいっぱいになる前に素材をルーティングします。
- **`[1]` アクティブコース高優先度 (`P10`)**: 緊急の学習のためにすぐにキューに入れられます。
- **`[2]` Evergreen 低優先度 (`P65`)**: 通常の増分摂取にスケジュールします。
- **`[3]` 参照専用ボールト (`P95`、アーカイブ済み)**: 期限内の SRS キューに入らずに、参照/検索用に保存します。
- **`[C]` 章ごとの事前チャンク / H2 見出し**: マークダウン (`## ` / `# `) または HTML (`<h2>` / `<h1>`) ドキュメントを、選択した層の優先順位を継承する順序付けされた子セクションに分割します。

**例:** 3 セクションのマークダウン記事 (`## コンセンサスの基本`、`## リーダー選挙`、`## ログ レプリケーション`) を **章ごとのプレチャンク/H2 見出し** を有効にしてインポートし、`1` を押すと、優先度 10 で 3 つのタイトル付きセクションが作成されます。

### ドキュメントビューア

インポートしたら、任意のドキュメントを開いてアクセスします。

**ビューアの機能:**
- **ページ ナビゲーション**: ページ/セクションをスクロールします。
- **ズーム**: テキストのサイズを調整します
- **全画面**: 気を散らすことなく読書が可能
- **検索**: ドキュメント内のテキストを検索します
- **目次**: セクションにジャンプします (可能な場合)

**注釈ツール:**
1. **テキストのハイライト**: テキストを選択 → ハイライトの色を選択
   - 黄色: 重要な概念
   - 緑: 例
   - 青: 定義
   - 赤: クリティカルポイント
   - 紫: 関連トピック

2. **抽出の作成**: テキストを選択 → 「抽出」ボタンをクリック
   - 抽出が「抽出」タブに表示されます
   - 後でフラッシュカードに変換できます

3. **メモを追加**: テキストを選択 → 「メモ」ボタンをクリックします
   - あなたの考え/メモを添付してください
   - メモは抜粋とともに表示されます

4. **ドッキングされた分割 Q&A / Cloze Creator (`Ctrl/Cmd + Shift + Q`)**:
   - 通路を塞ぐのではなく、Q&A または Cloze の作成を読者と並べて開きます。
   - **[選択範囲を質問に挿入]** または **[選択範囲を回答に挿入]** を使用して、強調表示されたテキストをアクティブなフィールドに直接取り込みます。

5. **優先継承チップと連鎖クローズ (`C`)**:
   - 選択バーには、ドキュメントの継承された優先度 (`P<N>`) が表示されます。 「Shift」を押したままチップ上でスクロール (「Shift+ホイール」) すると、優先度を ±5% 微調整します。
   - インライン抽出を作成した後、`ArrowUp` / `ArrowDown` は 4 秒間優先度を調整します。
   - **[C] Cloze** をクリックすると、リーダーを離れることなく 1 回のキーストロークでチェーンされた Cloze カードが生成されます。

6. **選択に固定されたソクラティック マージン (「Ctrl/Cmd + J」) およびグレースフル AI フォールバック**:
   - 文章をハイライト表示して `Ctrl/Cmd + J` を押す (または **⌘J Socratic** をクリックする) と、引用に固定されたインライン AI スレッドが開きます。
   - [**説明を抽出に変換**] または [**フラッシュカードに変換**] をクリックして、AI の説明をワンクリックで保存します。
   - ローカルまたはリモート LLM がオフラインまたはタイムアウトになった場合、**Graceful AI フォールバック**は見積もりとプロンプトを保存し、**手動抽出へのフォールバック** または **より小さいコンテキスト (50%) での再試行**を提供します。

7. **表、数学、コードのブレークアウト ビュー**:
   - 幅の広い `<table>`、`.katex-display` 方程式、または `<pre><code>` ブロック (Markdown、EPUB、または Extracts 内) にマウスを置くかフォーカスし、**Breakout View** をクリックして、独立した `0.5x–3.0x` パン アンド ズーム モーダルを開きます (`+`、`-`、`0` でリセット、`Esc` で閉じる)。

8. **地下鉄ミニマップ**:
   - [抽出] サイドバーの **地下鉄路線図** を切り替えて、ドキュメントのセクションを表示し、習得状態ごとに色分けされた抽出を表示します。

## 学習システム

### FSRS-7 について理解する

**FSRS-7** (Free Spaced Repetition Scheduler、バージョン 7) は、Plethora の実動フラッシュカード スケジューラです。以前の FSRS バージョンを **デュアル トレース** メモリ モデルで拡張します。

1. **デュアル トレース メモリ状態**: 各カードは 2 つの安定性トレースを追跡します。1 つは長期保持のための **遅いトレース** (`stability`) で、もう 1 つは短い水平リコール ダイナミクスのための **高速トレース** (`stability_fast`) です。 **検索可能性**は、単一の安定性値だけからではなく、両方のトレースの混合から計算されます。
2. **小数経過時間**: レビュー間の同日および半日の間隔は正確にモデル化されるため (丸一日に四捨五入されません)、短い間隔の後の間隔はより正確になります。
3. **34 パラメーター モデル**: FSRS-7 重みベクトルを使用します。十分なデータがある場合、パーソナル オプティマイザーはこれらをレビュー履歴に適合させることができます。
4. **4 つのボタンの評価**: 再度 / 難しい / 良い / 簡単 (評価 1 ～ 4) と各選択肢のプレビュー間隔。

**主要な指標:**
- **安定性** (遅いトレース): 長期記憶強度 (高い = より安定)
- **安定性 (高速)** (高速トレース): 低速トレースと組み合わせた短水平リコール ダイナミクス
- **難易度**: そのアイテムがあなたにとってどれくらい難しいか (1 ～ 10 段階)
- **検索可能性**: 二重トレース モデルから導出された現在の再現確率 (0 ～ 100%)

### SM-18 を理解する

**SM-18** は、ファミリーの前世代のスケジューラーです。これは SM-2 からの大幅な進化を表しており、メモリ安定性モデリングと間隔計算へのデータ駆動型アプローチが導入されています。

SM-18:

1. **指数関数的忘却のモデル**: 式 `R = 0.9^(t/S)` を使用して、検索可能性 (安定性 `S` を前提とした時間 `t` でアイテムを覚えている確率) を計算します。
2. **難易度を独立して追跡**: 各項目の難易度値 `D ∈ [0, 1]` を維持し、反復するたびに応答性が高まるトレーリング平均式を使用して更新します。
3. **3D SInc マトリックスを使用**: ビン化された難易度、安定性、および取得可能性によってインデックス付けされた 21×21×21 マトリックスから安定性増加係数を検索します。これが SM-18 のインテリジェンスの核心です。
4. **ラプスを適切に処理**: 失敗すると、安定性が 0.87 倍 (累積ラプスでさらに割られる) 減少し、繰り返しカウンタがリセットされますが、難易度の推定値は保持されます。
5. **安定性から間隔を計算**: 必要な保持目標から次のレビュー間隔を導出します: `interval = S × ln(1-FI) / ln(0.9)`

**主要な指標:**
- **安定性 (S)**: 記憶が減衰するまでの持続時間 (日数で測定)
- **難易度 (D)**: 0 (最も簡単) から 1 (最も難しい) までの値。各レビュー後にトレーリング平均ブレンディングによって更新されます。
- **検索可能性 (R)**: 現在の再現確率、「0.9^(経過/秒)」として計算されます。
- **SInc**: 9,261 エントリのマトリックスから調べた安定性向上係数 — レビューが成功するたびにどれだけ安定性が向上するか
- **失効**: 失敗の数。その後の失効で将来の安定性が損なわれます。

### SM-20 とアルゴリズム アリーナについて理解する

Plethora の **SM-20** オプションは **Algorithm Arena** です。これは、すべてのフラッシュカードで **5** の間隔をあけた繰り返しアルゴリズムを並列実行し、それらの予測を 1 つのスケジュールにブレンドする独立したアンサンブル実装です (純粋な単一カーネル SM-20 モードとは異なります)。 5 人の競合他社のデフォルトのブレンド ウェイトは次のとおりです。

|スロット |モデル |デフォルトの重み |どうやって学びますか？ |
|------|----------|---------------:|---------------|
| 1 | **SM-2** | 6% |修正済み |
| 2 | **SM-15** | 14% |継続的に、すべてのレビューで |
| 3 | **SM-19** | 45% |継続的に、すべてのレビューで |
| 4 | **SM-20** (35 パラメーターの「M4」忘却曲線カーネル) | 25% |オンデマンド、最適化ボタン経由 |
| 5 | **FSRS** | 10% |オンデマンド、最適化ボタン経由 |

**ブレンドの仕組み** 各モデルは個別にカードの安定性推定値を生成します。 Arena は加重平均を取得し、そこから次の間隔を導き出します。重みは固定されていません。**ユーザーに合わせて調整されます**。前回のレビューが少なくとも 1 日前であるカードをレビューするたびに、アリーナは実際に起こったこと (覚えているか忘れているか) に対して各モデルの「以前」の予測をスコアリングし、最もよく予測していたモデルに重みを微調整します。完全に排除されるモデルはないため、スロースターターは回復することができます。

**学習方法は 2 つあります:**

1. **すべてのレビューで自動的に** — SM-15 オプティマイザーと SM-19 マトリックスが即座に更新され、ブレンドの重みが変更されます。これは最初のレビューから始まります。 [設定] → [学習] で確認できます。**アリーナの重み** パネルには、各モデルの現在のパーセンテージが表示され、レビューのスコアが十分に得られると、**R メトリック** (ブレンドされた予測が SM-19 単独よりもどれだけ優れているか) が表示されます。
2. **オンデマンド、[最適化] をクリックすると** — 5 つの競合製品のうち 2 つ (SM-20 カーネルと FSRS) を個人のレビュー履歴に適合させることができます。これらの適合は、最小限のデータ (およそ数百日間隔のレビュー) と保留された検証チェックに基づいてゲートされます。適合は、適合が確認されていないレビューで出荷時のデフォルトを本当に上回る場合にのみ受け入れられます。それまでは、最適化ボタンで「レビュー履歴がまだ十分ではありません」と報告され、これら 2 つのモデルはデフォルトのパラメーターを使用し続けます。

**トレーニングが開始されていないと判断される理由。** 少なくとも **1 日**以上の間隔が空いたレビューのみがシグナルを伝達します。最初のレビューと同日の再レビューはアリーナに何も伝えないため (すべてのモデルはユーザーが覚えていると正しく予測します)、スコアの合計にはカウントされません。少数のカードしか持っていない場合は、それらのカードが日単位の間隔で表示され始めるまで、アリーナの重みはデフォルト近くに留まり、R メトリクスは非表示のままになることが予想されます。これは予期されたものであり、バグではありません。

**主要な指標:**
- **安定性 (S)**: メモリが持続する期間の各モデルの推定値 (日)。アリーナはこれらを融合させたものです。
- **難易度 (D)**: 各モデルのアイテム難易度の推定値。
- **アリーナ ウェイト**: モデルごとのライブ ブレンドのパーセンテージ。学習設定に表示されます。
- **R-Metric**: SM-19 単独と比較したブレンドの相対的な改善。レビューの減衰期間に基づいて計算されます。

**SM-20 (アルゴリズム アリーナ) と FSRS-7 の違い:**
- FSRS-7 は単一のプロダクション スケジューラであり、学習設定に表示される唯一のオプションです。
- SM-20 (アルゴリズム アリーナ) は、5 つのアルゴリズムを互いに戦わせ、独自のデータにブレンドを選択させる従来の実験的なアンサンブルです (一方、純粋な SM-20 モードは M4 カーネルのみを直接実行します)。研究のためにコードベースに残りますが、スケジューラ ピッカーからは隠されています。

#### SM-20 レビュー後の Memory Horizon の選択

**[設定] → [学習] → [アルゴリズム アリーナ] → [各評価後]** で、必要なスケジュールの詳細を選択します。

- **流れを維持する (推奨)** は、アリーナの加重ピックをすぐにコミットし、次のカードに移動します。これがデフォルトです。
- **アリーナの表示**は、対象となる評価の後に一時停止し、**メモリー ホライゾン**を開きます。5 つのモデルが次のレビューを配置する場所を表示している間、回答は表示されたままになります。

同じコンパクトな選択肢が 6 つの SM-20 評価コントロールの下に表示されるため、レビューを終了せずに次の評価で別のモードを使用できます。どちらのモードも、同じ 5 つのコレクション モデルを実行してトレーニングします。この設定は、最終的な間隔を選択するかどうかにのみ変更されます。決定ステップは通常の SM-20 フラッシュカードのレビューに限定されています。文書の読み取り、詰め込みモード、その他のアルゴリズム、および **Pure SM-20 モード** は、既存の直接スケジューリング フローを維持します。

- **アリーナピック**はデフォルトで選択されています。これは重み付けされた推奨事項であり、通常、アリーナに決定してもらいたい場合に最適な選択です。
- **SM-2、SM-15、SM-19、SM-20、および FSRS** を使用すると、このレビュー用に 1 つのモデルの正確な提案に意図的に従うことができます。 1 つを選択しても、そのモデルに特別な投票の重みが与えられるわけではありません。将来の重みは予測精度のみから学習し続けます。
- **カスタム** は、量と単位、または対数時間レンズ上の位置を受け入れます。表示された境界は無効なスケジュールから保護され、正確な期日は確認する前に更新されます。
- **この間隔の理由** により、提案、現在の重み、およびアリーナ範囲が拡張されます。この範囲は、5 つのモデルによって提案される最も古いものから最新のものまでの間隔であり、不確実性や信頼区間ではありません。

**[…のスケジュール]** を押すまで、何もコミットされません。プレビューが古くなったり、保存が失敗した場合でも、カードは成績と選択内容を保持したまま所定の位置に残るため、安全に再試行できます。 **評価に戻る** を選択すると、保留中の評定が破棄され、再度選択できるようになります。

Memory Horizon が開いている間のキーボード コントロール:

|キー |アクション |
|-----|----------|
| `←` / `→` |時系列で提案を検討する |
| `1`–`5` | SM-2、SM-15、SM-19、SM-20、または FSRS を選択します。
| `あ` |アリーナ選択を選択 |
| `M` |カスタム | を選択します。
| `Enter` または `Space` |表示されたスケジュールを確認する |
| `脱出` |評価に戻る |

ハンズフリーのオーディオ レビューでは、Plethora がアリーナの選択を自動的に確認するため、ビジュアル レビューで **アリーナの表示** が選択されている場合でも、再生を続行できます。自動コミットが失敗した場合でも、レビューは回復可能です。

### 文書読み取りスケジュール (増分読み取り)

FSRS-7 は **フラッシュカード** スケジューラーです。Q&A、クローゼ、および基本カードでトレーニングされ、目標は長期的な記憶です。 (SM-18 や SM-20 などの従来のスケジューラはコードベースに残りますが、UI には表示されません。) **ドキュメント** (Incremental Reading 経由で読む記事、論文、文章) は、**修正された FSRS-7** (*魅力的な* スケジューラ) によってスケジュールされます。これは、単一の事実の長期保存を最大限にするのではなく、コンテンツを定期的にローテーションし続けるという別の目標に合わせて調整されています。フラッシュカード スケジューラとは別の独自の FSRS インスタンスで実行されるため、[スケジュール] ビューでドキュメントに表示される **安定性**、**安定性 (高速)**、**難易度** の値は実際の FSRS-7 メモリ パラメーターです。

**スケジュール トラックは 1 つではなく 2 つです。** これが最大の混乱の原因です。

- **フラッシュカード** → FSRS-7 (学習設定のプロダクション スケジューラ) → FSRS オプティマイザーをトレーニングするレビュー履歴に書き込みます。
- **ドキュメント** → **修正された FSRS-7** (*エンゲージメント* スケジューラー。アプリ内のドキュメントを評価するあらゆる場所で使用されます。固定間隔の *増分* スケジューラーは API/MCP のフォールバックとしてのみ使用されます) → 個別に追跡され、**フラッシュカード スケジューラーにはまったくフィードされません。**

文書の評価には、フラッシュカードと同じ 4 つのボタン** (「再度」/「難しい」/「良い」/「簡単」) が使用されますが、評価はフラッシュカード アルゴリズムをトレーニングしない **別の** FSRS インスタンスに送られます。生成される間隔は、どのスケジューラが評価を処理するかによって異なります。

- **エンゲージメント FSRS-7 (アプリが使用するもの)。** キューまたはドキュメント ビューアからドキュメントを評価すると、Plethora は FSRS-7 を 0.9 の目標保持目標で実行し、目新しさ、多様性、偶然性に対して制限付きの *エンゲージメント * 乗数 (0.25 × ～ 2.0 ×) を適用します。間隔は FSRS によって計算されるため、**可変**です。間隔は、以下の固定値ではなく、カードと同様にドキュメントのデュアル トレースの安定性に応じて増加します。部分的にしか読んでいない長い形式のコンテンツの場合、期間を考慮した上限により、実際に文書をどの程度読んだかに基づいて、良好/簡単の間隔が 1 ～ 4 日に引き下げられます。
- **増分読み取りスケジューラ (フォールバック)。** プレーンな API/MCP 評価パスは、短い **固定** 間隔と 30 日のハード キャップを持つ別の非 FSRS スケジューラを使用します。

|評価 |増分 (フォールバック) 間隔 |フラッシュカードの間隔 (アルゴリズムによって異なります) |
|--------|------------------------------|------------------------------------------|
| **また** | ～4時間 |分 |
| **ハード** | ～1日 | 1 ～ 2 日 |
| **良い** | ～3日 |数日～数週間 |
| **簡単** | ～7日 |週 |

フォールバック スケジューラでは、連続する Good/Easy 評価には小さなボーナスが追加され、連続する Again/Hard 評価には小さなペナルティが追加され、間隔は約 **30 日**に制限されるため、素材はローテーションを維持します。 (キューからヒットした Engaging FSRS-7 パスには、30 日間の一律の上限はありません。唯一の上限は、上記の期間を考慮した上限です。)

**エンゲージメントは順序と間隔の両方に影響します。** エンゲージメント レイヤーは 2 つのことを行います。1 つは次に *どの* ドキュメントが登場するかを決定する (新規性の注入、多様性のバランス、セレンディピティ)、もう 1 つは FSRS-7 間隔を 0.25 × ～ 2.0 × の範囲内でスケーリングすることです。これは FSRS-7 計算の上に重ねられます。それはそれに代わるものではありません。

**実践的なポイント。** ドキュメント レビューは、**独自** FSRS-7 インスタンスを通じて実行され、個別に追跡されます。フラッシュカード FSRS オプティマイザーは**トレーニングされません**。フラッシュカード レビューからのみ学習します。パーソナライズされた FSRS 重み付けが必要な場合は、日単位の間隔でフラッシュカードを確認する必要があります。

### 評価システム

レビュー中に、思い出した内容に基づいて各項目を評価します。

|評価 |ラベル |説明 |一般的な間隔 |
|----------|------|---------------|----------|
| **1** |もう一度 |完全停電 | ～10分 |
| **2** |ハード |多大な労力をかけて思い出した | 1～2日 |
| **3** |良い |少し考えて思い出した | 5～7日 |
| **4** |簡単 |リコールは簡単でした | 10-14日 |

**プレビュー間隔:**
評価する前に、Plethora は 4 つの評価オプションすべてについて、各カードが次にいつ表示されるかを正確に表示します。スケジュールを最適化するためにこれを使用してください。

### カードの種類

#### 1. 基本的なフラッシュカード
シンプルな表裏カード

**表面:** フランスの首都はどこですか?
**戻る:** パリ

**以下に最適:** 事実、定義、語彙

#### 2. 削除を閉じる
穴埋め形式

**本文:** {{フランス}}の首都はパリです。

**次のように表示されます:** _____ の首都はパリです。

**最適な用途:** 状況に応じた学習、人間関係

#### 3. Q&A カード
質問と回答のペア

**Q:** TCP と UDP の違いを説明してください。
**A:** TCP は接続指向であり、配信が保証されています。 UDP はコネクションレスであり、保証はありません。

**こんな方に最適:** 概念、説明

#### 4. 画像のオクルージョン
画像の一部を非表示にする (図、チャート)

**用途:** 解剖学、地図、図表

**手動オーサリング:** ドキュメント内の画像にカーソルを置き、**画像オクルージョン カードの作成** をクリックしてオクルージョン エディターを開きます。画像上でドラッグして領域を描画し、領域内でドラッグして領域を移動したり、隅のハンドルを使用してサイズを変更したり、領域パネルでラベルを変更したり、領域を削除したりします (ボタンまたは Delete キー)。保存するリージョンが少なくとも 1 つ必要です。そうでない場合、保存は拒否されます。

**AI 提案は修正可能です:** AI がオクルージョン領域を提案すると、それらが事前に入力されたエディターが開きます。保存する前に領域を調整、追加、または削除します。モデルが使用できない領域を返した場合、それらは画像に固定され、手動で描画できるようにエディターが開きます。使用可能な領域がゼロのカードがサイレントに保存されることはありません。

## デッキマネージャー

**デッキ マネージャー** は、フラッシュカード デッキとそのカードを参照、検査、編集するための全画面ビューです。レビューのホームページの **デッキ マネージャー** ボタンから開きます。

### デッキの閲覧

- 左側のサイドバーには、すべてのデッキがカード数と今日期限インジケータとともにリストされます。
- デッキをクリックして展開します。一度に展開できるデッキは 1 つだけです。
- 各デッキのタグフィルターはデッキ名の下に小さな丸印として表示されます。

### カードリスト

デッキを展開すると、そのカードが仮想化されたスクロール可能なリストに表示されます。カードの各行には次の内容が表示されます。

- **状態バッジ** — 色分け: 青 (新規)、オレンジ (学習)、緑 (復習)、赤 (再学習)
- **質問のプレビュー** — 最大 80 文字
- **期限** — 相対ラベル (今日、明日、5 日、期限超過)
- **難易度** — 1 ～ 10 のミニ進行状況バー
- **間隔** — 現在のレビュー間隔（日）
- **レビュー数** — カードがレビューされた回数
- **リーチ インジケーター** — 5 回以上の失効があるカードの黄色の警告アイコン

### 並べ替えとフィルタリング

**カードを期限、状態、難易度、間隔、レビュー数、または経過時間で並べ替えます**。並べ替えボタンをもう一度クリックすると、昇順/降順が切り替わります。

**フィルター**:
- **状態** — 新規、学習、レビュー、再学習
- **期限ステータス** — 今日期限、期限超過、期限なし

上部の検索バーを使用して、質問テキストまたはタグ名で **検索** します。

### インラインカードエディタ

任意のカード行をクリックして、その下のインライン エディタを展開します。

- **質問**、**回答**、**タグ**を直接編集します。モーダルは必要ありません。
- **クローズ カード** には、削除範囲が強調表示されたクローズ テキストが表示されます。
- **複雑なカード タイプ** (複数選択、画像オクルージョン) では、[Studio で編集] リンクを含む読み取り専用のプレビューが表示されます。
- **一時停止/一時停止解除**をワンクリックで切り替えます。
- 変更は **オプティミスティック アップデート** で保存されます。UI は即座に更新され、保存が失敗した場合はロールバックされます。

### デッキ統計パネル

右側のサイドバーには、展開されたデッキの統計が表示されます。

- **今日期限** — 現在期限のカードの数
- **維持率** — 失効率に基づいて推定
- **平均的な難易度** — デッキ内のすべてのカードにわたる
- **リーチ数** — 5 回以上の失効があるカード (クリックしてリーチのみをフィルターします)
- **成熟度の内訳** — 新規/学習中/若手/成熟度カードの分布を示す積み上げバー
- **7 日間の予測** — 来週の予測期限数を示すスパークライン
- **FSRS メモリの健全性** — 色分けされた健全性インジケーターによる平均的な安定性と難易度

### 一括操作

チェックボックスを使用して複数のカードを選択し、一括操作ツールバーを使用します。

- **一時停止/一時停止解除** — 一時停止をバッチで切り替えます
- **削除** — 選択したカードを削除します (確認付き)
- **再タグ** — 選択したすべてのカードのタグを一度に追加または削除します

### 戦略を検討する

#### 毎日のレビュールーチン

1. **午前のセッション** (15 ～ 30 分)
   - 今夜締め切りのカードを確認する
   - より難しいアイテムに焦点を当てる

2. **イブニングセッション** (15-30分)
   - 日中に追加されたレビューカード
   - 読み取りから新しいカードを作成する

#### バックログの管理

期限切れのカードが多数ある場合 (100 枚以上):

1. **新しいカードに重点を置く**: レビューを 1 日あたり 20 ～ 30 件に制限する
2. **フィルターを使用**: カテゴリ別にレビューします (やりすぎないでください)
3. **学習セッション**: 週末の追いつきセッション
4. **維持率を調整**: 一時的に 85% に低下します (レビューが少なくなります)

#### 「また」カードの扱い

「再び」と評価されたカードはすぐに再表示されます (10 分)。戦略:

- **即時再学習**: 同じセッション内でカードを再確認します
- **別セッション**: 後日カードをもう一度確認します
- **問題について**: 再度多い場合は、カードの書き込みが不十分である可能性があります

## キュー管理

### キューを理解する

**キュー**には、レビューが予定されているすべてのアイテムが含まれており、次のように整理されています。

- **期限**: 期限が早いアイテムが最初に表示されます
- **優先度**: ユーザーが設定した優先度 (0-100)
- **カテゴリ**: 主題分野
- **カードの種類**: フラッシュカード、クローゼなど。

### キュービュー

#### 期限付きビュー
今日期限のアイテムと期限を過ぎたアイテムを期限順に並べて表示します

#### スケジュールされたビュー
今後のレビューを含む、スケジュールされたすべてのアイテムを表示します

#### 新しいビュー
新しく作成されたまだレビューされていないカードを表示します

#### 自動延期
学習設定で **セッション開始時の自動延期** を有効にして、Plethora が新しいアプリ セッションを開始するときに対象となる期限を過ぎたアイテムのスケジュールを変更します。これはセッションごとに 1 回実行され、次の 30 ローカル暦日にわたって項目を分散し、ブロックされない概要を表示します。レビュー履歴と記憶状態は保存されます。手動延期 すべては利用可能な状態のままです。

### キュー操作

**フィルタリング:**
- カテゴリ別 (例: 「プログラミングのみを表示」)
- カードの種類別 (例: 「Cloze カードのみを表示」)
- 優先度範囲別 (例: 「優先度 80+ を表示」)

**並べ替え:**
- 期日 (デフォルト)
- 優先順位
- 難易度
- ランダム（多様性のため）

**一括アクション:**
1. 複数の項目（チェックボックス）を選択します
2. アクションを選択します。
   - **カテゴリの変更**: 別のカテゴリに移動します
   - **優先度の設定**: 一括更新の優先度
   - **一時停止**: レビューを一時的に非表示にします
   - **削除**: 完全に削除します

### 抜粋を読む

キュー内の行を抽出すると、専用の **抽出リーダー** が開きます。ソース ドキュメントではなく、抽出自体のテキストが件名になります。リーダーからは次のことができます。

- 抽出の完全なコンテンツを読み取ります (保存されている場合はリッチ HTML、保存されていない場合はプレーン テキスト)
- **評価** (再度 / 難しい / 良い / 簡単) — キューは新しいスケジュールですぐに更新され、リロードは必要ありません
- **ソース ドキュメントを開く**。抽出の強調表示されたカードでドキュメント ビューアに戻ります。ソースドキュメントをロードできなくなった場合、ボタンは説明とともに無効になります。
- **ゴースト コンテキスト ピーク (`Alt` を押しながら)**: 抽出をレビューしているときに `Alt` を押したままにする (またはコンテキスト ピークの切り替えをクリックする) と、キューから離れることなく親ドキュメントの周囲の段落をプレビューできます。
- **アイテム終了優先順位バー**: 抽出の下部で、クイック優先順位アクション (「保持」、「延期」、「アーカイブ」) を使用して、完了したパッセージまたは価値の低いパッセージを破棄します。

### キューセッションモード、衛生およびモバイルエルゴノミクス

- **Zen vs. Architect 密度 (`Ctrl/Cmd + \`)**: **Zen** モード (スケジュール テレメトリが非表示でクリーンな読書/レビュー サーフェス) と **Architect** モード (完全な FSRS の安定性、難易度、インターバル テレメトリが表示) をグローバルに切り替えます。
- **統合セッション ヘッダーと出所ピル**: セッション ヘッダーから直接、**アダプティブ**と**厳密なマニュアル**の順序を切り替え、出所ピルをクリックしてアイテムのソース ドキュメントにジャンプします。
- **タイムボックス プレイリストと完了リング**: キュー スクロール ビューから制限されたセッション (**15 分**、**45 分**、または **10 分通勤**) を開始し、0 ～ 100% の完了リングで進行状況を追跡します。
- **コンポスト スイープのトリアージ**: キュー スクロール ビューでコンポスト スイープ モーダルを開き、`[J]`、`[K]`、`[L]`、および `[Backspace]` を使用して、古くなった延期されたアイテムを迅速にトリアージします。
- **インライン Leech リファクタリング ウィザード**: 「4+」の経過があるフラッシュカードには、**より単純なクローズへの分割**、**ローカル AI による書き換え**、または **読み取り抽出への降格** を提供するリファクタリング バナーが自動的に表示されます。
- **モバイル キュー 人間工学**: 電話機のレイアウトでは、**通勤オーディオ キュー** トグル、片手用**下部親指円弧** ドック (「再度」/「難しい」/「良い」/「簡単」および「優先度を上げる (-10)」/「延期 (+10)」) を使用し、**任意のプレビュー段落をダブルタップ**してデスクトップの受信トレイに直接キャプチャします。

### 優先システム

すべての文書、抽出、およびカードは、**単一のランク付けされたリスト** (1 つのキュー、すべての要素タイプが一緒) のどこかに配置されます。優先順位はその順位です。アイテムに優先順位を設定することは、アイテムにスコアを付けることではなく、*コレクション内のどこに属する*かを Plethora に伝えることです。

**優先順位は立場であり、ラベルではありません。**

これがプライオリティ キュー モデルであり、数値がそのように動作する理由です。アイテムを 70% に設定すると、コレクションの上位 70% のポイントに移動します。つまり、所有しているすべてのアイテムのおよそ 70% より上、上位 30% より下になります。他に番号が付け直されることはありません。アイテムは差し込むだけです。

任意の項目に優先度 0 ～ 100 を設定します。

- **90-100**: 他のほとんどすべてのものよりも優先して、最初に必要なものをいくつか挙げます。
- **70-80**: コレクションの上部
- **50-60**: パックの真ん中 (新しいマテリアルのデフォルト)
- **20-40**: 下部 — 最終的に読んでください
- **0-10**: キューの最後 - 参照、アーカイブ、いつか

**1 ～ 5 の重要度評価。** 一部のビューでは、アイテムの横にコンパクトな **1 ～ 5** 重要度評価も表示されます。この数値は、0 ～ 100% のスライダーを 5 つのバンドに分けたものです。**5 が最高** (81 ～ 100% の範囲)、1 が最低です。したがって、「優先度 5」を表示する 100% に設定されたドキュメントは、5 位ではなく、スケールの *トップ* を示しています。 1 ～ 5 の評価にはスライダー以外の情報は含まれません。スライダー自体 (およびライブ *Position X of N* の読み出し) が常に真実の情報源です。

**パーセンテージは自動的に変化しますが、それは正しいことです。**

パーセンテージは「コレクションの *現時点でのここまで*」を意味するため、周囲のコレクションが変化するにつれてパーセンテージも変化します。 500 件の新しい記事をインポートし、そのうちの半分を高く評価すると、手付かずの古いドキュメントの割合は先週よりも低くなります。これは、記事を降格したからではなく、より多くの資料がその上にあるためです。読む順番の中での実際の位置は、すでにそこにあったすべてのものと比べて変わりません。

ここでは固定の数字が静かに横たわっています。100 アイテムのコレクションに設定された「70」と 10,000 アイテムのコレクションに設定された「70」は、まったく異なる立場を説明しているにもかかわらず、同じことを意味すると主張します。パーセンテージは、現在のコレクションの真実を示します。

**N の X の位置**

任意のアイテムの優先順位ポップアップを開くと、スライダーの下にそのライブ ランクが表示されます。*位置 1* はコレクション内で最も重要な要素であり、*位置 N* は最も重要ではありません。大量のインポート後に再度開くと、位置が移動していることがわかります。この読み取り値は、開くたびに新たに検索されます。

**2 つのアイテムが同じ場所を共有することはありません。**

複数の項目を同じパーセンテージに設定しても、それらは 1 つの時点にスタックされません。各項目は最後の項目の直後に配置されるため、キューは厳密な順序のままになります。 200 個のドキュメントを 60% に一括設定すると、200 個のドキュメントが 60% 付近に順番に配置され、200 方向の結合が作成され、後でキューを任意に解除する必要がなくなります。

**優先スケジュール:**
優先度の高い項目は、混合レビューでより頻繁に表示されます。優先順位は *重要性 * を支配します。つまり、時間よりも資料が多いときに最初に取り掛かるものです。これは、*タイミング*、つまり特定のアイテムの次の期限を管理する FSRS スケジューリングとは別のものです。期限が大幅に過ぎている優先度の低いカードでも、昨日審査された優先度の高いカードよりも先に表示される可能性があります。

**抽出はドキュメントを継承します。** 新しい抽出はソース ドキュメントの優先順位で開始され、ドキュメントの優先順位を変更すると、抽出は古い値のままになります。抽出の優先順位を手動で設定すると、継承は停止され、独自の場所が維持されます。

### キューの順序付けと並べ替えの動作

キューがアイテムを順序付ける方法と位置が変化する理由を理解すると、研究フローを最適化するのに役立ちます。

1. **FSRS スケジューリングと動的優先度スコアリング**:
   - 各アイテムの位置は、選択したスマート キュー戦略またはアダプティブ ランキング プリセット (*保持期間の最大化*、*積極的なキャッチアップ*、*時間の最小化*、*探索*、*ディープ ワーク スプリント*、*疲れた/モバイル通勤*、*無慈悲なトリアージ*、または *バランスのとれたもの) と組み合わせた FSRS メモリ パラメーター (期限、間隔、安定性、安定性の高速性、取得可能性の低下) を使用して計算されます。発見*)。ドキュメントの場合、これらのパラメーターは、[ドキュメント読み取りスケジュール](#document-reading-schedule-incremental-reading) で説明されている *Engaging* FSRS-7 スケジューラーから取得されます。つまり、FSRS メモリ値はカードだけでなくドキュメントにも適用されます。唯一の違いは、ドキュメントの FSRS レビューが個別に追跡され、フラッシュカード スケジューラをトレーニングしないことです。詳細については、以下の [スマート キューとアダプティブ ランキング (DAQE)](#smart-queues--adaptive-ranking-daqe) を参照してください。
   - レビューを完了したり、項目を延期したり、メモをとったりすると、メモリ パラメータが更新され、項目はキューに戻るときに自然に再ランク付けされます。

2. **重み付けされた選択のランダム化**:
   - レビュー エンジンは、バックエンドからアイテムを取得するときに、微妙な重み付け減衰アルゴリズム (デフォルトでは「ランダム性 = 0.3」) を適用します。これにより、キューの疲労を避けるために若干の多様性を導入しながら、同様の優先順位を持つ項目が先頭近くに配置されます。

3. **状態の同期**:
   - キュー変更アクション (ドキュメントのアーカイブ、優先順位の一括編集、タグの変更など) を実行すると、キュー ビューに戻るときにバックグラウンドで更新がトリガーされ、リストがバックエンド データベースの状態に合わせて維持されます。
   - 受動的ビューの変更またはタブの切り替えは、予期しない再シャッフルを引き起こすことなく、安定したローカル順序を維持します。


### ニューラル レビュー (「ニューラルに進む」)

ニューラル レビューは、*Learn : Go ニューラル* コンセプトに触発されたオプションの探索モードです。優先キューを順番に処理するのではなく、単一の開始点 (現在読んでいる項目) から**アクティベーションを分散**し、それに関連するすべてのものを表面化することで、新しいレビュー シーケンスを構築します。これは、期限内にコレクションを進めるのではなく、コレクションを順番にたどっていきたいときに最適なモードです。

**使用方法** スクロール モードで読んでいるときに、上部バーの **Go neural** をクリックします。セッションは、現在のドキュメント、カード、または抽出にシードされた拡散アクティブ化キューに切り替わります。位置ピルが紫色に変わり、「ニューラル レビュー · N 残り」と表示されます。 [**終了**] をクリックすると、読書中の時点に正確に戻ります。ニューラル レビューによって優先キューやスケジュールが変更されることはありません。キューが少なくなると、完了したばかりの要素から自動的に補充されます。

**通常のスクロール モードと同様に、フラッシュカードと抽出を進めるには評価が必要**であるため、ニューラル セッションは引き続きスケジューリングに貢献します。書類は自由に進められます。

**何が「関連している」かを決定する方法** アクティベーションは、次の順序で 5 種類の接続を通じてシードから外側に広がります。

1. **コンセプト グループ (タグ)。** シードとタグを共有するアイテムは、コンセプト ピアとして扱われます。したがって、タグ付けは二重に役立ちます。検索用に項目をグループ化し、*さらに* ニューラル レビューを提供します。タグのないアイテムには概念のピアがありません。
2. **要素間参照。** 明示的な相互参照リンク (存在する場合)。
3. **子孫。** ナレッジ ツリー内のシードの子、つまりドキュメント内の抽出とカード、抽出内のカード。
4. **セマンティックな類似性** RAG のコレクションにインデックスを作成すると ([設定] → [埋め込みと RAG] → [インデックス コレクション])、ニューラル レビューによって、コンテンツがシードと埋め込みが類似しているドキュメントも表示されます。同様の文書がより早く出現します。インデックスを作成していない場合、このソースは単に沈黙したままになります。他の 4 つは引き続き機能します。
5. **親と兄弟。** シードの親 (抽出が存在するドキュメント) とその兄弟 (同じドキュメント内の他の抽出、同じ抽出内の他のカード、および近くのドキュメント)。

より近い接続 (直接の子、ほぼ同一のドキュメント、共有タグ) は、キューの早い段階で表面化します。最初の波で生成される項目が 20 未満の場合、キューがいっぱいになるか、それ以上到達できなくなるまで、アクティベーションは新しく到達した要素の隣接要素を介して外側に拡張されます。

**ヒント:**
- 一緒に探索したい項目にタグを付けます。このタグは、ニューラル レビューが続くコンセプト グループになります。
- コレクションにインデックスを付けて、セマンティックな発見を可能にします。これがなければ、ニューラル レビューはツリー構造とタグのみに依存します。
- ニューラル レビューは、通常のキューに関して読み取り専用です。ご自由にお使いください。優先順位や期日の変更については何もありません。


### スマート キューと適応型ランキング (DAQE)

Plethora のスマート キューは、**保存されたキュー** (スタディ セッションに *どの*アイテムが属するかをフィルターする) と **アダプティブ ランキング** (ダイナミック アダプティブ キュー エンジン、つまり **DAQE** を利用し、候補アイテムが表示される最適な *順序* を計算する) という 2 つの補完的なシステムを組み合わせています。

#### 保存されたキュー (フィルタリングとスコープ)

カテゴリ、要素タイプ、評価、または優先順位の範囲でコレクションをフィルターして、カスタムの焦点を当てたキューを作成します。

**キューの例:**
- 「今日のフォーカス」: メインカテゴリーのカードが期限付き
- 「クイックレビュー」: 簡単なカード、優先度 < 50
- 「Deep Dive」: 研究カテゴリーのハードカード
- 「試験準備」: 「生物学」カテゴリのすべてのカード

**保存されたキューの作成:**
1. **キュー** ビューで、ヘッダーの **保存されたキュー** ドロップダウン メニューをクリックします (または、ツールバーの **保存されたキュー** をクリックします)。
2. [**新しいキュー...**] をクリックします (または [**セッションのカスタマイズ**] をクリックして、[**新しいキューとして保存**] を選択します)。
3. 希望のフィルター (カテゴリ、タグ、項目タイプ、優先度のしきい値、セッション期間) を設定します。
4. 名前を入力してキューを保存します。

**保存されたキューの切り替えと管理:**
- キュー ヘッダーの **保存されたキュー** ドロップダウン セレクター、**保存されたキュー** ツールバー ボタン、またはコマンド パレット (`Ctrl/Cmd+K` → キューを検索) を使用して、保存されたキューを即座に切り替えます。
- ドロップダウンで [**キューの管理...**] をクリックして、キューの名前変更、キューの削除、またはデフォルトのキューの設定を行います。

---

**[設定] → [スマート キュー] → [キュー順序モード]** で [厳密な手動]** を選択し、保存された 0 ～ 100 の優先順位に従って対象商品を順序付けします。等しい優先度は、期限、次に項目タイプと ID によって順序付けされます。保存されたキュー フィルターと最適なセッション構成により、どの項目を表示できるかが引き続き制御されます。明示的な優先順位 0 が最低値です。自動リカバリが有効になっている場合、厳密な手動では、最大 50 個のアクティブなアイテムを未処理のままにし、容量を超えている場合でも 70 以上の優先順位を保護します。

#### アダプティブ ランキング (ダイナミック アダプティブ キュー エンジン)

フィルターが *メンバーシップ* (セッションに参加する内容) を決定するのに対し、アダプティブ ランキングは *順序* (今何を読むべきか) を決定します。

アダプティブ ランキングでは、期限切れステータスや静的な優先順位だけで項目をランク付けするのではなく、記憶の緊急性、現在の学習目標との整合性、認知エネルギーの適合性、トピックのインターリーブ、過去の読書の摩擦などを考慮して、候補項目をリアルタイムで評価します。

> [!重要]
> **適応ランキングは順序のみを管理し、スケジュールは管理しません。**
> ノブとプリセットは、FSRS の安定性、難易度、間隔、取得可能性、期限を変更することはありません。スケジューラーは、アイテムが「いつ」返されるかを決定します。アダプティブ ランキングは、現在の座席で *どの期限アイテムが最初に表示されるかを決定するだけです。

##### 5 タームの複合スコア計算式

キューを再ソートするたびに、DAQE は候補アイテムごとに決定論的な複合スコア $S(i)$ を計算します。

$$S(i) = w_{\text{srs}} \cdot R_{\text{srs}}(i) + w_{\text{goal}} \cdot M_{\text{関連性}}(i) + w_{\text{fit}} \cdot M_{\text{energy\_fit}}(i, K_{\text{energy}}) - w_{\text{interleave}} \cdot P_{\text{インターリーブ}}(i, H_{\text{最近}}) - w_{\text{friction}} \cdot P_{\text{friction}}(i)$$

すべての項は、重みが適用される前に単位区間 $[0, 1]$ に正規化され、単一の要因が暗黙的に支配するのを防ぎます。

1. **メモリ緊急度 ($R_{\text{srs}}$)** は $0.8T + 0.2P$ です。ここで、$T$ は時間的緊急度、$P$ は適応優先度信号です。デスクトップ DAQE は、利用可能な場合はライブラリ内にあるアイテムの優先順位を使用し、保存されたスライダーまたは従来の評価にフォールバックできます。厳密なマニュアルでは、保存された 0 ～ 100 の値が表示に使用されます。
   - **輪読** (文書と抜粋) では期限を使用します。新しいアイテムは中立的な緊急度で開始されます。将来のアイテムには時間的な緊急性はありません。
   - **Recall** (フラッシュカード) では、スケジューラの推定取得可能性も考慮されます。期限切れのカードの場合、一時的な緊急性は、リコールのリスクと期限切れの準備の高い方を採用します。
   - 期限を過ぎた準備は、日数が経過するにつれて順調に増加します。 14 日は曲線の時定数です。 14日目にはカットオフはありません。
2. **目標の関連性 ($M_{\text{関連性}}$)**:
   アクティブな **セッション目標** とのトピックの一致を測定します (例: *「量子コンピューティングの基礎ともつれの証明」*)。 3 段階で評価されます。
   - *Tier 1 (測定)*: 接続された AI 意思決定モデルからの連続 0 ～ 1 スコア (「evaluateScore」)。
   - *Tier 2 (推定/デフォルト)*: 意思決定モデルがアクティブでない場合の、目標と項目テキスト間のローカル語彙キーワードの一致。
   - *Tier 3 (タグ アフィニティ)*: 目標が指定されていない場合のタグベースの関連性ブレンド。
   - 同じナレッジ クラスター内の関連マテリアルに積極的に取り組むときに獲得できる *クラスター プロモーション ブースト* も吸収します。目標またはシグナルが存在しない場合、この用語は *未測定* (0.0) を明確に報告します。
3. **エネルギー フィット ($M_{\text{energy\_fit}}$)**:
   アイテムの認知的複雑さと目標エネルギー レベルの近さを測定します $K_{\text{energy}}$ ($1\text{--}5$):
   $$M_{\text{energy\_fit}} = 1 - \frac{|\text{ItemComplexity}(i) - K_{\text{energy}}|}{4}$$
   アイテムの複雑さは、意思決定モデル (*表面スキム* = 1、*中程度の分析* = 3、*ディープ基礎* = 5) によって分類されるか、要素タイプによって決定論的にデフォルト設定されます (ドキュメント = 4、抽出 = 3、フラッシュカード = 2)。
   *疲労ダウンシフト*: 過去 30 日間の読書速度がベースラインの 40% を下回った場合 ($\ge 5$ セッション以上)、DAQE は認知的燃え尽き症候群を防ぐために、有効エネルギー目標を自動的に軽い素材に下方シフトします。
4. **トピック バラエティ ペナルティ ($P_{\text{interleave}}$)**:
   最近のレビュー履歴ウィンドウ ($H_{\text{recent}}$) に対してトピックと意味の類似性を計算します。 「interleavingDiversity」を高くすると、レビューしたばかりのアイテムとタグや概念を共有するアイテムにペナルティが課され、インターリーブの実践が奨励されます。トピックが重複していない項目にはペナルティはかかりません。
5. **抵抗ペナルティ ($P_{\text{friction}}$)**:
   記録されたインタラクションから抵抗ポイントを獲得します。
   - 繰り返される延期 (それぞれ +0.10、上限は 4)
   - 急速スキップ (それぞれ +0.10、上限は 4)
   - 放棄されたレビュー (それぞれ +0.15、上限は 3)
   - アイドル支配 (インタラクションなしのアイドル滞留時間が合計時間の 50% を超え、最大 +0.35 に寄与)
   あなたが繰り返し避けたアイテムは緩やかに降格され、維持または分割の機会が表面化します。測定されていない項目にはペナルティはありません。

##### 6 つのランキングノブ

**[設定] → [スマート キュー]** または **セッションのカスタマイズ** モーダルを使用して、ランキング式のすべての要素を微調整できます。

|ノブ |範囲 |デフォルト |目的 |
|---|---|---|---|
| **メモリ緊急度** (`srsDecayWeight`) | `0.00`–`1.00` | `0.40` |期限を超過しているアイテムやリスクのあるアイテムがどれだけ上位に引っ張られるか。 |
| **目標の関連性** (`goalRelevance`) | `0.00`–`1.00` | `0.30` |アクティブなセッションの目標に一致するアイテムがどれだけ強く前方に引っ張られるか。 |
| **エネルギー目標** (`energyTarget`) | `1`–`5` (整数) | `3` |目標とする認知深度 (1 = 軽いスキム、5 = 濃い一次ソース)。 |
| **トピックの多様性** (`interleavingDiversity`) | `0.00`–`1.00` | `0.20` |多様性を促進するために、繰り返されるトピックをどの程度強く抑制するか。 |
| **剪定** (`剪定攻撃性`) | `0.00`–`1.00` | `0.10` |スキップおよび延期された項目がどの程度積極的にペナルティを受けるか。 |
| **アウェイ タイムアウト** (`afkIdleTimeoutMs`) | `15`–`120`s | `45`s |滞留追跡が一時停止し、時間をアイドルとしてマークする前の非アクティブしきい値。 |

すべてのスライダー調整は、「適用」ボタンを必要とせずにすぐに有効になります。

##### 厳選されたプリセット

プリセットは、6 つのノブの事前設定されたベクトルです。プリセットは、[キュー] ツールバーのドロップダウンまたは [設定] から切り替えることができます。

- **ディープ ワーク スプリント**: エネルギー目標「4」、目標関連性「0.50」、トピックの多様性「0.10」。トピックの切り替えを最小限に抑え、密度の高い一次情報源を集中的に研究するために調整されています。
- **疲れている/モバイル通勤**: エネルギー目標 `2`、記憶緊急度 `0.20`、トピックの多様性 `0.40`。通勤時の読書やエネルギーを抑えたセッション向けに、短くて摩擦の少ないアイテムやさまざまなトピックを取り上げます。
- **冷酷なトリアージ**: 枝刈り `0.60`、メモリ緊急度 `0.40`。避けたり延期した項目を前面に押し出し、保持するか、より小さな抽出に分割するか、削除するかという明確な決定を強制します。
- **バランスの取れた発見**: 記憶の緊急性 `0.35`、目標の関連性 `0.25`、トピックの多様性 `0.25`、剪定 `0.15`、エネルギー目標 `3`。リテンション、目標、多様性のバランスが均等なデフォルト。

*属性の誠実さ*: ノブがその定義と正確に一致する場合にのみ、UI にプリセット名が表示されます。スライダーを微調整すると、バッジがスムーズに移行してカスタム設定を示します。

##### 意思決定モデルとローカルファーストのプライバシー

アダプティブ ランキングは、オプションで、軽量 **System One** 評価プロトコル (`evaluateScore`、`evaluateChoice`、`evaluateNoul`) を実装する AI 意思決定モデルに接続できます。

- **なし (決定的ローカル フォールバック)**: デフォルト。ネットワーク リクエストなし、トークン コストなし、100% オフライン。目標と項目タイプの複雑さのヒューリスティックにローカル キーワード マッチングを使用します。
- **Spine**: [設定] → [AI] で設定されたプライマリ AI プロバイダーを通じて評価をルーティングします。
- **Laya (ローカル/オンデバイス)**: Apache 2.0 オープンウェイト小規模モデル (Convai による ~0.4B パラメータ)。ダウンロードした重み​​またはローカル サーバー (`http://127.0.0.1:8000`) を介してマシン上で完全に実行されます。データがデバイスの外に出ることはありません。
- **Jev (ホスト型)**: TypeSafe AI による特殊な意思決定モデル ($0.042/M の入力トークン、無料の出力トークン。API キーが必要)。
- **Clef (Cloudflare Workers AI)**: Workers AI でホストされる Apache 2.0 オープン モデル (`clef-flash` 9B、`clef` 27B; Cloudflare API トークンとアカウント ID が必要)。
- **OpenRouter Decisions**: `inception/mercury-decide:free` (無料で使用)、`liquid/d1`、および `upstage/solar-decide` などの意思決定モデルにアクセスします。
- **OpenAI Decisions**: Decisions API を介した OpenAI リアルタイム意思決定モデル。

> [!ヒント]
> **プライバシー ゲート**: 明示的なオプトインがなければ、アイテムのコンテンツがデバイスから流出することはありません。リモート モデルが有効になっている場合でも、Plethora は識別できない構造アウトライン (見出しのスケルトン、項目の種類、文字の長さ) のみを送信し、本文テキスト、ハイライト、ユーザー メモは送信しません。すべてのモデルの判定は、コンテンツ ハッシュによって SQLite にローカルにキャッシュされます。

---

##### 滞留テレメトリと適応学習ループ

Plethora は、パッシブなスクリーンタイムではなく **アクティブな滞在時間**を追跡します。
- 設定されたタイムアウト (例: 45 秒) を超えて非アクティブになると、トラッキングが「アイドル」に移行し、アイドル ブロックが遡ってクランプアウトされ、偶発的なウィンドウ リーフによって読み取りメトリクスが増大するのを防ぎます。
- 作成された抽出、スクロールのトラバーサルの深さ、終了アクション (*抽出作成*、*次項目*、*延期*、*却下*、*再優先*) などの対話の証拠を収集します。

バックグラウンド学習ループは、このテレメトリを使用して、モデルの微調整を行わずに適応します。
- **クラスター プロモーション**: 抽出やハイライトの作成に継続的なアクティブ時間 ($\ge 1$ min) を費やすと、アイテムのコレクションとセマンティック トピック クラスターが促進され、関連する知識がより早く表面化します。
- **耐性の推奨事項**: $\ge 3$ 回スキップされた項目は、**分割候補**の提案を受け取ります (内容を細分化するように求められます)。 $>50\%$ のアイドル時間があり、インタラクションがないアイテムは、**自動降格** の推奨事項を受け取ります。どちらもユーザー向けの提案です。どちらもアイテムを自動的に変更しません。

##### 説明可能なスコアの内訳

Plethora にスコアがないのはブラックボックスです。キュー リストまたはリーダーで:
- 任意の項目のランクの詳細またはポジション バッジをクリックして (またはモバイルでは行メニューをタップして)、**この順位の理由**を表示します。
- 複合スコア $S(i)$ を 5 つの項のそれぞれとその符号付き重みとともに表示します。
- 各用語には正直なステータス バッジが表示されます。
  - **測定**: ライブ テレメトリまたは意思決定モデルの評価から直接計算されます。
  - **推定**: 決定論的なヒューリスティック (要素タイプの複雑さなど) から導出されます。
  - **未測定**: 入力信号が利用できません。キューを歪めることなく、きれいに 0 を提供しました。
- 疲労ダウンシフトが発生した場合、最初に設定した目標と並んで有効エネルギー目標が表示されます。

##### セッション目標の管理

学習ブロックの一時的な学習目標を設定するには:
1. **キュー**を開き、**セッションのカスタマイズ** (またはスライダー アイコン) をクリックします。
2. **セッションの目標** 入力に目的を入力します (最大 200 文字、例: *「心臓血管生理学と血行動態」*)。
3. または、[**最近の目標**] チップの 1 つをクリックして、以前の目標を再適用します。
4. キューは即座に順序を変更して、トピックに関連する文書、抜粋、フラッシュカードを前方に引き出します。

### タグ対応スケジューリング (TAS)

Tag-Aware Scheduling は、レビュー キューにセマンティック インテリジェンスを追加します。
設定で有効にすると、TAS は 2 つの後処理パスを適用します
基礎となる SM-20/FSRS 間隔を変更せずに、期日が到来するアイテム:

- **前提条件ゲート**: タグの前提条件が満たされていない項目をブロックします。
  設定された成熟度のしきい値に達しました。  基礎となる材料は、
  高度なトピックが表示される前に安定化されます。
- **干渉ジッター**: 高コヒーレンスタグを共有するアイテムを分離します。
  最小限の時間枠で実行され、レビュー中のセマンティックな干渉が軽減されます。

TAS は **オプトイン** で **非破壊的** です。いつでもオフに切り替えることができます
デフォルトのキュー順序に戻ります。  ブロックまたは遅延されたアイテムは保持されます
元の期日と間隔。

#### TAS を有効にする

1. **[設定] → [タグ対応スケジュール]** を開きます。
2. **TAS を有効にする** をオンに切り替えます。
3. 必要に応じて、**干渉**と**前提条件**を有効/無効にします。
   サブシステムは独立しています。
4. 各スライダーを好みに合わせて調整します。

|設定 |範囲 |デフォルト |説明 |
|---|---|---|---|
|最小間隔 | 0 ～ 24 時間 | 4時間 |高一貫性タグを共有するアイテム間の時間 |
|コヒーレンスのしきい値 | 0.50～1.00 | 0.75 |これ以上の一貫性を持つタグのみが分離されます。
|成熟度比率 | 0.50～1.00 | 0.70 |成熟している必要がある前提条件タグ内の項目の割合 |

#### 前提条件のセットアップ

タグの前提条件を使用すると、トピックが表示される順序を制御できます。

1. (メディア パネルまたはライブラリ ツールバーから) **タグ管理** を開きます。
2. 上部にある [**前提条件**] ボタンをクリックします。
3. タグ名をクリックして編集用に選択します。
4. エディタパネルで、**前**に学習する必要があるタグをチェックします。
   このタグのアイテムはキューに表示される可能性があります。
5. [**前提条件の保存**] をクリックします。

右側の **依存関係グラフ** は関係を視覚化します (矢印)
前提条件タグから依存タグまでを指します。  循環依存関係は、
保存時に検出され拒否されました。

> **注意**: タグは既存のアイテムから自動的に同期されます。
> タグが表示されない場合は、最初にいくつかのアイテムにタグを付けてから、再度タグを開きます
> 管理 — TAS がそれらを検出して登録します。

#### キューの読み取り

TAS がアクティブな場合、キュー ヘッダーには **TAS アクティブ** バッジが表示されます
準備完了アイテムとブロックされているアイテムの数を表示します。

|バッジ |手段 |
|---|---|
| 🟡 "「タグ」の成熟を待っています (45%)" |ブロック済み — 前提条件タグは 45% しか完成していません |
| 🔵 "「タグ」との干渉を避けるために遅延しました" |遅延 - 高一貫性タグを共有するアイテムが最近スケジュールされました |

#### アイテムの強制

個々の項目の TAS をオーバーライドできます。

- ブロックされたアイテムまたは遅延したアイテムの横にある [**強制表示**] リンクをクリックします。
  現在のレビュー セッションにすぐに追加します。
- オーバーライドはセッションのみです - 項目は TAS に対して再評価されます
  ルールは次のセッションで。

#### コヒーレンスの計算方法

コヒーレンスは、タグの項目がどの程度意味的に厳密であるかを測定します。

1. キュー ビューから **セマンティック グラフの計算** を使用します。  これには必要です
   構成された埋め込みプロバイダー (OpenAI、Ollama、Cohere、OpenRouter)。
2. 各アイテムのタイトル、コンテンツ、タグが選択した LLM に送信されます。
   プロバイダーと埋め込みベクトルが保存されます。
3. 埋め込み後、TAS は各タグの **重心** を自動的に計算します。
   (そのタグを持つすべてのアイテムの平均ベクトル) および **一貫性** (平均
   これらの項目のペアごとのコサイン類似度)。
4. コヒーレンス値は、タグ管理の各タグの横に表示されます。

まだ埋め込みのないタグは coherence = 0 — no として扱われます。
これらのタグには干渉ジッターが適用されます。

#### タグの成熟度

アイテムの SM-20/FSRS が安定している場合、そのアイテムのタグは**成熟**しています。
タグの「maturityThreshold」（デフォルトは 0.8）以上です。  の
全体的な成熟度比率は「matureCount / itemCount」です。

- 前提条件エディターの進行状況バーには、各タグの現在の状態が表示されます。
  成熟度比率。
- 前提条件ゲーティングは、設定された `maturityRatio` を使用して決定します
  依存関係をロック解除するのに十分な前提条件タグが「満たされている」かどうか
  レビュー用のタグです。

#### ヒント

- **前提条件のみから始めてください**。まで干渉ジッターをオフにしておきます。
  埋め込みパイプラインを実行し、コヒーレンス値を取得しました。
- **詳細なタグを使用します**。 `calculus.limits` → `calculus.derivatives` は
  1 つの広範な「calculus」タグよりも効果的です。
- **ブロック率に注意してください**。多くのアイテムがブロックされたままになっている場合は、成熟度を下げます
  比率を調整するか、前提条件のグラフを簡略化します。
- **Force-show はあなたの安全弁です**。 TAS が攻撃的すぎる場合は、
  特定のアイテムを強制的に表示します。基礎となるスケジュール データは損なわれません。

## 言語学習

Plethora を使用すると、読んだり、見たり、復習したりしながら言語を学習できます。この言語機能は、ドキュメント、ビデオ、キュー、学習計画にまたがって機能します。**言語プロファイル**を構築し、単語に出会ったらその単語を確認し、**AI 講師**に助けを求め、**シャドーイング、ディクテーション、発音、ライティング**で練習し、**学習者の証拠**に次に取り組むべき内容を提案させます。

### 言語学習を始める

1. **[設定] → [言語学習]** を開き、**言語学習**を有効にします。
2. [**言語学習**] タブを開き、**言語プロファイル**を作成します。ターゲット言語、基本言語、推定熟練度を選択します。
3. [設定] (クラウドまたはローカル) で AI プロバイダーを構成します。講師、翻訳、執筆モードには AI プロバイダーが必要です。音声モード (シャドウイング、ディクテーション、発音) には、さらに音声認識プロバイダー (Groq など) とマイクの許可が必要です。

プロファイルは以下のすべてを推進します。AI 講師があなたの語彙に適応し、辞書のピークが単語ごとの知識状態を追跡します。

### 辞書のピーク

文書、トランスクリプト、またはビデオ内の単語またはフレーズを選択します。

- **言語ピーク** ポップオーバーには、定義、翻訳、発音、および (利用可能な場合) 文例が表示されます。
- **Memorize** は、単語を言語の下書きとして **Flashcard Studio** に送信します。
- **抽出** は、学習用抽出として保存します。 **再生** は、調整された録音が存在する場合に、元のオーディオを再生します。

### AI家庭教師

チューターは、あなたのレベルと勉強しているテキストを理解する会話アシスタントです。

**家庭教師セッションの開始:**
- 文書内: 文を選択し、選択メニューから **講師** (または **説明**) を選択します。
- 辞書のピークから: 単語の [**説明**] をタップします。
- ビデオの場合: 現在の文で [**講師**] ボタンを使用します。
- キュー内: ビデオ抽出クリップには **Ask tutor** チップが表示されます。

**モード:** 説明、ロールプレイ、書き直し、文法、発音、コロケーション、翻訳、最小ペア、会話、添削、練習。すべての返信には、その生成方法 (**根拠** (ソース資料から)、**生成**、または **一般**)、およびどのプライバシー パス (ローカルまたはクラウド。クラウド分析にはユーザーの同意が必要です) が使用されたかが記載されています。

**セッション履歴:** 完了した講師の回答は、ローカルの **講師履歴** パネル (最新 50 件) に保存されます。そこから、個々のセッションを**削除**、**すべてクリア**、または履歴を JSON ファイルとして**エクスポート**することができます。削除またはエクスポートはローカル履歴にのみ影響します。プロバイダー データは変更されません。

**キャンセルと再試行:** **キャンセル**で実行中の応答を停止します。 **再試行**を使用して同じリクエストを再実行します。

### 練習モード

**練習** エリア ([言語学習] タブ) では、次のことが提供されます。

- **シャドーイング** — ネイティブ音声の後に繰り返します。セッションでは、学習していたテキストまたはビデオの元のオーディオ クリップが利用可能な場合はそれを使用し、利用できない場合はテキスト読み上げに戻ります。
- **ディクテーション** — 同じオリジナルの音声範囲を使用して、聞いた内容を聞き、入力します。
- **発音** — 録音したものをターゲットの発音と比較します。
- **書き込み** — 回答を書いて修正を受けます。
- **音声会話** — 講師と大声でチャットします。

試行は、練習ハブの [**最近の試行**] に表示されます。

### ビデオとメディアの調整

ビデオでは、各文に独自の制御行（**再生**、**ループ**、**自動一時停止**、**翻訳**、**私の**、**講師**、**練習**）が与えられます。再生では、文の正確な位置で **元の音声**が優先されます。録音が欠落している、古い、曖昧である、または信頼性が低い場合は、テキスト読み上げに戻ります。 **私の**は、クリップの**メディア範囲**を維持するフラッシュカードの下書きを作成します。これにより、カードはビデオのどこから来たのかを正確に記憶します。練習開始では同じ範囲が再利用されるため、シャドウイングとディクテーションでは適切なクリップが再生されます。

### フラッシュカード スタジオ

言語の下書きは、**Memorize** (辞書の閲覧)、**Mine** (ビデオ)、および言語の練習から Flashcard Studio に届きます。ドラフトには、**出所** (ソースの文書またはビデオ、正確なメディア範囲、および言語プロファイル) が保持されているため、いつでもカードをどこで出会ったかまで遡ることができます。

### 学習計画

学習計画は言語学習と連携して機能します。

1. プランを作成または編集するときに、**言語プロファイル**をリンクします (また、必要に応じて、目標の熟練度と言語の焦点を設定します)。
2. プランを開いて、**学習者の証拠** パネルを探します。計画の目標と実際の学習データを比較し、次のステップを推奨します。
   - **語彙範囲** — 目標の用語が既知の語彙とほとんど重複しない場合。
   - **練習のリフレッシュ** — 過去 2 週間で受け入れられた練習の試行がほとんどなかった場合。
   - **フラッシュカード マイニング** — 言語に関連付けられたフラッシュカード コレクションがまだ少ない場合。
3. 各推奨事項には、[言語学習を開く]** ボタンがあり、[言語学習] タブに直接ジャンプします。

## 学習計画とガイド付き読書コース

**学習計画**と**ガイド付き読書トレイル**を使用して、書籍、記事、成績証明書を、構造化された目的に基づいたカリキュラムに変えます。

### スタディキュー、リストおよびグラフビュー

学習計画の **カリキュラム アウトライン** タブ内で、3 つの補完的なビューを切り替えます。

- **キュー**: 段階的な**学習キュー**。次に推奨される読書課題 (「学習の継続」)、推定読書時間、今後の課題、ブロックされている前提条件、および完了した項目を強調表示します。
- **リスト**: カリキュラム ノード、学習目標、リンクされた読書箇所を参照および編集します。
- **グラフ**: インタラクティブなカリキュラム グラフでトピック間の前提条件の依存関係を視覚化します。

### スタディトレイルの生成とカスタマイズ

1. 学習計画を開き、**カリキュラム アウトライン**の下の**キュー** ビューを選択します。
2. **[スタディ トレイルの生成]** (または、ソースまたは目的の編集後に **スタディ トレイルを再構築**) をクリックします。
3. Plethora は、選択したソース文書の構造を分析し、目次、参考文献、付随的な言及を自動的に除外し、各学習目標を一貫した前提条件順に並べた読書セグメントと組み合わせます。
4. [**プレビューとトレイルの編集**] をクリックして、セグメントの来歴を検査したり、代替パッセージと交換したり、手動順序を調整したり、項目を延期したり、無関係な一致を報告したりします。

### ガイド付き読書モード

**ガイド付き読書の開始** をクリックすると、割り当てられた文章がドキュメント ビューアで直接開き、専用の **ガイド付き読書モード** サイドバーが表示されます。

- **割り当てられた境界とコンテキスト**: 開始/終了セクションのマーカー、推定継続時間、およびこのセグメントが学習目標に選択された理由が表示されます。
- **進捗状況の追跡**: 割り当てられた範囲内での読書の進捗状況を追跡します (いつでも境界を超えて読書を続けることができます)。
- **キュー ナビゲーション (「前へ」 / 「次へ」)**: [学習計画] タブに戻ることなく、**前** / **次** コントロール (または **次: \<トピック\>**) を使用して、学習計画内の読書課題間を直接移動できます。
- **メモ、抜粋、およびソクラテス チューター**: 読書中にメモ/抜粋をキャプチャするか、永続的な **アシスタント** パネル (会話はドキュメントおよびビデオごとに保存されます) を開きます。

### 多肢選択式理解度チェック

読書課題を終えたら、**読書を終了 → 理解度チェック** をクリックして、低額の **理解度チェック (形成的)** を開きます。

- **デフォルトの多肢選択**: 読んだばかりの文章に基づいた 4 つの選択肢 (「A」–「D」) の多肢選択の質問が表示されます (プロバイダーの構成時に AI が生成され、確定的なオフライン/プライバシー保護のフォールバックが使用されます)。
- **柔軟な質問の角度**: *自分の言葉で説明*、*新しい例に適用*、*関連するアイデアを区別*、*議論をたどる*、*誤解を見つける*、*ソースに基づいた統合*を切り替えるか、**新しい質問**をクリックします。
- **オプションの書き込みモード**: 自由形式の説明を入力したい場合は、いつでも「**自分の答えを書く**」をクリックしてください。
- **即時フィードバックと次の課題**: 答えをチェックすると、正しい選択肢が強調表示され、その理由が説明され、次の読書課題に直接進むための **次へ: \<トピック\>** ボタンが表示されます。形成的チェックによって、正式な試験の成績や FSRS フラッシュカードの間隔が変更されることはありません。

### 対象を絞った修復と評価の資格

- **対象を絞った修正**: 満たされていない学習ギャップが学習キュー内の修正項目として自動的に表示され、前提条件の概念または関連する文章にリンクされます。
- **評価資格**: **ガイド**、**オープン**、または**テストアウト**ポリシーに基づいて、正式な学習計画評価の準備状況を追跡します。

## 睡眠の追跡と学習に関する洞察

[**学習インサイト**] タブ (デスクトップ ツールバーまたはモバイル ナビゲーションの HeartPulse アイコンからアクセス可能) で、睡眠履歴、概日リズム、生理学的テレメトリを学習成績と直接結び付けます。

SuperMemo の Piotr Woźniak 博士の古典的な SleepChart に触発された Plethora は、客観的な睡眠観察と間隔反復記憶保持 (FSRS-7)、読書セッション、および学習計画の習得を組み合わせることで、睡眠と概日追跡を最新化します。

### ダッシュボードとインタラクティブな睡眠グラフ

**睡眠チャート** は、統合された複数か月のインタラクティブなタイムラインで睡眠と学習の履歴を視覚化します。

- **生物学的な起床日の固定**: 睡眠エピソードは生物学的な起床日 (タイムゾーンおよび DST セーフ) に固定され、一晩の睡眠と昼間の昼寝が正しい認知日によるものであることが保証されます。
- **睡眠段階と昼寝**: 詳細な睡眠段階 (深い、レム、浅い、覚醒) を日中の昼寝や睡眠中断とともに表示します。
- **学習セッションのオーバーレイ**: フラッシュカードのレビュー セッション、読書セッション、評価の試みをタイムライン上に直接オーバーレイし、睡眠ブロックや概日位相と比較していつ勉強したかを正確に示します。
- **日付の検査と競合の解決**: 任意の日をクリックして、詳細な指標、睡眠段階の内訳、ソースの出所、およびマルチデバイスの不一致を検査します。

### 概日情報と睡眠インテリジェンス

Plethora は、臨床機器を必要とせずに睡眠の質とタイミングを分析します。

- **睡眠規則性指数 (SRI)**: 日々の睡眠スケジュールの一貫性を測定します (24 時間離れて同じ状態 (睡眠中と覚醒中) にある確率を計算します)。より高い規則性は、安定した認知能力と強く相関します。
- **Borbély 2 プロセス モデル**: 恒常性睡眠圧 (プロセス S) と概日覚醒 (プロセス C) を組み合わせた探索的で非臨床的な覚醒シミュレーションを表示し、自然なピーク学習ウィンドウと概日ディップを強調します。
- **睡眠時間と睡眠不足**: ベースラインに対してローリング睡眠合計を追跡し、急性の睡眠不足と回復を監視します。
- **生理学的回復**: 夜間の心拍数変動 (RMSSD と SDNN を個別に追跡した HRV) と安静時心拍数 (RHR) を視覚化し、自律神経の回復と準備状態を反映します。

### 学習パフォーマンスと記憶力の相関関係

Plethora は、相関関係が因果関係と等しいと仮定するのではなく、保守的な統計手法を適用して、睡眠が記憶保持にどのような影響を与えるかを評価します。

- **FSRS-7 想起残差**: すべてのフラッシュカード レビューについて、Plethora は評価の前に時系列で「観察された再現率 - 予測された回収可能性」を計算します。 This isolates the physiological effect of sleep from the card's age and inherent difficulty.
- **Response Latency**: Analyzes winsorized log-latency to measure recall speed and retrieval effort across different sleep states.
- **交絡因子調整分析**: 体内の重回帰を使用して、一日の時間帯の概日リズム (「sin」/「cos」)、カードの難易度、および以前の 24 時間の学習ワークロードを制御します。
- **証拠検査**: 個人パターンで [**証拠の検査**] をクリックすると、サンプル サイズ、日クラスター化ブロック ブートストラップ信頼区間、Benjamini-Hochberg 誤検出率 (FDR) コントロールを検査できます。 Plethora explicitly marks associations where data is insufficient rather than presenting premature conclusions.
- **学習計画の健康に関する洞察カード**: 埋め込まれた健康概要が学習計画の進捗状況ビューとホーム ビューに表示され、睡眠の規則性と睡眠時間がカリキュラムのマイルストーンや試験の成績とどのように一致しているかを示します。

### データソースとウェアラブル接続

Plethora supports a complete range of data collection options—from zero-wearable manual tracking to multi-device wearable ecosystems:

- **ウェアラブル不要 (手動ログ)**: [**睡眠のログ**] をクリックして、手動で睡眠 (就寝時間、起床時間、品質評価、およびオプションの段階) を記録します。
- **インタラクティブなサンプル データ**: [**サンプル データ**] をクリックすると、実際のレコードを変更せずに、メモリ内ボルトに読み込まれた一時的な合成データセットを使用して完全な機能セットを探索できます。
- **File Import & Export**: Import sleep and health records from Apple Health (`export.xml`), Plethora Health JSON, or CSV spreadsheets. Export your data as standard JSON/CSV or as a passphrase-protected encrypted bundle (`.plethora-health.enc` using PBKDF2 and AES-256-GCM).
- **Native Mobile Bridges**: On iOS, connect **Apple HealthKit**; on Android, connect **Android Health Connect** for automated, incremental background synchronization.
- **クラウド ウェアラブル プロバイダ**: **Oura Ring** (クラウド API v2)、**WHOOP** (開発者 API v2)、**Google Health** (v4、Pixel Watch と Fitbit をカバー) 用のダイレクト OAuth 2.0 PKCE コネクタ。
- **ソースの優先度**: 複数のデバイス (Apple Watch や Oura Ring など) が同じスリープ ウィンドウを記録する場合、Plethora は設定で設定された優先プロバイダーの優先度に基づいてレコードの重複を排除します。

### ローカルファーストのプライバシー アーキテクチャ

医療データは機密性が高く、厳格なローカルファースト分離の対象となります。

- **専用 Health Vault**: メイン ライブラリ データベース (`plethora.db`) から物理的に分離された、別のデバイス上の SQLite データベース (`<app_data_dir>/health/health.db`) に保存されます。
- **ゼロクラウドとAIエグレス**: ヘルスレコードは、Plethoraクラウドバックアップ、E2EEデバイス同期、セマンティックチャンクインデックス作成、またはAI/LLMプロンプトコンテキストには決して含まれません。
- **安全な保管庫の削除**: 個別のエントリを削除するか、**設定 → 統合 → ヘルス＆ウェアラブル** でデータベースの圧縮を使用して保管庫を完全に消去します。

### 学習設定

#### アルゴリズムの選択

Plethora は、実稼働間隔反復アルゴリズムである **FSRS-7** を使用してフラッシュカード レビューをスケジュールします。学習設定には、FSRS-7 が唯一のスケジューラとして表示されます。レガシー アルゴリズム (SM-18、SM-20、Plethora Classic) は研究と移行のためにコンパイルされたままですが、ピッカーには表示されません。

**FSRS-7 (製品版):**
- デュアル トレース メモリ モデル (低速 + 高速安定性トレース)
- 同日レビューの分数経過時間スケジュール設定
- オプションの個人最適化を備えた 34 パラメーター モデル
- プレビュー間隔付きの 4 つのボタンによる評価

#### パラメータ

**望ましい保持力:** 0.70 - 0.95
- **90%** (デフォルト): 保持とレビュー負荷のバランスをとります。
- **85%**: レビューが少なく、維持率もわずかに低下
- **95%**: 最大の保持率、より多くのレビュー

**1日あたりの学習量:** 10 - 100
- **20** (デフォルト): ほとんどのユーザーが管理可能
- **50**: 集中的な学習期間用
- **10**: レビュー負荷が軽い

**1 日あたりのレビュー:** 50 - 500
- **200** (デフォルト): 妥当な 1 日あたりの制限
- **500**: バックログのクリア用
- **50**: 軽いレビュー日

#### インターバル設定

**新しいカードの間隔:**
- 卒業間隔 (良い評価): 1 ～ 10 日
- 簡単な間隔: 3 ～ 21 日
- 最小間隔: 1 日

**最大間隔:**
- 最長間隔の上限 (デフォルトは 365 日)
- カードがあまりにも大幅にスケジュールされるのを防ぎます

**長尺安全キャップ (ビデオ/記事):**
- 長いビデオ/記事の場合、肯定的な評価 (「良い」/「簡単」) はカバレッジを考慮しています。
- 推定コンテンツ時間の **25%** に満たない場合、次の間隔は **1 日**に制限されます。
- 支出が **50%** 未満の場合、次の間隔は **2 日**に制限されます。
- 支出が **75%** 未満の場合、次の間隔は **4 日**に制限されます。
- これにより、部分的な進行後に長い形式のコンテンツが大幅にスケジュールされるのを防ぎます。
- 適用されると、スケジューラの理由には、透明性を確保するための **期間を考慮した上限** の注記が含まれます。

### 同期設定

Plethora は、**共有同期ルーム** を介してデバイス間で読書データを同期します。アカウント、サーバーへのログイン、API キーは必要ありません。同じ同期コードを知っているすべてのデバイスが同じルームに参加し、同じデータを共有します。これはアプリ内の唯一の同期システムです。

#### 仕組み

- 初めて同期設定を開いたときに、各デバイスは **同期コード** (ランダムな文字列) を生成します。
- そのコードを他のデバイスと共有します。コードをコピーするか、同期設定に表示されている QR コードをスキャンします。
- 2 台のデバイスがコードを共有すると、同時にオンラインになっているときはいつでも、その読書データ (文書、抜粋、学習項目、レビュー履歴、設定) が自動的に同期されます。ドキュメントに添付されたファイルは、同じ部屋を通じて同期されます。
- ルームへのアクセスを許可するのは同期コードだけです。非公開にしておきます。これを持っている人は誰でも同期データを読み取ることができます。

#### デバイスを接続する

1. 最初のデバイス (デスクトップなど) で **[設定] → [同期]** を開きます。そこに表示されている同期コードをメモするか、その QR コードを表示します。
2. 2 番目のデバイス (携帯電話など) で **[設定] → [同期]** を開きます。
3. 次のいずれか:
   - [**スキャン**] をタップし、最初のデバイスの QR コードにカメラを向けます。または
   - 同期コードを [別のコードに参加] フィールドに貼り付け、**参加** をタップします。
4. 2 番目のデバイスがルームに参加し、すぐに同期を開始します。リロードや再起動は必要ありません。
5. 同期を維持したいすべてのデバイスに対してこの手順を繰り返します。

> **ヒント:** [新規] ボタンをクリックすると、新しい同期コードが生成されます。これは、最初からやり直す場合にのみ使用してください。古いコード上のデバイスは、新しいコード上のデバイスとの同期を停止します。

#### 同期内容

- ドキュメントとそのメタデータ
- 抜粋（ハイライトとメモ）
- 学習項目 (フラッシュカード、クローズの削除、Q&A)
- 履歴とスケジュール状態を確認する
- アプリの設定
- ドキュメントに添付されたファイル (PDF、EPUB など)

#### ファイルの自動ダウンロード

**ファイル同期** で、新しいファイルを各デバイスにどの程度積極的にプルするかを選択します。

- **常に** — ルームに表示されるすべてのファイルを自動的にダウンロードします。
- **WiFi のみ** — WiFi 上でのみ自動ダウンロードします (モバイル データ プランで便利です)。
- **手動** — 決して自動ダウンロードしません。各ファイルにはダウンロード ボタンが表示されるので、必要なときにタップします。

#### エンドツーエンド暗号化 (オプション)

同期はデフォルトでは「TLS のみ」モードで実行されます。データはネットワーク上で暗号化されて送信され、同期コードは共有シークレットとして機能します。より強力な保護が必要な場合は、**エンドツーエンド暗号化**を有効にできます。これにより、デバイス上のデータが外部に送信される前に暗号化され、同期サーバーは暗号文のみを参照できるようになります。

暗号化がオンになっている場合、QR コードにはルームの秘密が埋め込まれます。信頼できるデバイスとのみ共有します。

#### プライバシー

すべての読書データは、まずデバイス上にローカルに保存されます。同期は、共有ルーム上のデバイス間でデータをミラーリングする便利なオプションです。個人的に構成した AI プロバイダー以外のサーバーには何も送信されません。

#### バックアップと復元

Plethora は、学習データを保護し、デバイス間で移行するための完全なバックアップおよび復元システムを提供します。

#### 完全なアプリのバックアップ

**バックアップされる内容:**
- **設定**: すべての設定、テーマ、学習パラメータ
- **ドキュメント**: メタデータを含むすべてのインポートされたドキュメント
- **抜粋**: すべてのハイライトと抽出されたコンテンツ
- **学習アイテム**: すべてのフラッシュカード、クローズの削除、Q&A カード
- **スケジュール データ**: アルゴリズムのメモリ状態 (安定性、難易度、間隔)、期日
- **コレクション**: すべてのコレクションとドキュメントの割り当て
- **UI 状態**: サイドバーの状態、テーマの設定
- **オプション**: 実際のドキュメント ファイル (PDF、EPUB など)

**バックアップの作成:**

1. **[設定] → [インポート/エクスポート] → [アプリの完全バックアップ]** に移動します。
2. [**バックアップと復元を開く**] をクリックします。
3. **バックアップのエクスポート** を選択します
4. オプションのラベルを追加します（例：「PC を再フォーマットする前」）
5. ドキュメント ファイルを含めるかどうかを選択します。
   - **メタデータのみ**: ファイルが小さい (~KB-MB)、ファイルを個別に再インポートします
   - **インクルード ファイル**: より大きなファイル (~MB ～ GB)、完全な自己完結型バックアップ
6. **[バックアップのエクスポート**] をクリックし、`.incrementum` ファイルを保存します。

**ファイル形式:**
- 拡張子: `.incrementum`
- 形式: ヘッダーコメント付きの JSON
- 命名: `incrementum-backup-[ラベル]-[日付]-[時間].incrementum`

**バックアップからの復元:**

1. **[設定] → [インポート/エクスポート] → [アプリの完全バックアップ]** に移動します。
2. [**バックアップと復元を開く**] をクリックします。
3. **バックアップのインポート**を選択します
4. `.incrementum` ファイルを選択します
5. バックアップの内容をプレビューします。
   - 文書数
   - 抽出数
   - 学習項目数
   - コレクション数
   - ファイルが含まれるかどうか
6. インポート オプションを構成します (オプション)。
   - **何をインポートするか**: 特定のデータ型を選択してください
   - **重複処理**: スキップ、置換、またはマージ
   - **ファイルのインポート**: 文書ファイルを復元するかどうか
7. [**バックアップのインポート**] をクリックします。
8. インポートが完了するまで待ちます (進行状況が表示されます)。

**重複処理戦略:**
- **スキップ**: すでに存在する項目をスキップします (ほとんどの場合に推奨)
- **置換**: 既存のアイテムをバックアップ バージョンで上書きします
- **マージ**: すべてのアイテムの新しいコピーを作成します (重複が作成される可能性があります)

**使用例:**

|シナリオ |推奨されるアプローチ |
|----------|---------------------|
| **新しいコンピュータに移行** |ファイルとともにエクスポートし、新しいマシンにインポート |
| **大きな変更の前にバックアップ** |メタデータのみの迅速なバックアップ |
| **デバイス間で同期** |エクスポート/インポートのワークフロー |
| **コレクションを共有する** |特定のコレクションをエクスポートする |
| **古いデータをアーカイブする** |エクスポートして長期保存 |
| **再フォーマット後の復元** |ファイルを含む完全なバックアップをインポート |

**重要な注意事項:**
- **スケジュールの保存**: すべてのアルゴリズム タイプのすべてのスケジュール データ (安定性、難易度、期日) が正確に保存されます。
- **ファイル パス**: ファイルなしでインポートする場合は、元のドキュメントを再インポートする必要があります。 Plethora はコンテンツ ハッシュによってそれらを照合し、メタデータを復元します。
- **バージョン互換性**: バックアップには上位互換性がありますが、古いバージョンのアプリでは動作しない可能性があります
- **ストレージ**: バックアップを安全に保管します - バックアップには個人の学習データが含まれます

Plethora 内で NotebookLM を使用して、調査、研究成果物の生成、レビュー可能な抽出物の保存を行います。

**セットアップ:**
1. 設定 → 機能 → **NotebookLM** を有効にします
2. 設定 → 統合 → **NotebookLM**
3. **接続** をクリックし、プロバイダーを選択します (テスト用には「mock」、ライブ NotebookLM には「cli」)
4. アクティブなノートブックを選択または作成します

**ノートの作成:**
- **新しいノートブック** (サイドバーまたは空の状態) をクリックし、アプリ内ダイアログにタイトルを入力します。
- 最初のクリックでタイトルが NotebookLM に送信されます。2 回目のクリックは必要ありません
- ノートブックの作成中、ボタンにはスピナーが表示され、無効になります。失敗は黙って何もしないのではなく、トーストとして表面化します。
- 空の状態から作成すると、新しいノートブックが自動的に選択されるため、次のアクションはそれに対して実行されます。

**あなたにできること:**
- Plethora から直接 NotebookLM チャットで質問する
- 調査プロンプトの実行 (Web 支援ノートブック調査)
- アーティファクトの生成:
  - フラッシュカード
  - クイズ
  - 報告書（説明会資料）
  - 学習ガイド
  - マインドマップ
  - データテーブル
  - スライドデッキ（形式：詳細/発表者、長さ：デフォルト/短い）
  - インフォグラフィック (向き、詳細レベル、スタイル オプション)
  - オーディオの概要
  - ビデオの概要
- アプリ内でアーティファクトをプレビュー:
  - テキスト/構造化された成果物 (レポート、学習ガイド、マインド マップ、データ テーブル) を専用ビューアでレンダリング
  - オーディオとビデオの概要は、アプリのメディア プレーヤーを通じてインラインで再生されます
  - インフォグラフィックスを画像として表示
  - スライドデッキは PDF として表示されます
- 生成されたフラッシュカード/クイズ項目を Plethora レビューキューに同期します

**アーティファクト アクション (ビューア内):**
- **コピー** — アーティファクトのコンテンツをクリップボードにコピーします
- **Markdown としてコピー** — Markdown エクスポート (テキストおよび構造化アーティファクト) をコピーします。
- **ライブラリに保存** — アーティファクトを現在のコレクションにドキュメントとしてインポートします。すでに保存されているアーティファクトは、複製ではなく、
- **エクスポート** — ネイティブの保存ダイアログを使用してアーティファクトをマークダウン ファイルとして保存します (JSON/HTML エクスポートは Studio ジョブの詳細から利用できます)

**ライブラリへのアーティファクトのインポート:**
- レポートとスタディ ガイドはマークダウン ドキュメントとしてインポートされ、すぐにキューに入れて抽出できます
- マインド マップとデータ テーブルは、インタラクティブなビューアを維持する構造化ドキュメントとしてインポートされます。
- オーディオ概要はポッドキャスト スタイルのアイテムとしてインポートされます。ビデオアイテムとしてのビデオ概要
- スライドデッキは PDF ドキュメントとしてインポートされます。インフォグラフィックスは画像ドキュメントとしてインポートされ、**イメージ レジストリ**にも追加されます (コンテンツによって重複が排除されるため、再保存しても重複は作成されません)
- インポートされたアーティファクトはコレクション ライブラリのルートに到達し、他のライブラリ アイテムと同じ条件でキューの対象になります。

**ソースの追加:**
- **URL**、**YouTube** リンク、貼り付けた **テキスト**、ローカル **ファイル**を追加するか、**ライブラリ**からドキュメントを選択します
- ライブラリドキュメントは同じ取り込みパイプラインを通じて添付され、NotebookLM が処理を完了するまで保留ステータスを表示します。
- すでに添付されている文書が検出されるため、重複した文書は追加されません

**チャットの応答を抽出として保存:**
1. NotebookLM ワークスペース チャットを開く
2. アシスタントの応答で、[**抽出として保存**] をクリックします。
3. オプション: 最初に応答の一部を強調表示して、選択したテキストのみを保存します
4. Plethora は、スレッド/ソースのメタデータを使用して NotebookLM にリンクされた抽出を作成します
5. 保存された回答には、重複を避けるために **すでに保存されました** インジケーターが表示されます

**ドキュメント Q&A + NotebookLM ワークフロー:**
1. Plethora でドキュメントを開きます
2. NotebookLM リサーチ モードで **ドキュメント Q&A** を使用する
3. 生成された回答テキストをインラインで編集/調整する
4. 洗練された回答から抜粋を作成する
5. これらの抜粋からフラッシュカード/クローズ/Q&A アイテムを生成します。

**トラブルシューティング:**
- アーティファクトのプレビューでメディアが利用できないと表示された場合は、NotebookLM の生成が完了するまで待って、アーティファクトを再度開きます。
- ビデオ、オーディオ、インフォグラフィック、またはスライド デッキが表示されない場合は、アーティファクトを再度開きます。ビデオ/オーディオおよびインフォグラフィックは、代替メディア パスを通じて自動的に再試行されます。スライドデッキが読み込まれない場合、「代替ビューアで開く」オプションが提供されます。
- 「cli」プロバイダーを使用する場合は、NotebookLM サイドカー/CLI がビルドで利用可能であることを確認してください。
- プロバイダーを変更した場合、または認証が期限切れになった場合は、「統合」→「NotebookLM」で再接続します。

#### セクションの言及 (`#`)

質問またはプロンプト内の文書の一部に言及するには、アシスタント (または Flashcard Studio) で「#」を入力します。

- 見出しまたは PDF/EPUB アウトラインのあるドキュメントには、以前と同様にセクションがリストされます。
- 見出しのないプレーンなインポート記事には **派生セクション インデックス**が付けられます。段落はラベル付きセグメントにグループ化されるため、読み取り可能なテキストを含むドキュメントのポップアップが空になることはありません。
- 文書内でテキストを**選択**している場合、その選択内容が最初のエントリとして表示されます。これを選択すると、選択したテキストがコンテキストとして正確に添付されます(必要に応じて、コンテキストの予算に合わせて切り詰められ、通知が表示されます)。
- 文書に抽出可能なテキストがない場合、ポップアップには空のリストが表示されるのではなく、その旨が明示的に表示されます。

#### ヘルスケアとウェアラブルの統合

ウェアラブル接続、データ ソースの優先順位、ローカル ボルト ストレージを管理します。

1. **[設定] → [統合] → [健康とウェアラブル]** に移動します。
2. **Local Health Vault**: データベースのストレージ サイズ、レコード数、および最後の最適化日を確認します。
3. **プロバイダーの接続**: サポートされているネイティブ プラットフォーム (iOS の Apple HealthKit、Android の Health Connect) またはクラウド プロバイダー (Oura、WHOOP、Google Health) に接続します。

5. **データ転送**: ローカルの健康ファイルをインポートするか、パスフレーズで暗号化された `.plethora-health.enc` バックアップをエクスポートします。
6. **Vault のワイプ**: 自動化された SQLite 圧縮を使用して、ローカルの健康状態と睡眠の記録をすべて完全に消去します。

#### オンデバイス Apple Intelligence (Mac および iPhone)

サポートされている Apple デバイスでは、Plethora は **Apple Foundation Models** (Apple の組み込みオンデバイス言語モデル) を使用して多くの AI 機能を実行できます。これはクラウド プロバイダー (OpenAI、Ollama など) とは別のものであり、**API キーは必要ありません**。

**概要:** スマート タグ付け、要約、フラッシュカードの生成、図書館に質問するなどのタスクのためのデバイス上でのテキスト生成。

**そうでないもの:** Apple Foundation Models はビデオや音声を**文字起こししません**、テキストの読み上げ (TTS) も**しません**、そして写真を**分析しません**。これらのジョブには、Plethora の **音声文字起こし** および **TTS** 設定を使用してください。

**要件:**
- **Mac:** macOS 26 以降、Apple Silicon、システム設定で Apple Intelligence がオンになっている
- **iPhone / iPad:** iOS 26 以降、Apple Intelligence 対応、互換性のあるデバイス

**オンにする方法:**
1. **[設定] → [AI プロバイダーの設定]** を開きます
2. **オンデバイス AI** までスクロールします
3. **オンデバイス AI を優先** をオンにします
4. **Foundation Models** (または **Apple Intelligence**) に **Ready** と表示されていることを確認します

準備が完了すると、Plethora はサポートされているタスクに対してデバイス上の Apple AI を自動的に使用します。 Apple をクラウド プロバイダー リストに追加しません。

**オンデバイスの Apple AI でできること:**

|特集 |デバイス上で動作しますか? |
|----------|-----------------|
|スマートタグ |はい |
|一節を要約/説明する |はい |
| Ask Library (図書館からの回答) |はい |
|テキストからフラッシュカードを生成 |はい |
|要点の抽出、質問の検討 |はい |
|スタジオレビューのヒント |はい |
|ビデオまたはオーディオブックを文字に起こす |いいえ — **[設定] → [音声文字起こし]** を使用します。
|テキストを読み上げる (TTS) |いいえ — **[設定] → [テキスト読み上げ]** を使用します。
|画像の説明/OCR |いいえ — OCR またはビジョン機能を使用します。

**プライバシー:**
- デフォルトでは、処理は **お使いのデバイス**に残ります
- **クラウド フォールバックを許可する**はデフォルトでオフになっています。オンデバイス AI がタスクを完了できない場合、Plethora はコンテンツを有料クラウド プロバイダーに**黙って送信しません**
- オンデバイス AI が利用できないときに Plethora が設定済みのクラウド プロバイダーで再試行するようにしたい場合は、クラウド フォールバックを有効にすることができます

**ステータスが準備完了でない場合:**

|ステータス |意味 |試してみること |
|----------|------|---------------|
|準備完了 |オンデバイス AI が利用可能 | AI 機能の通常の使用を開始する |
|ダウンロード中… |システム モデルはまだインストール中です |待ってから、オンデバイス AI | で [**更新**] をタップします。
|無効 | Apple インテリジェンスがオフになっています |システム設定で Apple Intelligence を有効にする |
|対象外 |デバイスまたは地域がサポートしていません |代わりにクラウドまたはローカルプロバイダーを使用してください。
|サポートされていない OS |バージョン 26 より前の macOS/iOS |システムを更新するか、別のプロバイダーを使用してください。

**ヒント:** 長いドキュメントは自動的に処理されます。Plethora はドキュメントをデバイス上のコンテキスト ウィンドウに適合するチャンクに分割し、結果を結合します。これを設定する必要はありません。

#### オンデバイス Windows AI (Windows 11)

Windows デスクトップでは、Plethora はライブラリ コンテンツを OpenAI、Anthropic、または個別に構成したその他のクラウド API に送信せずに、**PC 上**で AI タスクを実行できます。 Windows では、次の 2 つの補完的なオンデバイス パスが提供されます。

1. **システム オンデバイス AI** — PC と Windows のバージョンがテキスト タスクと OCR をサポートしている場合は、テキスト タスクと OCR 用の組み込み Windows AI API
2. **Foundry Local** — 自分でインストールするオプションの OpenAI 互換ローカル サーバー (Copilot+ NPU を持たないハードウェアを含む、多くの GPU で動作します)

これらのパスはクラウド プロバイダーとは別のものであり、クラウド フォールバックを有効にしない限り、**OpenAI API キーを使用しないでください**。

**概要:** スマート タグ付け、パッセージの要約、フラッシュカードのアイデア、図書館への回答、ワークフロー ショートカットのためのデバイス上でのテキスト生成。さらに、**[設定] → [ドキュメント] → [OCR]** で有効にすると、スキャンされた PDF および画像に対する **Windows システム OCR** が追加されます。

**特徴:** System On-​​Device AI は音声やビデオを**文字起こししません** (**[設定] → [音声文字起こし]** を使用)、**テキストを読み上げません** (**[設定] → [テキスト読み上げ]** を使用)、**すべての Windows PC で実行されるわけではありません**。 Copilot+ NPU 機能 (Phi Silica テキスト AI および Windows System OCR) にはハードウェアが必要であり、Windows ビルドの多くのゲーム PC はこの条件を満たしていません。**Foundry Local**、**Tesseract**、またはクラウド プロバイダーが現実的な選択肢として残ります。

**要件:**
- **Windows 11 バージョン 24H2 以降** (ビルド 26100+) (システム オンデバイス AI ステータス チェック用)
- **パッケージ ID** がインストール時に登録されます (Plethora の Windows インストーラーはスパース MSIX ID を自動的に登録します。登録が失敗すると、System On-Device AI は非アクティブなままになります)
- Microsoft の Phi Silica 言語モデル用 **Copilot+ / NPU クラス ハードウェア** - 多くのディスクリート GPU (古い GeForce カードなど) は、Foundry Local が正常に動作する場合でも Tier 1 テキスト AI を使用できません
- **Foundry Local:** Foundry Local ランタイムをインストールして有効にする任意の Windows PC

**オンにする方法:**
1. **[設定] → [AI プロバイダーの設定]** を開きます
2. **オンデバイス AI** までスクロールします
3. **オンデバイス AI を優先** をオンにします
4. **System On-Device AI** および **Foundry Local** ステータス行を確認します

**オンデバイス AI を優先** がオンの場合、Plethora は最初に Windows 上で System On-Device AI を試行し、次に有効になっている場合は、設定されたクラウド プロバイダーの前に Foundry Local を試行します。ただし、**クラウド フォールバックを許可する** がオフの場合は、失敗がオンデバイスに残ります。

**あなたにできること:**

|特集 |システムオンデバイス AI |ファウンドリ ローカル |
|----------|---------------------|--------------|
|スマートタグ |準備ができたら |ランタイムとモデルの準備が完了したら |
|一節を要約/説明する |準備ができたら |準備ができたら |
|図書館に聞く |準備ができたら |準備ができたら |
|テキストからフラッシュカードを生成 |準備ができたら |準備ができたら |
|インポート時の OCR / PDF (Windows システム OCR) | OCR の準備ができたら |いいえ — Tesseract またはクラウド OCR を使用します |
|音声またはビデオを文字に起こす |いいえ |いいえ |
|テキストを読み上げる (TTS) |いいえ |いいえ |

**ドキュメント → OCR:** **設定 → ドキュメント → OCR** に **Windows システム OCR** が表示されたら、それを直接選択するか、**Windows システム OCR を優先** を有効にして、利用可能な場合はインポートと PDF OCR に自動的に使用します。上記と同じ Windows AI スタックを使用し、利用できない場合は Tesseract または選択した OCR プロバイダーにフォールバックします。

**プライバシー:**
- **オンデバイス AI を優先** は、サポートされているタスクを最初にオンデバイス バックエンドにルーティングします。
- **クラウド フォールバックを許可する**はデフォルトでオフになっています - オンデバイス AI が失敗した場合、Plethora はライブラリ コンテンツを有料クラウド API にサイレントに送信しません**
- Foundry Local はマシン上で推論を維持します。構成されたローカル エンドポイントのみが接続されます

**ステータスが準備完了でない場合:**

|ステータス |意味 |試してみること |
|----------|------|---------------|
|利用可能 / 準備完了 |機能は準備完了です | AI 機能を通常どおり使用します。それでも問題が解決しない場合は、**診断** を開きます。
|ダウンロード可能 / ダウンロード | Windows AI モデルはまだインストールされていません | Windows Update またはモデルのインストールを待ってから、**更新** | をタップします。
|パッケージ ID が見つかりません |スパース MSIX が登録されていません。 Plethora を再インストールまたは修復します。 **診断**でスパースMSIXパスを確認してください。
|制限付きアクセスが拒否されました | Phi Silica には Microsoft LAF ロック解除が必要です |高度なセットアップのみ。 Foundry Local には必要ありません |
|サポートされていないハードウェア | PC には、この Windows AI 機能に必要な NPU がありません。 **Foundry Local** を有効にするか、クラウド プロバイダーを使用するか、OCR に Tesseract を使用します。
|サポートされていない OS | Windows ビルド 24H2 以前 | Windows を更新するか、Foundry Local/クラウドを使用する |

Windows で **[設定] → [オンデバイス AI] → [診断]** を開き、パッケージ ID、ブリッジの可用性、OCR の準備状態、Foundry Local エンドポイントの健全性を確認します。

**ヒント:** 強力な GPU を搭載しているが Copilot+ NPU を搭載していないゲーミング PC では、通常、**Foundry Local** が現実的なオンデバイス AI パスです。 System On-​​Device AI ステータスは、Phi Silica または Windows System OCR がハードウェアで利用できない理由を確認するのに依然として役立ちます。

#### コンテキスト ウィンドウ

**トークンの制限:**
- リクエストあたりの最大トークン数 (レスポンスの長さ)
- 関連カードのコンテキスト
- 文書スニペットの長さ

**ローカルモデル (オラマ):**
- **コンテキスト ウィンドウ** は、`num_ctx` として送信されるランタイム KV キャッシュ サイズ (プロンプトと応答が収まるサイズ) です。 8K ～ 16K で開始します。値が大きいほど、より多くの GPU/RAM が使用されます。
- **最大応答トークン** は、生成される長さ (`num_predict`) に対する個別の上限です。コンテキストウィンドウではありません。
- 自動解決は、モデルの理論上の最大値ではなく、4K ～ 16K の間の実際的な値に解決されます。
- クラウド プロバイダーは、依然として出力長の max-response 設定のみを使用します。

### OCR (光学式文字認識)

画像からテキストを抽出します。

**サポートされているプロバイダー:**
- Mirage Vision Engine (ローカル) — ドキュメントの取り込み、画像のオクルージョン、FTS5 検索、およびブラウザ クリップにわたる視覚的なインデックス作成
- GLM-OCR (ローカル) — llama.cpp または vLLM を介したマルチモーダル OCR
- テッセラクト (ローカル)
- Google クラウド ビジョン
- AWS Textract
- Azure コンピュータ ビジョン
- マーカー (ローカル) — PDF からマークダウンへ
- ヌガー (ローカル) — 数学を含む科学文書

**使用例:**
- スクリーンショットのキャプチャ
- スキャンした文書
- テキスト付きの画像
- 手書きのメモ

**セットアップ (クラウドプロバイダー):**
1.設定→OCR
2. プロバイダーを選択します (Google、AWS、または Azure)
3. API キーと認証情報を構成する
4. 言語を選択します
5. サンプル画像でテストする

**セットアップ (llama.cpp を使用した GLM-OCR):**

llama.cpp は、GPU を必要としない、GLM-OCR 用の軽量のローカル LLM サーバーを提供します。ポート 8080 で OpenAI 互換 API を使用します。

1. **llama.cpp をビルドします** (まだビルドされていない場合):
   「」バッシュ
   git clone https://github.com/ggml-org/llama.cpp.git
   cd ラマ.cpp
   cmake -B ビルド
   cmake --build build --config Release -j$(nproc)
   「」

2. **マルチモーダル モデルをダウンロード** (GGUF 形式):
   「」バッシュ
   # Qwen2.5-VL (OCR推奨)
   ハグフェイス-cli ダウンロード bartowski/Qwen2.5-VL-7B-Instruct-GGUF \
     Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf --local-dir models/
   「」

3. **サーバーを起動します**:
   「」バッシュ
   ./build/bin/llama-server \
     -m モデル/Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf \
     --ポート 8080 --ホスト 0.0.0.0 -c 16384 -t $(nproc)
   「」

4. **Plethora での設定**:
   - 設定 → OCR → プロバイダー: **GLM-OCR (ローカル)**
   - バックエンド: **vLLM (GPU)** (これは llama.cpp/vLLM モードです - 両方で機能します)
   - エンドポイント: `http://localhost:8080/v1`
   - モデル: モデルのファイル名 (例: `Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf`)

**パフォーマンスに関するヒント:**
- 長い文書には `-c 16384` 以降を使用します (デフォルトの 4096 はほとんどの OCR タスクには小さすぎます)
- すべての CPU スレッドを使用するには、「-t $(nproc)」を使用します。
- Q4_K_M 量子化は、CPU 推論に最適な品質と速度のトレードオフを提供します
- GPU アクセラレーションの場合、CUDA、Metal、または Vulkan をサポートする llama.cpp をビルドします。

**セットアップ (vLLM を使用した GLM-OCR):**

vLLM は、大規模なモデルに対して GPU アクセラレーションによる推論を提供します。十分な VRAM を備えた NVIDIA GPU が必要です。

「」バッシュ
pip install -U vllm
vllm は zai-org/GLM-OCR --allowed-local-media-path / --port 8080 を提供します
「」

次に、Plethora を同じ方法で設定します (エンドポイント `http://localhost:8080/v1`)。

**セットアップ (GLM-OCR と Ollama):**

始めるための最も簡単なオプション — Ollama はモデルのダウンロードとランタイムを自動的に管理します。

1. 設定 → OCR → プロバイダー: **GLM-OCR (ローカル)**
2. バックエンド: **Ollama (CPU)**
3. [**Ollama をダウンロード**] をクリックします (インストールされていない場合)
4. [**ランタイムの開始**] をクリックします。
5. モデルを設定します (例: `llava:7b` または `qwen2-vl:7b`)
6. [**プルモデル**] をクリックします。

**数学 OCR:**
- 方程式の特殊な処理
- LaTeX出力
- 記号認識
- 最適な用途: 科学論文、教科書

## ヒントとベストプラクティス

### カードの作成

**実行:**
- カードを具体的にする (カードごとに 1 つの事実)
- シンプルで明確な言葉を使用する
- 回答にコンテキストを含める
- 関連する例を追加します
- 人間関係にはclozeを使用する
- 質問は簡潔にしましょう

**禁止事項:**
- 複数の事実を 1 枚のカードに入れる
- 曖昧な表現を使用する
- 質問が簡単すぎたり、難しすぎたりする
- 大きなテキストブロックをコピーする
- 定義のない略語を使用する

**例 - 悪いカード:**
「」
Q: ミトコンドリアの機能とは何ですか?また、どのように機能するのですか?
それは細胞呼吸におけるATP生成に関係しているのでしょうか？
A: [段落の説明]
「」

**例 - 良いカード:**
「」
カード 1:
Q: ミトコンドリアの主な機能は何ですか?
A: 細胞呼吸を通じて ATP を生成します。

カード 2:
Q: ミトコンドリアはどのようなプロセスを使用して ATP を生成しますか?
A: 細胞呼吸（好気性）

カード 3:
Q: ミトコンドリアによって生成されるエネルギー通貨とは何ですか?
A：ATP（アデノシン三リン酸）
「」

### 勉強のルーチン

**毎日のスケジュール (20 ～ 30 分):**
1. **午前**: 期日カードを確認する (15 分)
2. **一日中**: 読書からの抜粋を作成します
3. **夕方**: 抜粋からカードを作成します (10 ～ 15 分)

**週間スケジュール:**
- **月～金**: 定期的なレビューとカードの作成
- **土曜日**: 長時間の勉強会 (1 ～ 2 時間)
- **日曜日**: 分析のレビュー、目標の調整、整理

**大容量の管理:**
- 1 日のレビュー制限を設定します (例: 50 枚のカード)
- カテゴリごとに優先順位を付ける（1 つのテーマに焦点を当てる）
- スマートキューを使用してタスクを分割する
- 20～30分ごとに休憩を取る

### 保持の最適化

**定着率の向上:**
- 正直に評価してください (評価を水増ししないでください)
- 一貫してレビューします (毎日がベストです)
- 十分な睡眠をとる（睡眠中に記憶が定着します）
- アクティブリコール (覗かないで、まず考えてください)
- 間隔をあけてレビューする（詰め込みすぎない）

**物忘れへの対処:**
- 通常は 10 ～ 20% 忘れます (目標の保持率に応じて)
- 「もう一度」カードは学習の機会です
- 頻繁に忘れる場合 (>30%)、次のことを考慮してください。
  - 望ましい保持率を下げる (85 ～ 90%)
  - よりシンプルなカードの作成
  - コンテキストをさらに追加する
  - より頻繁にレビューする

### カテゴリの組織

**ベストプラクティス:**
- まず大まかに開始し、次に細分化します
- 例: `プログラミング` → `プログラミング/Python` → `プログラミング/Python/非同期`
- 一貫した命名を使用する
- あまり多く作成しないでください (5 ～ 10 個は管理可能です)
- 使用されていないカテゴリをマージします

**カテゴリ構造の例:**
「」
§── プログラミング
│ §── パイソン
│ §── 錆びる
│ └── アルゴリズム
§── 言語
│ §── スペイン語
│ └── 日本語
§── 科学
│ §── 物理学
│ └── 生物学
━── プロフェッショナル
    §── プロジェクト管理
    ━── システム設計
「」

### 優先順位の管理

**優先ガイドライン:**
- **100 (重要)**: 試験準備、緊急作業プロジェクト
- **80-90 (高)**: 現在のコース、アクティブ ラーニング
- **60-70 (中)**: 継続的な関心、一般知識
- **40-50 (低)**: 知っておくと便利な補足
- **0-20 (アーカイブ)**: 参照のみ、レビューはほとんどありません

**優先スケジュール:**
- 毎日のレビューで 80 以上の優先順位に焦点を当てる
- 数日ごとに 60 ～ 70 をレビューします
- 毎週 40 ～ 50 件のレビューを行う
- 毎月またはオンデマンドで 0 ～ 20 件をレビューします

### プレビュー間隔の使用

**プレビュー間隔** 機能は、4 つの評価すべてについて各カードが次にいつ表示されるかを正確に示します。

**使用方法:**
1. カードを読み取ります
2. 評価ボタンの下にあるプレビュー間隔を確認します。
3. 以下に基づいて評価を選択します。
   - 現在の思い出
   - どれくらい早くもう一度見たいですか
   - あなたのスケジュール (例: 試験が近づいています)

**戦略の例:**
- 2 週間後の試験: 重要なカードを「簡単」と評価すると、すぐにもう一度表示されます
- 忙しい日: レビューの間隔を空けるために「良い」または「簡単」と評価します
- マスターしたい: 「難しい」と評価して、より頻繁に復習してください

### 圧倒される状況に対処する

**期限切れのカードが多すぎますか?**
1. レビュー制限を設定します (設定 → レビュー → 1 日あたりの最大数)
2. 優先度の高い項目に焦点を当てる
3. 優先度の低いカテゴリーを一時的に停止する
4. 望ましい保持力をわずかに下げることを検討してください

**コンテンツが多すぎて処理できませんか?**
1. ドキュメントを段階的にインポートする
2. 重要なポイントのみを抽出します（すべてではありません）
3. カードを選択して作成する
4. カテゴリを使用して整理する

**燃え尽き症候群?**
1. 休憩します (大丈夫です!)
2. 1 日あたりの制限を減らす
3. 重要でないカテゴリを一時停止する
4. 一度に 1 つのカテゴリに焦点を当てる

## トラブルシューティング

### 一般的な問題

#### カードがレビューに表示されない

**考えられる原因:**
- 今日レビューされたすべてのカード
- カードの停止
- アクティブな非表示カードをフィルタリングします

**解決策:**
1.「レビュー」タブで「期限」数を確認する
2. キューを確認 → カードが一時停止されていないことを確認します
3. フィルターをクリアする
4. レビュー日を確認します (将来予定されているカードの可能性があります)

#### 定着率が低い

**症状:** 多くのカードを忘れ、頻繁に「またか」と評価される

**解決策:**
1. **カードの品質を確認します**: カードは透明ですか?カードごとに事実は 1 つですか?
2. **望ましい保持率を下げる**: 90% ではなく 85% を試してください。
3. **より頻繁にレビューする**: 詰め込みではなく、毎日レビューします。
4. **コンテキストの追加**: 回答の詳細情報
5. **カードを簡素化**: 複雑なカードをより単純なカードに分割します

#### 同期の競合

**症状:** カードが重複し、同期後にデータが不一致になる

**解決策:**
1. 競合解決戦略を選択します ([設定] → [同期])
   - **ローカル勝利**: 変更を保存します
   - **リモート勝利**: サーバーの変更を受け入れる
   - **質問**: 各競合を手動で解決します
2. 定期的に同期して競合を最小限に抑える
3. 1 つのプライマリ デバイスを使用する

#### インポートの失敗

**症状:** ドキュメントのインポートが失敗するかエラーが発生する

**解決策:**
1. **ファイル形式を確認**: サポートされている形式 (PDF、EPUB など) を確認します。
2. **ファイル サイズを確認**: 非常に大きなファイルはタイムアウトになる可能性があります
3. **URL を確認**: 一部のサイトは自動アクセスをブロックします
4. **インターネットを確認**: URL インポートには接続が必要です
5. **代替案を試す**: Web コンテンツにはコピー＆ペーストを使用します

#### パフォーマンスの問題

**症状:** 読み込みの遅さ、ラグ、フリーズ

**解決策:**
1. **大規模なデータベース**: 古いカードをアーカイブします (設定 → データ → アーカイブ)
2. **画像が多い**: 画像の読み込みが遅くなる
3. **システム リソース**: 他のアプリを閉じます
4. **データベースの再構築**: 設定 → データ → 再構築 (最後の手段)

#### OCR が機能しない

**症状:** OCR が失敗するか、悪い結果が得られる

**解決策:**
1. **API キーを確認**: 有効でクレジットがあります (クラウド プロバイダー)
2. **画質を確認**: 鮮明な高解像度の画像が最適です。
3. **言語を確認**: 正しい言語が選択されています
4. **代替プロバイダーを試す**: 特定のコンテンツではより適切に機能するプロバイダーもあります
5. **ローカル OCR**: インターネットに問題がある場合は Tesseract を使用してください

#### llama.cpp が応答しません

**症状:** 「LLM 呼び出しエラー」またはローカルホストへの接続が拒否されました:8080

**解決策:**
1. **サーバーが実行されているかどうかを確認します**: `curl http://localhost:8080/v1/models`
2. **サーバーを起動します**: 上記の [OCR セットアップ](#ocr-optical-character-recognition) を参照してください。
3. **コンテキスト サイズが小さすぎます**: `-c 16384` 以降で再起動してください
4. **使用中のポート**: 別のプロセスがポート 8080 を使用している可能性があります。 `lsof -i :8080` で確認してください
5. **メモリ不足**: より小さい量子化 (Q4_K_M の代わりに Q3_K_M) またはより小さいモデルを使用します。

#### オラマが起動しない

**症状:** GLM-OCR Ollama ランタイムが起動に失敗する

**解決策:**
1. **Ollama をインストール**: [設定] → [OCR] の [ダウンロード] ボタンを使用するか、ollama.com からインストールします。
2. **バイナリ パスの確認**: デフォルトの場所にない場合は、Ollama バイナリ パスを設定します。
3. **Linux 権限**: Ollama サービスをインストールまたは実行するには、「sudo」が必要な場合があります。

#### Windows: 「サイドバイサイド構成が正しくないため、アプリケーションを起動できませんでした」

**症状:** Windows では、`plethora-tauri.exe` (または `pdf-reflow-diag.exe`) がウィンドウを開きません。代わりに、アプリケーションのサイドバイサイド構成が正しくないことを示し、「sxstrace.exe」を推奨するダイアログが表示されます。 **アプリケーション コードが実行される前**にプロセスが停止されるため、Plethora 自体のログには何も書き込まれません。

**確認:** イベント ビューアー → Windows ログ → アプリケーションを開き、次のようなメッセージが表示されたイベント ID 62 の「SideBySide」を探します。

「」
「...\plethora-tauri.exe」のアクティベーション コンテキストの生成に失敗しました。
マニフェストまたはポリシー ファイル「...\plethora-tauri.exe」の 1 行目にエラーがあります。
必須属性「packageName」が要素「msix」にありません。
「」

```パワーシェル
Get-WinEvent -LogName Application -MaxEvents 300 |
  Where-Object { $_.ProviderName -eq 'SideBySide' } |
  Select-Object -最初の 3 回作成、ID、メッセージ |フォーマットリスト
「」

**原因:** 実行可能ファイルの**埋め込みアプリケーション マニフェスト**がマニフェスト スキーマに準拠していないため、Windows の Side-by-Side アクティベーション コンテキスト ジェネレータは 1 行目でマニフェスト全体を拒否し、プロセスの作成を中止します。これは、インストールしたビルドのパッケージングの欠陥であり、PC の問題ではありません。この問題は、Plethora 3.3.1 以降の Windows インストーラーで修正されています。

**解決策:**
1. **現在の Plethora for Windows をインストールします**: 最新のインストーラーをダウンロードし、既存のコピーを上書きインストールします。壊れた 3.3.0 インストールでは、アプリはまったく起動できないため、自動的に更新できません。ダウンロードして再インストールする手順が必要ですが、ライブラリと設定は保持されます。
2. **インストールした内容を確認します** (オプション、Windows SDK コマンド ライン ツールが必要): マニフェストを抽出し、`<msix>` 要素を確認します。
   「」
   mt.exe -inputresource:"C:\Path\To\plethora-tauri.exe";#1 -out:%TEMP%\plethora.manifest
   「」
   正常なマニフェストには、`packageName`、`publisher`、および `applicationId` 属性を持つ単一の空の `<msix ... />` 要素が含まれています。
3. **Microsoft Visual C++ 再頒布可能パッケージの再インストール、`sfc /scannow` の実行、または DLL の再登録は行わないでください**。この障害は DLL が読み込まれる前に発生し、マニフェストの唯一の依存関係は Windows の一部である Microsoft Common Controls アセンブリです。これらの手順では結果が変わることはなく、エラー テキストはそれらの手順を示していません。

**注:**
- パッケージ ID (Windows AI 機能) は、インストーラーに同梱されている ID パッケージを登録できる場合にのみ使用可能になります。そのためには、マシンがすでに信頼している証明書によって署名されている必要があります。登録できない場合、Plethora は通常どおり実行され、ID に依存する Windows AI 機能のみがオフのままになります。その理由は、[設定] → [オンデバイス AI] で確認できます。
- Windows 10 2004 以降では、同じマニフェスト要素がその ID を付与します。古いシステムでは、アプリケーションはそれなしで実行されます。

## 用語集

**抽出**: ドキュメントから抽出されたコンテンツの一部、潜在的なカード素材

**学習項目**: 学習する任意の項目 (フラッシュカード、クイズ、Q&A など)

**キュー**: レビューが予定されているすべてのアイテム (優先度別に整理)

**レビュー セッション**: カードを積極的に思い出して評価する期間

**FSRS**: フリースペース反復スケジューラ。 FSRS-7 は、デュアル トレース メモリ モデル (低速および高速安定性トレース) を備えた現在の製品バージョンです。

**安定性 (高速)**: FSRS-7 のデュアル トレース モデルの高速トレース。安定性と検索性を両立

**間隔**: レビュー間の時間 (例: 7 日)

**安定性**: メモリの持続時間 (FSRS メトリクス)

**難易度**: アイテムがあなたにとってどの程度難しいかを 1 ～ 10 のスケールで示します (FSRS メトリック)

**検索可能性**: 現在の再現確率、0 ～ 100% (FSRS メトリック)

**望ましい定着率**: 目標定着率 (通常 90%)

**プレビュー間隔**: 各評価オプションの次回レビュー日を表示する機能

**Cloze**: 穴埋めカードのタイプ

**一時停止**: レビューからアイテムを一時的に非表示にします

**カテゴリ**: 組織の対象領域

**タグ**: クロスカテゴリー組織用のカスタムラベル

**優先度**: ユーザーが設定した重要度 (0 ～ 100)

## よくある質問

**Q: Plethora にニュースレターを追加するにはどうすればよいですか?**
A: ニュースレターは 2 つの方法で追加できます。
1. **ニュースレター ディレクトリ**: RSS → ニュースレター アイコン (📬) → 厳選されたニュースレターを参照して購読する
2. **ダイレクト URL**: ニュースレターの URL (Substack、Beehiiv など) → RSS → フィードの追加 → URL を貼り付けます。 Plethora は RSS フィードを自動検出します。

**Q: NotebookLM のビデオ、オーディオ、インフォグラフィック、またはスライドデッキが表示されないのはなぜですか?**
A: メディア アーティファクトをプレビューするには、そのファイルを生成して準備する必要があります。生成が完了するのを待ってから、アーティファクトを再度開きます。ビデオ/オーディオおよびインフォグラフィックスは代替メディア パスを通じて自動的に再試行され、スライド デッキは読み込まれない場合に「代替ビューアで開く」オプションを提供します。それでも失敗する場合は、「設定」→「統合」で NotebookLM に再接続し、アーティファクトを再生成します。

**Q: どのニュースレター プラットフォームがサポートされていますか?**
A: Plethora は、Substack、Beehiiv、Ghost ブログ、Buttondown、ConvertKit、Revue、Medium、WordPress サイトからの RSS フィードをサポートしています。ほとんどのニュースレターは RSS フィードを公開しています。ニュースレターの Web サイトで RSS リンクを確認するか、URL に「/feed」を追加してみてください。

**Q: 1 日に何枚のカードを確認する必要がありますか?**
A: 1 日あたり 20 ～ 50 個から始めてください。スケジュールや目標に基づいて調整してください。一貫性は量よりも重要です。

**Q: 1 日に何枚のカードを作成できますか?**
A: いくつでも構いませんが、量よりも質を重視してください。 50 枚の粗末なカードよりも、10 ～ 20 枚のよくできたカードの方が優れています。

**Q: どのくらいの定着率を目標にすべきですか?**
A: 推奨されるデフォルトは 90% です。レビューが多すぎる場合は 85% に調整し、重要な内容の場合は 95% に調整します。

**Q: 言語に Plethora を使用できますか?**
A: もちろんです！完全なワークフロー - プロファイル、辞書のピーク、AI 講師、シャドーイング/ディクテーション/発音/ライティングの練習、メディアに合わせた再生、および学習計画のギャップに関する推奨事項については、[言語学習](# language-learning) セクションを参照してください。また、語彙、文法、文章カードにも最適です。文法パターンにはクローゼ カードを使用してください。

**Q: 数式はどのように処理すればよいですか?**
A: カードでは LaTeX 構文を使用してください。 OCR の場合、数学コンテンツで最良の結果を得るには、Mathpix プロバイダーを使用してください。

**Q: Anki と同期できますか?**
A：はい！ [設定] → [統合] → [Anki] で AnkiConnect を双方向同期用に設定します。

**Q: 一時停止と削除の違いは何ですか?**
A: 一時停止すると、カードが一時的に非表示になります (一時停止を解除することもできます)。削除すると完全に削除されます (バックアップから復元できます)。

**Q: どれくらいの頻度でレビューする必要がありますか?**
A: 毎日が理想的です。日数を逃した場合でも、カードは蓄積されますが、「失われる」ことはありません。可能なときに取り戻してください。

**Q: Plethora を複数のデバイスで使用できますか?**
A: まだ直接ではありませんが、Dropbox/Google Drive 経由でデータを同期することも、ブラウザ拡張機能を使用することもできます。

**Q: 私のデータは非公開ですか?**
A：はい！すべてのデータはローカルに保存されます。クラウド同期は暗号化されています。構成された AI プロバイダー以外のサーバーにはデータは送信されません。

**Q: カードをエクスポートするにはどうすればよいですか?**
A: 設定 → バックアップ → エクスポート、または Anki 同期を使用して .apkg 形式にエクスポートします。
