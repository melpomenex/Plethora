## Provider and privacy audit

- `src/lib/ai/providers/index.ts` orders Android Nano, Apple Foundation/Core AI, Windows system, optional Foundry, local decision engine and configured `CloudProvider`; `tasks/router.ts` resolves capability snapshots and reasoning fallback. Do not add a parallel router.
- `provider.ts:72` resolves native readiness; `provider.ts:155` provides explicit fallback consent; `runAiAction` uses `ensureCloudAiDisclosure`. Direct `runTask` callers must not assume `runAiAction` ran. `CloudProvider.generateStream` delegates to the configured LLM API; verify destination authorization before sending any content, including retrieval queries that may use cloud embeddings.
- `CloudProvider.kind === "cloud"` includes Ollama and local endpoints. `providerAllowsKeylessAccess` and existing privacy/disclosure helpers matter; kind alone cannot establish privacy or billing. A remote endpoint must not be assumed local simply because it needs no key. `aiBillingConsent`, `paidEmbeddingsConsentFlag` and backend paid-embedding gates are reusable, not proof of universal content-disclosure coverage.
- Android: `src-tauri/plugins/plethora-android-genai/android/src/main/java/com/plethora/androidgenai/` contains `AndroidGenAiPlugin.kt`, `GenAiSchemas.kt`, `EmbeddingSupport.kt`, `LiteRtEmbeddingSession.kt`. Prompt/status/download/cancel, OCR and embedding paths exist, subject to actual capability/model availability.
- Apple: `src/lib/ai/apple/`, `providers/appleFoundationProvider.ts`, `appleCoreAiProvider.ts`, and `src-tauri/plugins/plethora-apple-intelligence/{ios,macos}/Sources/` provide native paths. iOS installs an embedding closure in the shared Rust backend. macOS has a Foundation bridge; this is not proof that it uses the identical iOS embedding installation. Detect each capability independently.
- Windows: `src/lib/ai/windows/`, `foundryLocal/`, native plugin `src-tauri/plugins/plethora-windows-intelligence/src/windows/mod.rs:40` and `winrt/native_bridge.rs` gate actual availability. Existing native-ai-routing spec requires OS/API/hardware/package/LAF-aware behavior. No universal Phi Silica availability claim is justified.
- Linux: configured Ollama/local endpoints can serve generation/embeddings; missing native embedding backend degrades to lexical retrieval. External configured providers remain available with explicit disclosure and cost authorization where applicable.

Additional verified seams for implementation/release tests:

- `src/types/cardSourceReference.ts` and `utils/cardSourceAnchor.ts` already serialize a bounded source excerpt and existing document-jump locator onto `learning_items.source_reference`; both single and batch create accept it. `acceptLearnThis.ts` does not currently populate it. Reuse this source anchor at creation, with `extracts.selection_context` authoritative for extract-linked cards, rather than inventing a competing provenance envelope. Keep AI generation metadata in existing AI provenance records.
- `commands/learning_item.rs:331` intentionally skips semantic duplicates in batch creation and performs daily-note work after the database batch. The agent needs scoped duplicate enforcement/idempotency and reconciliation for errors after commit; changing occlusion's batch policy globally would be a regression.
- `utils/llmProviderUtils.ts:24` treats all Ollama providers as keyless regardless of URL. Keyless/free is not local: remote Ollama and LAN `.local` hosts can process private text off-device. F0 must classify actual destinations separately from authentication/billing.
- `ai_learning/embeddings_backend.rs:117` / `:250` names the generic installed on-device backend `embeddinggemma-2-270m`, while iOS installs the NaturalLanguage closure (`NaturalLanguageBridge.swift:44`). Test model identity/version/dimension fidelity on iOS; bridge existence does not prove correctly labeled vectors. This is a release risk, not a claim that a device test failed.
- The concept daily-cap query filters `created_by='ai'` (`concept_repository.rs:294`), while acceptance changes that field to user. Test that endorsements cannot release the original AI generation quota; immutable origin is relevant to both provenance and caps.

## Reader evidence and reuse boundary

`DocumentViewerWrapper` publishes Assistant context; `DocumentViewer` selects reader modes. `selectionInteraction/adapters.ts` supports top documents and registered content iframes; `geometry.ts` handles coordinate transforms; `selectionActionRegistry.ts` resolves actions. `api/ai-learning.ts:66` carries `ChunkLocation` with PDF page, offsets, optional CFI and media timestamps; some locators are extension points rather than guaranteed populated fields.

PDF fixed layout uses virtualized page text layers and page coordinates. EPUB uses rendition-owned spine iframe documents and CFIs (`EPUBViewer.tsx:2355`). HTML has frame/content bridges, Markdown a rendered host, RSS `src/components/media/RSSReader.tsx` has both article HTML and full-content surfaces. Scoring must attach to mounted content roots; it cannot use a single top-level paragraph query or treat a page number as a paragraph anchor. Existing recall DOM sampling is a reuse pattern for eligibility, not a valid positioning implementation.
