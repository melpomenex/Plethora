## Cross-feature coverage notes

- **#1/#2/#5 shared TTS state model:** all covered by **Proposal A** — `tts-playback-state-model` defines the canonical-vs-derived state contract; `tts-position-persistence` (#2) and `tts-pause-resume-correctness` (#5) depend on it; the cross-feature sequence (start 37 → highlight → follow → 51 → pause → no jump → resume → close → reopen → resume from correct location) is encoded in A's specs and `tasks.md` §5.5.
- **#3/#4/#9/#15/#18 shared settings-UX principles:** all covered by **Proposal B**, which references the common `SettingsSection`/`SettingsRow`/`useToast()`/range-control patterns.
- **#14/#19 share billing/settings concerns but are distinct subsystems:** #14 (billing guards) is **Proposal F**; #19 (HF model manager) is **Proposal H**; both reuse the established settings persistence and confirmation patterns.
- **Persistence:** all new persistent settings (TTS resume position, sidebar width, model registry, paid-consent flags, model config) go through the established mechanisms — zustand `settingsStore` (`plethora-settings`) for UI settings, `ttsListeningPosition.ts` IndexedDB for TTS position, SQLite/established config for the model registry — no scattered one-off `localStorage` keys.
