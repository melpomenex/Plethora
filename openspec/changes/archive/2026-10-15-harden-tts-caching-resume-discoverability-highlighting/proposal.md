# Change: Harden TTS Caching, Resume Position, Desktop Discoverability, and Spoken-Word Highlighting

## Why

Plethora's document-reader TTS is functionally rich but has four hardening gaps that cost users money, time, and trust. Audited against the current implementation (2026-08-19):

**1. Cache is best-effort, not durable — users can pay twice for the same audio.** `src/utils/ttsCache.ts` (IndexedDB `plethora-tts-cache` v1, 500 MB LRU, `makeCacheKey(provider,model,voice,speed,format,digestText128(text))`) and `src/api/tts.ts:generateSpeech` correctly check the persistent cache before synthesizing and evict LRU on overflow. The architecture is sound and must be preserved. Two gaps remain: (a) writes are `void cacheAudioResult(...)` fire-and-forget — generation is considered "complete" before `setCachedAudio` commits, so closing the app between synthesis success and IndexedDB commit causes a paid re-synthesis on next open; (b) the cache key omits synthesis-affecting dimensions (`instructions`, preset/prompt/temperature, pronunciation dictionary hash, `language`, cloned-voice `speakerEmbeddingUrl`, `cloneModelId`, `baseUrl` for openai-compatible) — same-text/different-style reuses the wrong clip; and (c) concurrent cache misses for the same key race to two provider calls (prefetch × manual play × remount) with no in-flight deduplication. The in-memory buffer in `ReaderTTSControls.tsx` (`BUFFER_TARGET_SEC=60`, `MAX_CONCURRENT_GEN=3`, `EVICT_BEHIND_COUNT=3`) is correctly transient and must stay explicitly separate from the persistent cache.

**2. No dedicated TTS listening checkpoint — reopening drops the user at the wrong place.** `ReaderTTSControls` initializes from `startPosition {pageNumber, scrollPercent}` via the anchored `ReaderSpeechIndex` priority chain (`explicit → viewport → authoritative position → saved position → start`, `src/utils/readerSpeechIndex.ts:634`), which is correct for "where am I looking now" but not for "where did I stop listening." No TTS-specific checkpoint is persisted. Closing mid-chapter (e.g., sentence 37:42 into the document) and reopening falls back to the visible page top. The only durable position systems are `ViewState` (localStorage `document-view-state:v2:…`, debounced 350 ms, `src/lib/readerPosition.ts`) and `DocumentPosition` (`page|cfi|scroll|time`, SQLite via `src/api/position.ts`) — both represent *visual* reading progress. Their scroll-percent granularity and profile-namespace drift make them unsuitable as a listening anchor, and chunk-index-only persistence would break when `CHUNK_MAX` or segmentation changes.

**3. Reader hides the Listen affordance when TTS is disabled — users never discover the feature.** `ReaderTTSControls:163` does `if (!ttsEnabled) return null` — no bar, no button. The enable toggle lives only in **Settings → Text to Speech** (`TTSSettings.tsx`). A user opening a supported document (PDF/EPUB/Markdown/HTML article) with `tts.enabled=false` (the default, `src/utils/ttsSettings.ts:341`) sees no speaker control and no path to enable TTS except prior knowledge of the settings location. `tts.enabled` currently means "hide the feature entirely" when it should mean "not yet configured/usable."

**4. Highlighting defaults to off for existing installs — the flagship karaoke feature looks broken.** Prior spec `improve-pocket-tts` required default-off. Code now defines `highlightSpokenWord: true` / `followSpokenWord: true` in `createDefaultTTSSettings()` (v4, `src/utils/ttsSettings.ts:152-155,348-350`) with `migrateTTSSettings` v3→v4 filling the new fields and `DocumentViewer:613` reading `settings?.tts?.highlightSpokenWord ?? true` — so *new* installs are default-on, but `useState(false)` is gone. The gap is migration semantics and hardening of the timing/mapping layers: cloud audio still synthesizes timings via `synthesizeWordTimings(text,0,durationSec)` (`src/utils/wordTimings.ts`, weighted `length+1`, 60 ms floor) when measured timestamps are absent, while `WordHighlightLayer`/`WordHighlighter` now correctly support anchored `highlightAnchoredWord(chunk,wordIndex,approximate)` with section-keyed EPUB routing and `foldForMatch` matching. Work remains to make measured provider timings actually flow through cache, use them where available (elevenlabs/fal/openai/elevenlabs/openai-compatible/plethora), wire `SpeechSynthesisUtterance.onboundary` charIndex→word mapping, and keep approximate interpolation strictly as fallback.

Prior OpenSpec context: `improve-reader-tts` (exact-start anchoring, unified timing model, default-on highlighting via v4, follow behavior — all tasks `[x]`) superseded `improve-pocket-tts` (archived). `implement-plethora-premium-neural-tts-and-audiobook-generation` (premium hosted voices, `tts_generate` jobs, 500 MB cache, karaoke) and `add-audio-editions-and-hands-free-study-mode` (unified audio editions + hands-free) are complementary pipelines and stay untouched; this change reuses their anchor/timing vocabulary without coupling to their job/session infrastructure.

## What Changes

### 1. Harden persistent TTS audio cache (preserve architecture, strengthen guarantees)

- **Cache key completion.** Extend `makeCacheKey` (or introduce `makeCacheKeyV2` with alias) to include every synthesis-affecting dimension: `provider`, `model`, canonical `voiceId` (or `voice` string), `speed` (normalized string), `responseFormat`, `language` when non-Auto, `instructions` digest (only when non-empty and adapter `supportsInstructions`), `presetId` + canonicalized preset prompt/temperature/topP/topK/repetitionPenalty digest (when `supportsInstructions` or non-default preset), stable hash of `pronunciationDictionary` when non-empty, `speakerEmbeddingUrl` / `cloneModelId` for cloned voices, and `baseUrl` for `openai-compatible`. Values that do not affect output (e.g., `requestMode`, `proxyUrl`, `favorites`) MUST NOT enter the key. Review each `TTSAdapterCapabilities` flag to decide inclusion; document the decision matrix in `design.md`.
- **Durable write becomes the completion gate.** For cloud/paid providers (`fal`, `elevenlabs`, `openai`, `openai-compatible`, `openrouter`, `plethora`, `groq` when metered), generation is not "complete" until `setCachedAudio` has committed for the returned `audioData`/`ArrayBuffer`. Implement an `await` path (with timeout and retry) and a **durable-commit semantics** sequence: `getCachedAudio` → miss → `adapter.synthesize` → `setCachedAudio` (await) → expose/play → update metadata. If low-latency start-of-playback is desired, playback may begin from the in-memory blob *while* the commit is pending, but the commit MUST be awaited before the segment is considered cached — and on commit failure the segment MUST be retried or re-queued, never reported as cached. System/android/pocket (`auth.mode==='none'` or `kind==='local'`) remain best-effort/optional caching.
- **Persist measured word timings alongside audio.** Extend `TTSCacheEntry` to store `wordTimings?: WordTiming[]` (measured only) and `cacheHitSource` metadata; on cache hit, return timings so `resolveChunkTimings` can use measured data without re-synthesis.
- **In-flight deduplication.** On cache miss, `generateSpeech` (or a new `ttsGenerationDeduper` keyed by `cacheKey`) coalesces concurrent identical requests into one `adapter.synthesize` promise; additional callers await the same promise and share the result (and the single cache write).
- **Lifecycle hardening.** Keep default cap 500 MB, LRU by `lastAccessed`, bounded total. Harden `ensureCacheSize` (currently collects cursors then promise-chains deletes — serialize correctly, handle `QuotaExceededError`/corrupt entries by deleting the corrupt key and retrying). Keep IndexedDB v1 store names; if key schema changes, bump `DB_VERSION` with an upgrade handler that either aliases old keys or lazily invalidates them — never bulk-invalidates hundreds of MB without necessity. Do not clear persistent entries on in-memory buffer eviction.
- **Cache management UI.** Add **Downloaded speech** section in **Settings → Text to Speech**: cached size / max / entry count (from `getCacheSize`), controls for max size (250 MB / 500 MB / 1 GB / 2 GB / Unlimited→`Number.MAX_SAFE_INTEGER` capped), and **Clear cached speech** (with confirmation). Copy: "Cached speech lets Plethora replay previously generated audio without sending the same text to your TTS provider again."
- **Hit-visibility diagnostics (dev only).** Log/attach `cacheSource: 'memory'|'persistent'|'synthesized'|'system'|'android-native'` and `cacheKey` identity at debug level; not in normal UI.

### 2. Persist exact TTS listening position per document

- **New per-document checkpoint, distinct from visual position.** Introduce a lightweight durable checkpoint (not the audio blob) — e.g., `tts_listening_position` table in SQLite / IndexedDB mirror for browser mode — keyed by `documentId` (+ `profileId` namespace, mirroring `getPreferredViewStateKey`). Shape: `{documentId, profileId, updatedAt, textFingerprint (hash of normalized doc text), speechSectionFingerprint, provider, model, voiceId, chunkTextHash, stableAnchor: SourceAnchor, chunkIndex, wordIndex, intraChunkMs, normalizedCharOffset, cfi?, pageNumber?, scrollPercentHint, ttsSettingsFingerprint}`. Canonical location is the stable `SourceAnchor` (CFI / `pdf-word` `p{N}:w{M}` / `text` `surface+startOffset` / `page`) plus `chunkTextHash` + `normalizedCharOffset` for recovery when chunking changes.
- **Write strategy (throttled, complete).** Throttle periodic writes to ~3–5 s during playback + immediate flush on `chunkChange`, `pause`, `stop`, `seek`, `skip`, `document close`, `tab close`/`visibilitychange`, `beforeunload`, app background. Reads on document open attempt `locate(stableAnchor)` against the current `ReaderSpeechIndex`; if stale, try `chunkTextHash`/char-offset recovery, then closest document position, then visual position.
- **Resume UX.** On open with a meaningful checkpoint (heuristic: >30 s or >2% of document, not at start), surface a lightweight non-blocking resume affordance — e.g., inline banner in/above the TTS bar: "Resume listening from 37:42?" with **Resume**, **Start from here** (current viewport), **Start over**. Do not modal-block reading. If ignored, checkpoint stays and Play's existing 5-level priority chain gains a new level for TTS checkpoint (see design).
- **Separation + synchronization rules.** Listening position and visual position remain distinct. When `followSpokenWord` is active, TTS-driven `onChunkChange` may advance `DocumentPosition`/`ViewState` (coarse), but manual reading position writes MUST NOT overwrite the listening checkpoint, and listening progress MUST NOT force visual progress when follow is off.

### 3. Make TTS discoverable from the desktop reader

- **Persistent Listen affordance.** Every supported document (PDF/EPUB/Markdown/HTML article) shows a visible **Listen** (speaker) button in the reader chrome even when `tts.enabled===false` or no provider is configured. The button no longer disappears — `ReaderTTSControls` no longer `return null` on `!ttsEnabled` for the affordance tier; instead it renders a discovery tier (compact button) that opens a lightweight setup sheet.
- **Lightweight setup sheet (not full settings).** Triggered from the Listen button when unconfigured: dynamic provider list from `listAdapters()` filtered by platform (`pocket` desktop-only, `android` mobile-only), with **Use System Voice** as the zero-config first option when `systemTtsAvailable` (device speech engine), cloud choices (OpenRouter/Groq/Fal/…) annotated "needs API key", and **Configure more…** linking to **Settings → Text to Speech** (`tts.enabled` + provider config stay there). No credential collection in the sheet beyond optional quick System selection; cloud setup still goes to settings.
- **Enabled semantics redefined.** `tts.enabled` becomes "TTS is configured and usable" (not "hide the feature"). `validateTTSConfiguration` valid ⇒ discoverable bar is interactive; invalid ⇒ sheet guides configuration. Existing saved `tts.enabled=false` users see the Listen button on next open and are offered System voice with one tap.
- **Layout.** Place the affordance in the existing reader top chrome alongside Queue controls (not as an absolute `z-40` floating bubble over content); keep `ReaderTTSControls`' playback bar placement compatible with Queue/minimap/selection/rating chrome on desktop tabs and Queue surfaces.

### 4. Make spoken-word highlighting reliable and default-on (harden improve-reader-tts)

- **Default-on contract.** `highlightSpokenWord` stays default `true` for new installs; for existing installs whose `tts` predates v4 (schemaVersion < 4 and no `highlightSpokenWord` field), migrate to `true` (not false) — the old default-off requirement is explicitly superseded. Preference persists via `settingsStore.updateSettings({tts:{...highlightSpokenWord}})` and survives restarts.
- **Timing capability ladder (preserve, harden, persist).** Prefer measured provider `wordTimings` (elevenlabs `/with-timestamps`, openai-compatible Azure boundaries, fal timing shapes, plethora hosted timestamps) when `supportsWordTimings` and payload present; else System `SpeechSynthesisUtterance.onboundary charIndex → wordIndex` via `normStart/normEnd` binary search; else native Android `tts://word-position onRangeStart` for fallback engine; else `synthesizeWordTimings(text,0,durationSec)` approximate, rendered softer and never persisted as measured. Cache persisted entries now include measured timings so replay uses them.
- **DOM mapping hardening.** For PDF fixed-layout via pdf.js text-layer spans / `[data-w="{wordId}"]` reflow spans, for EPUB via `sectionContainers Map<string,HTMLElement>` + `sectionKey` routing, for Markdown/HTML/article via rendered DOM flattened-text offsets — resolve via `WordHighlighter.highlightAnchoredWord` with chamber-owned section container; validate via `foldForMatch` check before applying. Never highlight a duplicate occurrence merely because the word exists elsewhere; on failure fall back `chunk-level` then `no highlight`.
- **Behavioral coverage.** Transient highlight cleared on `stop`/`chapter switch`/`document switch`/`unmount`; `pause` freezes; `resume`/`seek`/`skip`/`retarget` re-anchors; auto-follow keeps the highlighted word visible when `followSpokenWord` on (existing `useSpokenWordFollow` semantics: comfort offset, debounced, arrival-based user-scroll detection, Re-center resume).

**Prefetch + cost-safety preserved.** Prefetch checks persistent cache first, participates in deduplication, never fires multiple paid calls for the same key, remains demand-driven bounded by ~60 s ahead and bounded concurrency. Large audio blobs stay in IndexedDB — never in Zustand/localStorage. Diagnostics and tests verify provider adapter invocation counts under cache hit.

## Capabilities

### New Capabilities
- `tts-persistent-cache`: Durable, bounded, key-complete TTS audio cache with in-flight deduplication and user-visible management.
- `tts-listening-position`: Per-document durable TTS checkpoint with stable-anchor recovery, persistence strategy, and resume UX.

### Modified Capabilities
- `tts-spoken-word-highlighting`: Supersede the `improve-pocket-tts` default-off requirement and the current `improve-reader-tts` delta — new default-on (including migration for existing users), timing persistence through cache, and hardened cross-surface anchoring remain within this capability. The prior spec's `highlightSpokenWord: true` default is retained; only the migration semantics for pre-v4 persisted settings change (now default-true even for previously-unset users).
- `tts-reader-discoverability`: Reader Listen affordance semantics — what `tts.enabled` means and when `ReaderTTSControls` may return null — supersedes the current "return null when disabled" behavior inside `ReaderTTSControls` and the `DocumentViewer` `canReadAloud` gate's TTS-enabled requirement.

## Impact

- **Components**: `src/components/common/ReaderTTSControls.tsx` (discoverable affordance tier, deduplicated prefetch, checkpoint writes, highlight wiring), `src/components/common/WordHighlightLayer.tsx` (no functional change, timing source preserved), `src/components/viewer/DocumentViewer.tsx` (Listen button chrome, setup sheet, `resolveViewportAnchor`/`resolvePositionAnchor`/`sectionContainers` wiring, resume banner, checkpoint persistence), `src/components/settings/TTSSettings.tsx` + `SettingsPage.tsx` (Downloaded speech section, highlight toggle clarification), reader viewers (PDF/EPUB/Markdown/HTML) for section-structured speech text already present.
- **API/utils**: `src/api/tts.ts` + `src/utils/ttsCache.ts` (key completion, durable commit gate, wordTimings persistence, deduper, IndexedDB versioning/migration, corruption handling), `src/utils/ttsSettings.ts` (no schema bump needed — v4 already has `highlightSpokenWord`/`followSpokenWord`; only migration default for pre-v4 unset users changes behavior), `src/utils/readerSpeechIndex.ts` (checkpoint anchor helpers reused), `src/utils/wordHighlighter.ts` / `src/utils/wordTimings.ts` (deduped timings path kept, highlight distinctness preserved), new `src/utils/ttsListeningPosition.ts` or `src/lib/ttsListeningPosition.ts` (checkpoint storage abstraction over SQLite + browser IndexedDB) and `src/stores/ttsStore` or `src/stores/settingsStore` extension if appropriate.
- **Persistence**: New durable store for listening checkpoints (Rust `src-tauri/src/commands/position.rs` or new `tts_position` commands + repository, or reuse `positions` table with `type: 'tts'` / new `tts_listening_positions` table) with `profileId` namespacing, content-fingerprint invalidation, and debounced writes; IndexedDB audio cache stays separate from Zustand settings.
- **Native**: No new native plugin changes required for this change's caching/resume/discoverability; Android `onRangeStart` word events from `improve-reader-tts` are reused unchanged.
- **i18n**: New keys for cache section, resume affordance, Listen/setup sheet.
- **Tests/perf**: New suites for cache durability/dedup/key completeness, checkpoint round-trips and staleness recovery per doc type, discoverability affordance, highlighting default-on/migration and timing ladder; new/updated benches for any newly-hot paths per `scripts/perf-baselines.json`.
- **Docs**: Update settings copy, diagnostics notes, and cache-migration notes.

## Risks

- Cache key expansion could orphan large legacy caches — handled via versioned migration that preserves/aliases still-valid keys; bulk invalidation avoided.
- Durable commit awaiting could regress perceived playback latency — mitigated by overlapping playback start with pending commit and by caching only after commit (not blocking first audible frame).
- Listening checkpoint may staleness-resolve to the wrong occurrence if text changed heavily — handled by context-anchored recovery with graceful fallback, never highlighting/starting at an unrelated duplicate.

## Non-Goals

- No rebuild of the provider registry, job framework, premium hosted billing/quotas, or audio-edition/hands-free pipelines (those changes stay authoritative; this change only hardens the reader TTS path that reuses their concepts).
- No full audiobook export or background download queue (existing download/migration handles offline audio).
- No change to chunking constants `CHUNK_TARGET`/`CHUNK_MAX` semantics beyond adding stable hash anchors.
- No iOS App Store work; Android word-event behavior unchanged except via cache timing reuse.
