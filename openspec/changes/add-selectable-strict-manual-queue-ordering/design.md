## Context

`ReviewSettings.tsx` persists `smartQueue.queueOrderingMode`. `daqeRankingClient.ts` invokes `rank_queue` and `rank_queue_with_decision` without mode. `QueueScrollPage.tsx` consumes queue order on the sequential path, then uses composition and combined-criterion sort on the Optimal path. The standalone variety guard is insufficient because its production consumer is absent.

## Decisions

1. Use `adaptive | strict_manual` in Settings, IPC and stored snapshots. Missing/unknown legacy input uses Adaptive after validated parsing. Keep the existing settings IDs and current DAQE/default paths. Add optional mode to queue-producing requests that have existing public callers. In `queue_daqe.rs` and `queue_daqe_decision.rs`, dispatch after selecting the canonical candidate pool. Skip fetching/applying decision terms for strict presentation. Build explanations and top-ten from the same final ordered rows. Rank before count/pagination and include mode, collection, eligibility and mutation generation in snapshot identity.
2. Derive an integer effective priority from the explicit persisted slider (including zero), then the existing inheritance/legacy display policy, then neutral 50. For legacy document ratings preserve existing buckets 10/30/50/70/90. `priority_explicitly_set` exists for document/card and nullable extract sliders encode presence. Inspect each video/external storage contract before proposing any additive flag. Never use adaptive `priority` or urgency as a strict fallback. Shared Rust and TS fixture vectors govern both implementations. Compare descending effective priority, then valid due instant ascending (missing/invalid last), then stable type and ID ascending. Parse timestamps before comparison to handle offsets.
3. Eligibility stays at each existing producer. Due-only honors its existing due cutoff and excludes later future dates, normal backlog/custom Browse may show eligible future items, and new material is included per the rotation owner. Suspended, archived, dismissed, out-of-collection and explicitly excluded items cannot enter. Treat saved snapshots as membership and explicit composition/type quotas as pool constraints. Rank each type before quotas and the mixed eligible set afterward. Preserve current anchor if still eligible, then traverse the new strict order. Hide or disable contradictory presentation controls while active (random/Neural/variety/goal/energy, adaptive sort overrides). Persist existing adaptive preferences for mode changes. Keep explicit non-queue library sorting available.
4. In strict mode use effective priority and the same tie-break for automatic capacity decisions. Explicit do-not-postpone pins are eligibility exclusions for the automatic operation. Existing protection threshold uses the effective priority. Protected rows can exceed capacity and remain visible in the preview. Postpone lowest-priority eligible overflow. Show counts and skipped rows. Re-check candidate revision, policy/mode and current membership before applying the existing transactional plan. Manual postpone remains available.
5. Use the current typed priority mutations for all input controls. On failure restore confirmed value and surface retry. Suppress stale fetch responses after writes and invalidate ranking only once per committed change. Native legacy callers default to existing Adaptive behavior.

## Risks and migration

Avoid recoding adaptive coefficients. The current canonical terms implement saturation and a single manual term. Verify legacy presentation separately and align explanations to actual returned terms. Preserve existing rows, missing flags and due values. No destructive backfill. If a type lacks explicit-zero representation, add nullable presence compatible with existing archives and restore, backed by old/new DB and IndexedDB fixtures.
