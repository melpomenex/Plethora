## Context

Some macOS users experience a blank window or freeze on startup where the main dashboard does not load. This is caused by tauri-plugin-window-state attempting to restore a corrupted, empty, or invalid window state file, or hit macOS-specific deadlocks during state restoration.
Additionally, the OPML import feature contains a regression where feed URLs with the `feed://` or `feed:` protocol are silently skipped, and mixed-case outline/body tags fail to parse correctly.

## Goals / Non-Goals

**Goals:**
- Implement auto-validation and deletion of corrupted/empty `.window-state.json` files on startup.
- Provide a `--clear-window-state` command line recovery argument.
- Add a macOS application menu item "Clear Window State" that triggers deletion and prompts for restart.
- Fix the OPML import regression by normalizing feed protocols (`feed://`, `feed:`) and enabling case-insensitive XML node parsing.

**Non-Goals:**
- Completely rewrite window creation logic.
- Support non-desktop window-state persistence.

## Decisions

### 1. Automatic Window State File Validation on Startup
- **Decision**: Inside the builder's `setup` hook in `src-tauri/src/lib.rs`, check if the `.window-state.json` file is empty or contains malformed JSON, and delete it if so.
- **Rationale**: Keeps startup robust against silent corruption of the state file. Checking inside the `setup` hook allows us to use `app.path().app_config_dir()` to accurately resolve the path across different OS configurations.

### 2. Command Line Argument for Manual State Clearance
- **Decision**: In `src-tauri/src/lib.rs`'s `run()` function, inspect `std::env::args()` for `--clear-window-state` or `--reset-window-state` and delete the state file if present.
- **Rationale**: If the application hangs or crashes before the `setup` hook or window rendering finishes, a CLI flag allows developers/advanced users to perform a clean start.

### 3. Native macOS App Menu Item
- **Decision**: Add a "Clear Window State" button under the native app submenu in `src-tauri/src/lib.rs`, and handle its click event by deleting the file and prompting the user with a dialog.
- **Rationale**: Since the native macOS menu bar is run by the native Appkit event loop rather than the WebView engine, it will remain responsive and usable even if the dashboard/WebView fails to load.

### 4. OPML Feed Protocol Normalization and Case-Insensitive Element Traversal
- **Decision**: In `src/api/rss.ts` inside `importOPML`:
  1. Normalize `feed://` to `https://` and `feed:` to empty/standard prefix before running the regex protocol check.
  2. Implement case-insensitive body/outline element traversal, filtering elements dynamically by checking `.tagName.toLowerCase() === "body"` / `"outline"`.
- **Rationale**: Aligns the frontend OPML parser with the Rust backend's URL normalization, and makes the XML parser robust against mixed-case OPML files generated by different feed reader applications.

## Risks / Trade-offs

- **Risk**: Deleting window-state resets window size.
  - *Mitigation*: Re-centers the window to the default safe dimensions specified in `tauri.conf.json`, which is the intended recovery state.
