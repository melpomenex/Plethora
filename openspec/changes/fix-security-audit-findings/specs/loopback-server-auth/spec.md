## ADDED Requirements

### Requirement: CORS never allows opaque or wildcard-local origins
The browser-sync server's CORS policy SHALL NOT accept `Origin: null` or wildcard port forms of localhost origins. The allowlist SHALL contain exact origins only: the app's own origin(s) and the shipped extension's exact extension-id origin.

#### Scenario: Sandboxed-iframe origin is refused
- **WHEN** a preflight arrives with `Origin: null` (e.g. from a sandboxed iframe on an attacker site)
- **THEN** no `Access-Control-Allow-Origin` header is returned and the preflight fails

#### Scenario: Extension origin still works
- **WHEN** the bundled extension makes preflighted requests from its exact `chrome-extension://<id>` origin
- **THEN** the CORS layer reflects that origin and requests succeed (e2e extension smoke)

### Requirement: Unauthenticated routes enforce Origin and Host
Every route exempt from API-key authentication SHALL run an Origin/Host enforcement middleware: requests carrying an `Origin` header must match the allowlist exactly; requests with no `Origin` (non-browser local clients) pass; the `Host` header must be the loopback host and configured port.

#### Scenario: Cross-site browser request with allowlisted-spoofed host fails
- **WHEN** a non-allowlisted origin sends a request to an unauthenticated route (with any Host)
- **THEN** the middleware rejects it before the handler runs

#### Scenario: Local non-browser client still passes
- **WHEN** a local script sends the same request with no `Origin` header
- **THEN** the request proceeds normally

### Requirement: Unauthenticated routes are rate-limited
Routes reachable without the API key SHALL apply a per-source token-bucket rate limit; excess requests receive `429` with `Retry-After`.

#### Scenario: Burst is throttled
- **WHEN** a single source exceeds the configured unauthenticated rate (e.g. 30 requests/minute)
- **THEN** subsequent requests receive `429` until the bucket refills

### Requirement: Automation key is CSPRNG-generated and constant-time compared
The automation API key SHALL be generated by the backend using an OS CSPRNG, SHALL NOT be generated or stored by the frontend, and SHALL be compared in constant time. The key SHALL rotate on app version upgrade with a one-time re-pairing notice for the extension.

#### Scenario: Key is unpredictable and never frontend-generated
- **WHEN** browser sync is enabled for the first time (or upgraded)
- **THEN** the backend generates the key with `OsRng` and the extension obtains it through the pairing flow

#### Scenario: Timing-safe comparison
- **WHEN** any automation request presents a candidate key
- **THEN** the server compares it with a constant-time equality check

### Requirement: Public endpoint exemptions are minimal
The only routes reachable without the API key SHALL be the extension-facing set (`POST /`, `POST /ai/process`, `GET /ai/status`, `POST /ai/image-occlusion`, `GET /api/theme`) and, at most, podcast search — all behind the Origin middleware and rate limit. Any other route requires the key and fails closed when no key is configured.

#### Scenario: Automation routes fail closed without a key
- **WHEN** automation routes are called while no automation key is configured
- **THEN** every request is denied
