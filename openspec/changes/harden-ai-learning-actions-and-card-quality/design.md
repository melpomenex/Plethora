## Current implementation decisions

1. Move the existing alias handling into the descriptor-validation path as an allowlist per field. Canonical `topic` accepts `query/search/concept/term/text` for `get_related_material`. Treat multiple equal trimmed strings as one, reject non-string or conflicting values even when the canonical key is set, and keep existing length and unknown-property checks. Use typed invalid-argument details that name expected fields without echoing unsafe text. Keep model-visible canonical schema and normal authorization/bounds. Apply the same pattern to `search_library` only for aliases declared in its descriptor.
2. Resolve once per submission with `resolveScopedSectionContext`. Carry immutable selected/pinned text or locator, parent document ID, optional extract ID, source revision, displayed scope and disclosed length through Assistant, Document QA, Learn This and Studio. Precedence is explicit mention/selected range, then pinned selection, then explicit document scope. When multiple scopes are explicitly selected, include them only within the validated source boundary. Empty heading bodies resolve by verified locator to the next peer/higher heading or content boundary. Ambiguous or stale locators fail with a scope-specific message. Preview truncation before send and retain included locator slices. Scope changes abort/supersede old runs. No library-wide expansion.
3. Represent runs by conversation ID and request ID with stream partial, tool-running, completed, cancelled, interrupted, timeout, refused, invalid/empty result and persistence-error states. A valid tool-only response shows tool/proposal activity. Zero meaningful content without successful tool output becomes an actionable terminal state. Preserve already committed tool receipts and any labelled partial text. Cancellation and older conversation/model streams cannot overwrite the current run. Persist run outcomes in the existing conversation history with backward-compatible reads. Offer Retry for the same scoped request, or an explicit model change through the existing route/disclosure UI. Safety blocks preserve work and stop automatic retries/fallback.
4. Use a shared validated draft contract wrapping `validateGeneratedCard` with candidate ID, kind, editable text/structured payload, source identity/revision, and structured violations. Parse supported structured outputs and documented small-model text formats, reject malformed or ambiguous payloads, keep unaligned answers reviewable with warnings, and require user acceptance. Q&A requires a nonempty question and supported answer, ordered-step requires actual ordered steps, cloze requires balanced numbered markers with nonempty answers. Never silently reclassify an ambiguous card. Revalidate on acceptance against fresh source rows. Extract cards derive parent document from the persisted extract, never from a model-supplied foreign key. Reuse candidate identities and repository uniqueness/receipts. Return saved/rejected/failed/unknown per candidate and reconcile uncertain acknowledgement by identity before retry. Keep failed drafts editable and stable across retries.
5. `ExtractScrollItem.tsx` calls `generate_progressive_summaries` on mount when enabled. `commands/ai.rs` uses default provider and writes the whole loaded extract after the call. Route generation through the configured task/provider boundary, use existing on-device/cloud authorization and keep automatic summarization local or explicitly consented for the exact route. Validate current extract revision before persisting only summary fields. Keep current content, tags and scheduling. Learn This uses its existing sheet/accept adapter with the same source and error contracts. Show Retry on recoverable failures and retain readable source when generation is unavailable.
