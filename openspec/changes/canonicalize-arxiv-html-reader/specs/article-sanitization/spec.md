## ADDED Requirements

### Requirement: Scholarly allowlist is centralized and narrow
The canonical sanitizer SHALL accept only the semantic tags and centralized Plethora-owned scholarly class tokens emitted by canonical normalization. It MUST remove arbitrary publisher classes and all unapproved class tokens even when they resemble a valid scholarly hook. The extractor, normalizer, sanitizer, and canonical reader SHALL consume one authoritative hook contract or a mechanically verified equivalent.

#### Scenario: Approved scholarly hooks survive
- **WHEN** normalized content contains approved abstract, equation, theorem, proof, table, bibliography, reference, and footnote hooks
- **THEN** those exact hooks survive final sanitization with their semantic descendants

#### Scenario: Publisher classes are stripped
- **WHEN** candidate HTML contains `ltx_*`, styling-framework, or attacker-supplied classes alongside safe text
- **THEN** safe semantic content remains and every unapproved class token is removed

### Requirement: Generated fragment identifiers remain safe and consistent
The sanitizer SHALL retain `id` only when generated by the canonicalizer and matching the restricted canonical identifier format. It SHALL retain same-document fragment links only when their targets use that format and survive sanitization. It MUST reject arbitrary source IDs, malformed fragments, and fragment values that attempt attribute, selector, or URL-scheme injection.

#### Scenario: Canonical citation target survives
- **WHEN** the canonicalizer emits a generated citation link and matching bibliography target
- **THEN** final HTML retains the matching safe `href="#…"` and `id` pair

#### Scenario: Arbitrary identifier is removed
- **WHEN** source content supplies an ID outside the generated namespace or a malformed fragment link
- **THEN** the unsafe identifier or link destination is removed without deleting safe visible text

#### Scenario: Missing target does not leave a trusted broken pair
- **WHEN** a fragment target is removed by sanitization
- **THEN** post-sanitization validation removes or neutralizes the corresponding canonical fragment relationship and reports a normalization warning

### Requirement: Accessible scholarly attributes are element scoped
The sanitizer SHALL retain only canonicalizer-generated accessibility attributes required for scholarly content, such as safe `aria-label` or `aria-labelledby` on their approved elements. MathML alternative text SHALL be converted or filtered according to this element-scoped contract. Arbitrary ARIA references, source `alttext`, and accessibility attributes on unrelated elements MUST NOT pass through merely because their names are allowed elsewhere.

#### Scenario: MathML accessible name survives
- **WHEN** the canonicalizer emits an approved accessible name for a MathML equation
- **THEN** the final MathML retains that name and exposes no unapproved LaTeXML-only attribute

#### Scenario: Untrusted ARIA reference is rejected
- **WHEN** source HTML supplies `aria-labelledby` pointing outside the generated safe identifier namespace
- **THEN** the sanitizer removes that attribute while retaining safe element content

### Requirement: Active and presentation content remains forbidden
Extending scholarly semantics MUST NOT admit source `style` elements, stylesheets, inline style attributes, scripts, event handlers, SVG, forms, iframes, objects, embeds, unsafe URL schemes, or source-controlled active content. Existing safe URL and image policies SHALL remain in force for canonical HTML.

#### Scenario: Mixed scholarly XSS payload is neutralized
- **WHEN** a scholarly fixture includes valid MathML, a figure, and citation markup mixed with scripts, event attributes, CSS, an iframe, and `javascript:` or unsafe data URLs
- **THEN** final HTML retains the safe scholarly structures
- **AND** removes every active node, presentation source, event handler, and unsafe URL

#### Scenario: No publisher CSS survives persistence
- **WHEN** an arXiv source includes linked stylesheets, style blocks, inline styles, and presentation attributes
- **THEN** none are present in the canonical HTML passed to `updateWebArticle`

### Requirement: Final sanitized DOM is the tested security boundary
Tests for scholarly normalization SHALL assert the output of `sanitizeArticleHtml`, not only the site-specific extractor candidate. The extraction version SHALL be bumped for the expanded canonical contract, and sanitizer regressions SHALL use deterministic local fixtures without network access.

#### Scenario: Full fixture passes final-DOM assertions
- **WHEN** the expanded local arXiv fixture runs through extraction, normalization, and sanitization
- **THEN** tests verify required semantics and reference pairs in the final persisted-shape DOM
- **AND** verify the absence of source presentation and active-content vectors
