## Goals / Non-Goals

**Goals:** explicit local gesture ownership; immediate finger tracking; one tactile recognition point; one global mobile conversation surface; no reader remount or position mutation; native dictation with honest capability/privacy boundaries; executable tests plus hardware evidence.

**Non-Goals:** modifications to edge recognition, Android native Back/predictive routing, Home areas or navigation history; hidden reader-wide listeners; rewriting `AssistantPanel`; adding animation dependencies; speech auto-send or automatic capture; v1 long-press activation; migrating all conversation stores or legacy speech jobs. All new API names below are proposed implementation contracts, not claims that these functions already exist.

## Decisions

### 1. A small central pill owns invocation

Create `MobileAssistantHost` and `MobileAssistantPill` under `src/components/assistant/`, mounted once in the mobile branch of `MobileLayoutWrapper`. Use a real button, sparkle glyph plus localized “Assistant”, tonal fill and full radius. The button's minimum hit area is 120 × 48 CSS pixels; width can grow for localization/text scaling. Center above the actual visible nav top with an 8px gap. Keep the complete hit area at least 32px inside both screen edges and outside system safe areas. A `ResizeObserver` on the nav element supplies its actual rectangle; do not assume its 56px minimum includes all device padding. The surrounding fixed positioning layer is pointer-transparent; only the button accepts input. No invisible full-width activation strip.

In ordinary views the pill stays available without bouncing, pulsing or timed hints. Hide it while another modal/sheet/menu or selection action surface owns interaction, the keyboard belongs to another control, a review answer/grade gesture is active, or fullscreen media owns the screen. Pause invocation while app hidden, a gesture/settle is being cancelled, or mobile presentation is leaving. If nav is intentionally absent outside fullscreen, place the pill 12px above the bottom safe inset, still outside Home territory. Expose a narrow host availability registration for reader controls/selection/review owners; use lifecycle cleanup and active pane/tab eligibility, not DOM polling or global touch interception.

For fullscreen reading, follow the reader's existing controls-visible lifecycle: pill appears with revealed controls and disappears with them. For DOM fullscreen whose subtree excludes the shell, and native fullscreen video, hide the pill; expose an Assistant action in the existing visible reader toolbar that first exits fullscreen then opens the same host. Do not move a body portal above native fullscreen or install another reveal gesture. Preserve reader position. Physical verification decides per-reader routing details, not whether Home can be intercepted.

Alternatives rejected: right-edge drag competes with Android Back; arbitrary upward drag competes with reading/refresh/selection; bottom-edge starts compete with Home; top-edge drag conflicts with OS shade and pull-to-refresh and is difficult to reach; left-edge competes with existing Back. A tap-only floating action lacks direct physical manipulation but remains the complete accessibility fallback. Long press to dictate is deferred because it competes with selection and introduces permission/cancellation complexity.

### 2. Separate recognition, tactile latch, and presentation state

Add a pure reducer/geometry helper and a small `useAssistantSheetGesture` hook. Sheet states are `closed` (pill only), `partial`, `expanded`; transient states are `contact`, `dragging`, `settling`, `cancelling`. An uncommitted reveal is a preview, not an open conversation: it must not focus, read context, invoke AI, or acquire the microphone.

Let `H` be the usable visible height after top/bottom safe insets, from existing visual-viewport metrics. Invocation threshold `T = clamp(0.12 × H, 64, 96)` CSS px; slop = 8px. Freeze geometry on pointerdown. Finger displacement `d = max(0, startY - currentY)` controls reveal: `r = min(partialHeight, d)` up to T, then `r = min(partialHeight, T + 0.35 × (d - T))`. This gives resistance after the recognition point without disconnecting the sheet from the finger. The pill translates with the reveal and tones its armed state; the sheet top emerges behind it. No layout movement of the document.

| Input/state | Ownership, visual state and outcome |
| --- | --- |
| Primary contact inside visible pill | Start one opaque gesture ID, record origin; subtle pressed tone, silent. Ignore secondary mouse buttons; do not cancel screen-reader synthesized click. |
| Movement below 8px | Remain contact; pointerup can produce normal click. |
| Upward movement with `d >= 8` and `d >= 1.25 × abs(dx)` | Own local drag, capture pointer on pill, reveal sheet; suppress compatibility click for this sequence. |
| Horizontal/downward intent after slop | Reject for the entire sequence. If ambiguous, wait only until max-axis travel reaches 16px, then reject unless upward ratio qualifies. A rejected movement is never a tap. |
| First crossing `d >= T` | Set `thresholdAnnounced` latch before dispatch, render armed state immediately and request one threshold cue. Haptic suppression does not unset latch. |
| Retreat/re-cross | Armed appearance follows current `d >= T`; latch remains true, no second request. |
| Pointerup with current `d >= T` | Open partial, settle from current transform; no opening/detent cue for this invocation. Crossing earlier does not authorize a release below T. No velocity bypass. |
| Pointerup below T | Spring to closed, no open, no cancellation cue, no synthesized tap. |
| Pointer cancel, capture lost, second contact, background, view change, geometry change, owner hidden | Invalidate sequence, return to prior stable detent (closed for invocation), release capture; never commit or navigate. |
| New contact during settling | Cancel running animation and start from its sampled transform if same eligible owner; cancel stale completion callbacks. Closing/Back cannot be undone by an old animation promise. |

Use Pointer Events and `touch-action: none` only on pill/handle, declared before contact. Acquire capture when directional ownership is earned; cancellation must work before and after capture. Mark owners `data-gesture-lock`; their button/dialog semantics already satisfy global gesture exclusions. Register no reader or iframe pointer/touch listeners. Pointer capture and `touch-action` behavior must be tested in shipped WebViews; platform cancellation is terminal ([MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)).

### 3. Two useful detents, handle-only dismissal, viewport-safe motion

Compute `expandedHeight = min(0.90 × H, H - 8px)` and `partialHeight = min(expandedHeight, max(0.45 × H, 320px))`. If expanded minus partial is less than 96px, or text scaling makes partial chrome/composer unusable, offer expanded only; never shrink text to preserve two stops. Expanded content includes header/handle, source chip, scopes, scrolling history, and pinned composer. Initial tap/drag targets partial or the sole expanded detent and never forces keyboard focus. “Collapsed” means closed to the pill, not a third answer-card system.

The sheet handle has a 48px-tall hit region and accessible Expand/Collapse actions. Only this region starts resize gestures; history, text inputs, selection and citations keep normal vertical scrolling, selection and taps (`overscroll-behavior: contain` on history). From partial: upward handle displacement of at least `min(80px, 0.15H)` expands, downward at least that distance closes; otherwise return to partial. From expanded: qualifying downward handle drag collapses to partial, or closes if partial is unavailable; nonqualifying release restores expanded. One gesture changes at most one detent, independent of fling velocity. Use continuous height/reveal geometry while dragging, with 0.2 resistance outside allowed bounds. Explicit Close, scrim tap and committed Back close directly from either detent; explicit Expand/Collapse buttons match the handle transitions.

Animate transforms and scrim opacity, using refs/motion values and at most one rAF write per frame. React state changes only for semantic transitions, content updates and viewport changes. Fix maximum panel geometry during drag; reveal by translation rather than animating document height. Adopt existing duration/easing tokens; implement a small critically damped settle (initial stiffness 320, damping 36, mass 1), stop within 0.5px/5px per second, cap at 320ms. These are initial tuning constants, not native physical units. No animation library required. Reduced motion/E-Ink preserves direct manipulation but uses immediate release settlement, without spring overshoot or pulse. Do not tie haptic delivery to animation timing promises.

Reuse scaffold `--app-viewport-height`, `--app-viewport-offset-top`, and safe inset variables; do not start another viewport listener. On composer focus/keyboard resize, expand within the visual viewport, keep composer visible, and avoid adding keyboard height a second time. Remember pre-keyboard detent and restore silently on keyboard dismissal when no handle/button changed it. Recompute on orientation/viewport change; cancel active drag before using new geometry. Distinguish ordinary pinch/viewport resize from keyboard focus rather than using height alone.

Use `dialogSurface`/dialog styling and focus-trap behavior from `useDialogFocus`, with exactly one overlay registration. Add a narrowly scoped optional priority argument to that hook for this host; its default stays 100 and existing dialog callers remain unchanged. Assistant registers global owner at priority 60: below context menus 80 and dialogs 100, above underlying view history. Portal at z-index 1040 (pill 1001), below existing adaptive dialogs 1050+; nested Assistant menus/dialogs retain their normal higher layers. Never wrap it in `MobileContextMenuSheet` at z-index 9999. If a foreground legacy selection sheet at 9999 exists, suspend the pill and close the global presentation before opening it. Reuse a scoped body/content scroll lock with restoration; do not overwrite another modal's lock.

Back behavior uses `dispatchApplicationBack` unchanged. Register a raw global overlay entry from the first visible preview; it cancels preview without falling through and without any Assistant haptic/session effect. A separately committed Back retains its existing Back-completion cue. Preview must not activate focus trapping or mount the conversation. At committed open, replace that entry with the single dialog-focus registration; retain it through exit settlement. On open Back the overlay callback stops dictation, cancels drags and closes once; its existing Back completion owns the single navigation cue. Do not emit an Assistant detent/dismissal cue too. Unregister when exit finishes; claimed overlay entries swallow repeated Back during exit. Native IME, fullscreen, OS pickers and predictive Back cancellation retain their existing higher ownership. Do not add a separate key listener, `plethora:system-back` listener, edge recognizer, Android callback, system gesture exclusion rectangle, or native protocol change.

### 4. A single, semantically precise haptic sequence

Add typed events to `feedback/events.ts`, map with the existing `interaction` helper in `policy.ts`, and emit synchronously via `emitInteractionFeedback` / `emitUserInteraction`, always `origin: "user"`. No new effects or native wire fields.

| Proposed event | Existing effect; cooldown; priority | Sole owner / identity | When |
| --- | --- | --- | --- |
| `assistant.invoke-armed` | `threshold`; 250ms; 10 | Pill recognizer; `${gestureId}:armed` | First valid invocation crossing; latch before admission even if dropped. |
| `assistant.opened` | `activation`; 250ms; 10 | Host accepted tap/accessible activation; `${activationId}:opened` | First successful closed→open transition by tap only; not request initiation, rerender, restoration or drag commit. |
| `assistant.detent-settled` | `selection`; 120ms; 0 | Sheet controller; `${gestureId}:detent` or button activation ID | User handle/button settles at a different nonclosed detent. No cue on initial opening, no-change settlement, geometry/keyboard adjustment, cancellation or dismissal. |

Idle/contact/movement/cancellation/drag commit are silent. A threshold followed by reversal and release below T already delivered a recognition cue; do not pretend it can be undone, and do not add a cancellation buzz. Tap has its distinct activation effect because no threshold was felt. Drag opening has only the threshold, avoiding redundant double output. Closed→partial/expanded settlement is part of invocation, not a separate detent event. Back keeps existing `navigation.back-completed`; explicit close/handle close stays silent.

Commit armed styling/transform at the same semantic transition before initiating nonblocking feedback. Do not await native IPC or notification/audio queries. Do not preflight capability in the gesture owner, retry a suppressed event, schedule delayed fallback, fire per movement frame, or suppress normal opening because vibration is unavailable. `HapticAdmission` already limits eight submissions/second, four outcomes/second, 60ms micro / 120ms outcome minimum spacing, event cooldown and bounded ID retention; service busy/configuration gates and native rate limits remain authoritative. Proposed Assistant cooldowns further restrict intentional rapid repetition. Exactly one **request attempt** per qualifying gesture is testable; at most one admitted hardware effect follows, possibly zero due to preferences/readiness/system policy. Never equate `submitted`/`platformAccepted` with a felt motor response.

Respect existing enabled/intensity settings, sound-independent admission, foreground/configuration revisions and native suppression. Android `performHapticFeedback` uses semantic constants without ignore-settings flags. iOS reports system preference unknown and relies on OS suppression; do not invent a getter. Unsupported iPad/motor/WebView gets the same visual/accessibility behavior with silence. Intended feel: a short, subtle, crisp mechanical detent exactly when intentional travel becomes armed, not a long vibration. Judge it on physical phones using existing diagnostic tooling.

### 5. Extend the existing conversation surface, preserve selection Ask

Host one `AssistantPanel` with `fillContainer`. Add a mobile-host-only presentation option that delegates header collapse/close/size to the host and enables the shared microphone control. Add an explicit optional `conversationKey` override; default continues `getConversationKey(context)`. Use reserved key `mobile:global` inside the existing `assistant-panel-conversations-v1` map; do not overwrite `general`, `document:*`, `video:*`, or `web:*`. Key changes, not active source changes, drive rehydration when override is supplied. Retain max 200 stored messages, existing safe parsing and draft/scope restoration; optional source provenance fields default empty for old records. No settings version change.

Lazy-mount panel at first committed open, not during preview; keep conversation state mounted across closed presentation, inert/hidden and excluded from focus/overlay ownership. On wide tablet/desktop transition, unmount the mobile host, save session, cancel microphone and prevent duplicate panel listeners; restored narrow presentation uses the same key. Existing desktop panel props/key derivation/provider selection remain unchanged. New conversation explicitly clears only this key and resets Chat, draft, summary, pinned source and request epoch. Closing/collapse/reopen never clears it. Resume the saved scope after first initialization; “Chat by default” must not erase an explicit Document/Library choice on every open.

Reuse current storage and optional conversation sync helpers without broadening what is synced: raw active excerpts, microphone data, native session IDs and context callbacks remain ephemeral. Do not add a new cross-device sync behavior for the mobile-only key in v1; gate that key out of automatic publish/remote hydration while keeping existing keys unchanged. Safe storage failure leaves the session working in memory; do not lose the active conversation merely because localStorage is full/corrupt.

`AskSheet` retains its existing request-scoped history reset. New selection invokes a fresh isolated context chip/session; it neither resets nor appends to `mobile:global`. Keep its editable/removable chip, page Ask, suggested questions, docked cards, citations and flashcard/read-aloud/copy/follow-ups. Use the same speech adapter in both composers. Do not replace Ask with a global Chat invocation or force its cards into the modal conversation. Suspend global invocation during selection Ask (including docked answer interaction); if selection Ask is explicitly requested while global is open, close the global presentation, preserve its state, then present Ask.

Replace the reader-local PWA floating trigger on mobile presentation with this one global entry; PWA/native now share it. Route any Queue mobile general Assistant toggle to this host. Existing feature/provider configuration remains meaningful; absent AI configuration opens an explanatory composer/settings action rather than a dead pill. Do not change desktop PWA/reader behavior or selection feature flags.

### 6. Active-view context is registered, sampled per turn and privacy checked

Add a narrow `MobileAssistantContextProvider` above mobile children. A registration supplies `{ownerTabId, ownerPaneId, revision, context: AssistantContext, controlsVisible, unavailableReason}` and cleanup token; only the active navigation pane/tab registration wins. Explicitly allow a view-scoped selection/page snapshot for Ask; do not scrape DOM or ask a background pane for selection. An absent provider means `general` with no document attachment.

Register existing context objects in `DocumentViewerWrapper` even when `embedded` returns early. In Queue, publish its final current-item context with live video/PDF refs; suppress embedded child's registration while the Queue parent owns source selection. Add RSSReader registration from its current article model. Library, dashboard and settings supply safe view labels only, no invisible document/credential fields; review provides general context and disables the pill during grading. Clear source atomically on tab/item change and ignore late registrations/results by owner/revision. Source label/status chip makes current context visible and removable; removal is sticky for that source revision until explicit reattachment.

At submit, freeze current source, selection, scope, playback/page anchors, history, provider and conversation epoch. Resolve `resolveForPrompt` then pass source content/status, sections, canonical transcript segments/coverage/time and `previousSourceId/Title` through the existing panel/request pipeline. General questions need no extraction. Expose honest loading/unavailable/partial status and retain retry; no fake transcript-ready or 2000-token head slice. Stable source registrations with refs prevent playback ticks from rerendering the entire panel; resolving context occurs at request time, never on drag frames. After changing views, retain history but show the new source explicitly; earlier documents/quotes are not automatically new evidence.

Persist per-turn source IDs/privacy provenance alongside messages (optional additive fields) and include referenced history sources in existing privacy checks before resending history or summaries. Resolve actual parent IDs for extracts and actual library document IDs; ephemeral RSS article IDs use source text without fabricated DB lookups. If a historical source is now excluded/deleted/unknown or local-only on a cloud request, block sending that protected history with a clear local-provider/new-conversation action. Do not silently send it, label it current evidence, or erase visible history. Library retrieval continues to use existing filters and privacy gates; do not implement another retrieval path. Reuse source attribution and current citation navigation.

Collapsed requests may finish into the same session without reopening UI; background/interruption cancels live dictation and aborts request work where supported. A user clear/new conversation invalidates callbacks and prevents late output from resurrecting the old thread. A source change after submit cannot retarget an in-flight result; it stays attributed to the frozen turn. No reader navigation, scroll mutation, or automatic source attachment from another pane.

### 7. Shared dictation with native first, explicit privacy and bounded lifecycle

Add a small adapter under `src/lib/speech/` and a composer hook reused by Panel's mobile composer and AskSheet. Proposed frontend contract: capability `{platform, available, locale, processing: on-device|system-service|unknown, microphonePermission, speechPermission?, reason}`; `start({sessionId, locale, requireOnDevice})`; `stop(sessionId) -> {text}`; `cancel(sessionId)`. Native capture maximum 60 seconds; stop/finalization timeout 5 seconds, initialization timeout 10 seconds. Return typed denial/unavailable/busy/no-speech/timeout/interrupted/cancelled errors. A single process-wide capture owner prevents competing Ask/global/lecture sessions. Existing lecture capture wins; do not stop another owner's recording.

| Input mechanism | Chosen behavior |
| --- | --- |
| System keyboard dictation | Normal editable textarea input from Gboard/iOS/installed keyboard. The keyboard owns its microphone/privacy/offline behavior. App cannot promise or invoke Gboard's private dictation UI. Focus keyboard through normal user action only. |
| Android app mic | Extend `plethora-android-speech`, keeping ML Kit file APIs unchanged. New commands `dictation_status`, `start_dictation`, `stop_dictation`, `cancel_dictation` wrap Android `android.speech.SpeechRecognizer` (not the ML Kit class of the same name). Use on-device recognizer when API 31+ and reported available; otherwise expose system recognition only with explicit network-processing disclosure/consent and local-only gating. Do not substitute file/lecture jobs. |
| iOS app mic | Reuse `apple_speech_start_live`, `stop_live`, `cancel` through the existing plugin, adding optional `purpose: composer-dictation`, session ID, locale and local-only requirements. Default legacy purpose stays unchanged. Add a side-effect-free dictation-status command rather than equating file capability/Apple Intelligence eligibility with microphone readiness. |
| Browser/PWA app mic | Capability-check Web Speech constructor, secure context, microphone availability and policy. Browser speech may use a server and has uneven support; disclose before starting and disable when strict local processing cannot be guaranteed. Never silently fall back to browser capture after a native failure. ([MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)) |

Android status must not prompt/download. Add `RecognitionService` manifest query where required for service visibility, existing `RECORD_AUDIO` runtime request at explicit mic tap, RecognitionListener before start, main-thread create/start/stop/cancel/destroy, locale errors and bounded native cleanup. `start_dictation` resolves only readiness/start acceptance; `stop_dictation` awaits final results (or returns already finalized cached result for that session) once; spontaneous end stores a bounded result until stop or timeout. No event stream required for v1: show listening and Stop; final transcript arrives on Stop or 60-second auto-stop. The composer starts a 60-second stop timer after accepted start, and native independently enforces the same capture cap; a native auto-finalized result remains retrievable by that session's stop call. Cancel invalidates session and drops late results. Existing package/build/Rust command/permission generation must be extended together. On-device availability does not guarantee a particular locale works; runtime errors remain typed. Android docs explicitly describe recognizer service/lifecycle and on-device APIs ([Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)). No `EXTRA_PREFER_OFFLINE` guarantee.

iOS composer purpose explicitly requests mic plus Speech authorization only at start, on correct queues; validates locale/recognizer availability; uses `supportsOnDeviceRecognition` with `requiresOnDeviceRecognition` for guaranteed local mode. Where unsupported, disable in local-only mode or require explicit system-network disclosure before starting. Stop ends audio input and awaits final recognition callback before teardown/resolve; on timeout keep the original composer and expose retry. Cancel/background/audio interruption cancels task and engine/tap, restores audio session, and cannot insert later segments. Harden error callbacks (currently ignored) and deduplicate termination. Inspect canonical plist configuration and remove duplicate usage keys only as necessary for correct permission packaging; verify resulting archive contains one mic and Speech usage string. Never claim preexisting SpeechAnalyzer adoption or guaranteed offline locales ([Apple on-device recognition](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition), [request local processing](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition)).

At mic tap, save composer text/caret and session generation; opening sheet alone starts nothing. Stop inserts final transcript once at saved selection, preserving surrounding draft; if user edits while listening, cancel dictation before applying their edit, avoiding replacement races. Interim browser/native text is preview only, never repeatedly appended or auto-submitted. Close/Back/collapse/background/permission dismissal cancels and keeps original draft. Label permission/service/network/unavailable failures inline, offer typing and keyboard dictation guidance, and require explicit retry. Microphone stays visible but disabled with a readable explanation if unsupported. No new cloud STT provider, retained audio file, automatic upload, LLM call or send-on-final. Ephemeral composer audio does not enter lecture/file persistence. Do not reuse notification/haptic success signals for speech capture.

### 8. Gesture ownership and accessibility matrix

Highest applicable owner wins; rows do not install a new global dispatcher.

| Surface/input | Existing owner / priority | Assistant rule / regression proof |
| --- | --- | --- |

| Sheet history/composer/selection | Native scroll/text and controls | No gesture listeners on content; contain scroll chaining; avoid forced keyboard. |
| Library swipeable rows/horizontal lists | `.swipeable-item`, scroll owner | No origin outside pill can open sheet; preserve view handlers. |
| PDF page/pinch/vertical scroll, EPUB iframe/selection | Reader and selection controller | No injected iframe listeners, page position changes or selection-handle capture; hide pill during selection interactions. |

Use named dialog with `aria-modal`, focus trap, inert background, named Close/Expand/Collapse controls, stable accessible button labels, `aria-expanded`/`aria-controls` on pill, 48px targets and keyboard Enter/Space activation. Move focus to heading/close on committed open, not composer, so keyboard remains closed; restore to pill or active-view fallback on close. Announce open/detent/listening/error transitions politely, never movement frames. Preserve message reading order and selectable text. Support TalkBack/VoiceOver, switch/keyboard, large text, RTL and high contrast. Haptic/colour cannot be sole indication; armed shape/tone and resulting sheet provide visible evidence. Underlying reader remains mounted and position-stable; while the global modal is open its background is intentionally inert, whereas selection Ask docked cards retain their existing readable/scrollable document behavior.

## Risks / Trade-offs

- [Native feedback is present in code but predecessor acceptance is unfinished] → Complete both predecessor and new hardware matrices before release; no success inferred from APK build or IPC.
- [Persistent global history spans protected sources] → Preserve per-turn source provenance and recheck historical documents before sending; block unknown/forbidden attachments with a clear recovery action.
- [Existing Panel is large and has automatic listeners/persistence] → Add optional mobile host boundaries with unchanged defaults; test hidden state, key restoration and desktop; avoid a wholesale extraction.
- [Nested legacy z-index/body locks can conflict] → Host below existing dialog/menu layers, suspend for selection surfaces, use one registered owner and scoped lock cleanup; regression-test nested layers.
- [Native speech can route through a remote system service] → Capability-specific disclosure and consent; strict-local blocks unknown/remote processing, no silent fallback.
- [Late speech/animation/AI callbacks can reopen or corrupt a different session] → Session/gesture epochs, terminal cancellation, one-shot stop and immutable turn snapshots.
- [Full immersion makes the pill unavailable] → Deliberately reveal through existing controls or exit-and-open; never compete with OS/fullscreen gestures.
- [Geometry/motor constants need tactile tuning] → Fixed initial values and bounded documented device tuning; changing semantic rules requires updating specs/tests, not ad hoc per-device hacks.

## Migration Plan

Implement in the dependency order in [tasks](tasks.md). Add optional fields/props and native commands without removing legacy keys, raising deployment floors or changing settings versions. Preserve old speech defaults; test generated permissions on both platforms. Replace only mobile general entry points once the single host works. Do not enable/disable native Back rollout flags as part of this feature.

Record automated evidence and hardware results in [validation](validation.md), with missing physical rows left unchecked. Rollback removes the new host/entry routing and added events, restoring prior mobile entry points; existing panel sessions/selection workflows and native Back stay intact. Reserved mobile session data can remain safely ignored. Do not delete stored conversations or user data during rollback.

## Open Questions

No product or ownership decision is deferred. Device work will establish actual haptic feel/latency, installed recognizer/locale availability, OEM system suppression and per-reader fullscreen/IME behavior. These are acceptance observations with defined failure/fallback paths, not permission to invent new gestures or assume unsupported native APIs.
