## Why

When a user watches a long video (such as a 2-hour YouTube video like *Michael Pollan on Consciousness*) and opens the Assistant sidebar to run whole-source actions—such as **Key points**, **Summarize**, **Explain**, **Outline document**, **Quiz me**, **Make flashcards**, or asks general questions—the assistant only operates on an arbitrary small slice from the opening minutes (e.g., 00:06–00:45). The generated response explicitly states that its claims are based on a "supplied window" and omits the entire remainder of the lecture.

This defect occurs even when the user has configured a 50,000-token context window in AI Settings. Investigation of HEAD reveals six compounding root causes:

1. **Premature Head-Truncation in Context Actions (`src/features/assistant/contextActions/execution.ts:27`)**: `resolveActionEnvelope` takes the full canonical transcript loaded via `loadDocumentQaText` and immediately runs `trimToTokenWindow(content, Math.floor(policy.promptBudgetTokens * 0.55))` before any planner sees it. Because `trimToTokenWindow` (`src/utils/tokenizer.ts:83`) defaults to a head slice when no scroll/selection is provided, it irreversibly discards 95%+ of the transcript, freezes the truncated text into `target.content`, marks `target.resolved = true`, and sets `coverage = 'window'`.
2. **Video Planner Bypass via `explicitSourceContent` (`src/components/assistant/AssistantPanel.tsx:1574, 2569` & `src/lib/ai/assistant/orchestrator.ts:227`)**: `AssistantPanel` passes `action.target.content` as `sourceContentOverride`, which flags `explicitSourceContent: true`. In `orchestrator.ts`, the video context planner (`resolveVideoSourceContext`) is guarded by `!request.explicitSourceContent`. Thus, the pre-trimmed context action completely bypasses video context planning and hierarchical map-reduce.
3. **Broken Global Context Window Propagation (`src/components/assistant/AssistantPanel.tsx:2295` & `execution.ts:26`)**: In `AssistantPanel.tsx`, `resolveRequestPolicy` is explicitly passed `globalContextTokens: undefined`. In `execution.ts:26`, `globalContextTokens` is not passed at all. Both call sites ignore `useSettingsStore.getState().settings.ai.maxTokens`.
4. **Context Window Configuration Dropped for Non-Ollama Providers (`src/components/settings/LLMProviderSettings.tsx:214-220, 790`)**: `persistContextFields` only saves `contextWindowTokens` and `contextWindowPreset` when `newProviderType === "ollama"`. For OpenRouter, Anthropic, OpenAI, Gemini, and DeepSeek, context window fields are stripped on save and hidden in the UI. Consequently, cloud providers without per-model overrides always resolve to `CONSERVATIVE_CONTEXT_FALLBACK = 8192` tokens.
5. **Artificial 32,000-Token NumericInput Cap (`src/components/settings/AISettings.tsx:512` & `AIProviderSettings.tsx:668`)**: The numeric input for the global context window in `AISettings` has `max={32000}`, which clamps user input on blur.
6. **Planner Complete-Coverage Gaps & Degradation (`src/lib/ai/assistant/videoContextPlanner.ts:156` & `videoMapReduce.ts:31, 48`)**: In `videoContextPlanner.ts`, hierarchical map-reduce is only triggered for queries matching a narrow regex or when `requireCompleteCoverage` is true. But `requireCompleteCoverage` was only wired for Document Q&A workspace turns, never for the Assistant sidebar. Furthermore, `videoMapReduce.ts` divides the token budget by the total number of windows, causing long transcripts (e.g. 50+ windows) to degrade to 32–64 tokens per window, producing empty or garbled summaries.

The previous change (`fix-document-qa-full-video-transcript`) fixed single-video turns inside the dedicated Document Q&A tab (`workspaceGrounding.ts`). It did not address the Assistant sidebar, context action execution, LLM settings persistence, or long-transcript degradation. This proposal establishes unified, full-source transcript intelligence across all Assistant surfaces.

## What Changes

- **Preserve Untruncated Source Targets in Context Actions**: Remove premature `trimToTokenWindow` and the `0.55` multiplier from `resolveActionEnvelope` (`src/features/assistant/contextActions/execution.ts`). Context action envelopes for full documents/transcripts retain canonical content, remain marked for complete coverage, and delegate context budgeting to the orchestrator and video planner.
- **Differentiate Explicit Selection from Whole-Source Action Targets**: Update `explicitSourceContent` semantics in `AssistantPanel.tsx` and `orchestrator.ts` so that whole-source context actions and document targets route into `resolveVideoSourceContext` instead of bypassing it. Genuine user selections (`kind === 'selection'` or explicit pinned ranges) remain strictly bounded.
- **Unify Request Policy Resolution with Complete Precedence**: Guarantee that `globalContextTokens` (`settings.ai.maxTokens`) flows into `resolveRequestPolicy` everywhere (`AssistantPanel.tsx`, `execution.ts`, `PwaAssistantButton.tsx`). Ensure the precedence is strictly enforced: `per-model override` → `per-provider override` → `global context window` → `discovered runtime context` → `conservative fallback (8192)`.
- **Expose and Persist Context Window for All Providers**: Enable context window configuration and presets (`auto`, `4k`, `8k`, `16k`, `32k`, `64k`, `128k`, `custom`) for all provider types (OpenRouter, OpenAI, Anthropic, Gemini, DeepSeek, Ollama) in `LLMProviderSettings.tsx`. Update `persistContextFields` to persist `contextWindowTokens` and `contextWindowPreset` across all providers.
- **Remove 32,000 Clamping in AI Settings**: Raise the numeric input limits in `AISettings.tsx` and `AIProviderSettings.tsx` to 1,000,000 (supporting large-context models like Claude 3.5 Sonnet, GPT-4o, and Gemini 1.5/2.0/Flash) with sensible step intervals.
- **Broaden Full-Transcript Coverage across All Assistant Entry Points**: In `AssistantPanel.tsx`, pass `completeTranscriptSource: true` when the active document is a video and the scope is `document` or whole-source action, guaranteeing parity with the Document Q&A tab.
- **Robust Multi-Stage Long-Transcript Map-Reduce**: Redesign `videoMapReduce.ts` to ensure intermediate window summaries maintain a viable minimum token budget (e.g., 150–250 tokens per window) using chunked recursive reduction rather than dividing prompt budget by total window count, preventing degradation to 32-token summaries on multi-hour transcripts.
- **Intent-Aware Routing & Whole-Source Retrieval**: Distinguish global analytical requests (Key points, Summarize, Outline document, Examine argument) requiring whole-video synthesis from specific factual inquiries across long videos (which utilize high-recall semantic retrieval across the entire transcript) and explicitly localized questions (timestamps or playback position).
- **Per-Turn Source Coverage & Budget Diagnostics**: Provide structured, privacy-safe turn diagnostics indicating configured context, effective model context, prompt budget, output reserve, transcript duration, coverage mode (`full` direct, `hierarchical-full`, `window`, `chunks`), and window counts.
- **Honest UI Coverage Indicators**: Display accurate processing status on Assistant responses (e.g., `Full transcript · 2h 02m · Direct context` or `Full transcript · 2h 02m · Analyzed in sections`), replacing false claims or misleading "supplied window" warnings.

## Capabilities

### New Capabilities

None. (Reuses and extends existing canonical specifications).

### Modified Capabilities

- `youtube-canonical-transcript-intelligence`: Broaden requirements to mandate full-transcript grounding by default for whole-source actions and general queries across all Assistant surfaces (Document Viewer, Queue Scroll, Assistant sidebar, and Document Q&A). Prohibit premature head-truncation in context actions. Upgrade long-video hierarchical synthesis to maintain minimum per-window budgets without duration limits. Enforce honest coverage reporting.
- `context-window-settings`: Update settings requirements so that context window controls and presets apply to all providers (including OpenRouter, Anthropic, OpenAI, Gemini, DeepSeek, and Ollama) and persist in `LLMProviderConfig`. Remove artificial 32,000 UI token limits in AI Settings. Ensure `settings.ai.maxTokens` is propagated as the global fallback to all policy resolution call sites.
- `assistant-composable-prompt-budget`: Enforce single authoritative token policy resolution across all Assistant entry points. Replace arbitrary frontend multipliers (`0.55`) with structured prompt budgeting (protecting core system instructions, tools, user queries, and output reserves). Add requirements for per-turn source coverage diagnostics.
- `selection-aware-assistant`: Clarify the boundary between bounded user selections (which must remain localized with window coverage) and whole-source document/transcript targets (which must never be tagged as bounded explicit source content or pre-trimmed to a head slice).
