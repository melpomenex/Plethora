### 9a. Crash fixes found during the first on-device run (2026-07-31)

The first real device run crashed the app process 13 times. All three defects below
are fixed and re-verified on the same device; see the git history for this change.

- [x] 9a.1 **Foreground-service crash (process death on every speak).** `TtsPlaybackService.onCreate` called `startForeground()` without `android.permission.FOREGROUND_SERVICE` — the plugin manifest asserted the host app declared it, but the merged manifest had no such permission. `SecurityException` was thrown inside `ActivityThread.handleCreateService`, out of reach of the caller's try/catch, killing the process. Added `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PLAYBACK` (required for `mediaPlayback` from API 34; the app targets 36), made `startForeground` non-fatal with `stopSelf()` on refusal, and switched `START_STICKY` → `START_NOT_STICKY` (sticky restart re-created the service with no audio behind it and turned the crash into a loop). **Verified**: `dumpsys activity services` reports `isForeground=true foregroundId=4201 types=0x00000002`.
- [x] 9a.2 **React hook-order crash on provider switch.** `useTTS` returned the native surface before eight further hooks, so changing the provider to/from `android` changed the hook count between renders and React threw "Rendered fewer hooks than expected", blanking the app until restart. The branch now sits below every hook. **Regression test**: `src/hooks/__tests__/useTTS.providerSwitch.test.tsx` (confirmed to fail against the old structure).
- [x] 9a.3 **R8 stripped the plugin in release builds.** `consumerProguardFiles("consumer-rules.pro")` pointed at an empty file while all keep rules sat in `proguard-rules.pro`, which never applies to the consuming app's R8 pass. Release builds renamed `com.k2fsa.sherpa.onnx.**`, breaking implicit JNI name resolution. Rules moved to `consumer-rules.pro`. **Verified** via `mapping.txt`: 0 renamed classes in both `com.k2fsa.sherpa.onnx` and `com.incrementum.androidtts`.
- [x] 9a.4 **Event payloads corrupted by JS splicing.** `dispatchEvent` escaped the JSON then spliced it into `evaluateJavascript` as a raw object literal, so a JSON-escaped `\"` — i.e. any sentence containing a double quote, which is most epub dialogue — closed the string early and made the script a syntax error the inner try/catch could not catch. Now passes the payload as a `JSONObject.quote` string literal parsed with `JSON.parse`.
- [x] 9a.5 **Utterance ids could never correlate.** `useNativeAndroidTTS` seeded `utteranceRef` with `Date.now()` "to be reconciled on the first event", but nothing reconciled it and a ~1.7e12 timestamp never equals the native monotonic counter — so every `sentence-position` and `utterance-complete` event was discarded (no highlighting; UI stuck in the speaking state after playback ended). Handlers now adopt the id from the first event and reject only strictly-older ids.
