## Why

[Incrementum issue #44](https://github.com/melpomenex/Incrementum/issues/44) is historical evidence from the retired Incrementum repository; **Plethora is the sole active implementation target**. The issue went through three rounds: the initial report (2026-08-14), a fix round shipped as Incrementum v2.5.0/v2.5.1 (tracked here as the completed-but-unarchived change `fix-issue-44-bugs`), and the reporter's final follow-up (2026-08-17, retested on Incrementum v2.7.0) which found **five of the "fixed" old bugs still broken and reported seven new defects** — twelve in total.

Plethora forked from Incrementum at merge-base `6881032c` (2026-08-17), *after* the v2.7.0 tag the reporter tested, so the reporter-tested code is present at Plethora HEAD. Per-file `git diff v2.7.0..HEAD` confirms every affected subsystem is byte-identical or rebrand-only except the selection-interaction V2 rebuild (Bug 06's invocation path) and AI-provider fixes. The eight Incrementum commits not in Plethora are security hardening plus mobile image-registry UX — none claims to fix any #44 item, so nothing may be assumed fixed from Incrementum's later state. This change independently audits all twelve reports against Plethora HEAD (`fb98a5b7`) and remediates what is still broken, at root cause.

## What Changes

Eleven root-cause groups, ordered by subsystem:

1. **Knowledge Universe reframing (Bug 01)** — a scope/data change on a live universe re-frames the camera deliberately (tween to the new home) instead of following only when already at home; `homeTarget` is computed from the visible core (clusters + system nodes), with rim content covered by fit bounds rather than dragging the center. Deliberate same-data pans are preserved.
2. **NotebookLM listing integrity (Bug 02)** — an empty notebook list is reported only from a parseable empty envelope; unparseable/non-JSON CLI output becomes a surfaced error; login strategies verify before reporting success; the Connected badge never displays over an unverified listing; the list timeout stops racing the Playwright-backed CLI.
3. **Section-mention reliability (Bug 03)** — `#` chips keep a stable id↔title identity across keystrokes in Document Q&A; `#` explains itself (loading and unavailable states) instead of silently doing nothing outside document contexts and in Whole-Library mode; send-time matching tolerates case/punctuation drift; pseudo-document assistant contexts (podcast, `extract:`) resolve against their attached content or say why they can't.
4. **OCR pipeline availability (Bug 04)** — the OCR processor is initialized deterministically at startup and reconfigured whenever OCR settings change; every OCR entry point preflights provider availability and returns actionable errors instead of per-page-swallowed blanks; image-only providers rasterize PDF pages; the language setting reaches Tesseract.
5. **Due-queue completeness (Bug 05)** — the workload forecast counts the same item types as Due All (extracts, video extracts) and buckets the overdue backlog instead of rendering zero; the collection fallback uses the real default-collection sentinel across all four item-type queries; imports thread the chosen collection onto created cards.
6. **Reader search teardown (Bug 06)** — clearing in-document search surgically unwraps highlight marks and restores a pristine DOM (no leftover marks, no nested marks on re-search, no cache pollution); the legacy AI-action memo no longer acts on a stale selection.
7. **Embedded-browser redirectors (Bug 07)** — known search-result redirector URLs (`google.com/url?q=`, `duckduckgo.com/l/?uddg=`, `bing.com/ck/a`) are unwrapped to their target before proxying, through the existing validated fetch path; a watchdog surfaces "frame escaped the proxy" as the existing blocked/reader-view fallback on the Tauri path. No CSP or sandbox loosening.
8. **Unified extract editor (Bugs 08 + 12)** — all extract creation paths converge on one data shape; a single shared extract editor (annotation toolbar, article images, embedded Image Registry) serves both creation and post-creation editing; `update_extract` accepts `html_content`; annotation buttons are focus-safe (mousedown-preserving, Cmd+B/I); reading surfaces render markdown from `content` when `html_content` is absent, preserving the reading presentation and keeping Search excluded from the Extract reader.
9. **Extract image ingest (Bug 09)** — image paste reaches the embedded Image Registry regardless of focus inside the dialog; drag/drop of image files onto the shared editor or registry is accepted through the canonical `ingest_image_asset` pipeline; registry picks embed full-resolution assets, not list thumbnails.
10. **Deck-manager visibility (Bug 10, hardening)** — saving a card with a deck reference always materializes the corresponding StudyDeck in the shared store, so every deck offerable at creation is visible and editable in Deck Manager; a regression test pins the creation↔manager parity invariant.
11. **Document-category editing (Bug 11)** — a document's category is editable inline from the Library (details popover/details surface, following the `ItemTagEditor` pattern) and from the document reader's details, with preset chips from existing document categories plus free text; Library filters, queue chips, and search update consistently; the Stats category breakdown also reflects document categories.

## Capabilities

### New Capabilities

- `knowledge-universe-scope-reframing`: camera re-framing on scope/data changes and core-based home targeting for the Knowledge Universe.
- `notebooklm-listing-integrity`: fail-closed notebook listing, verified login, and honest Connected state for NotebookLM.
- `section-mention-reliability`: stable chip identity, honest availability states, and tolerant resolution for `#` section mentions.
- `ocr-pipeline-availability`: deterministic processor initialization, settings propagation, provider preflight, and PDF rasterization for OCR.
- `due-queue-completeness`: forecast parity with Due All item types, overdue bucketing, and correct collection scoping across item types and imports.
- `reader-search-teardown`: full DOM restoration after clearing in-document search, with no stale selection context.
- `embedded-browser-redirectors`: search-redirector unwrapping and blocked-frame surfacing in the embedded browser.
- `unified-extract-editor`: one capability-equivalent extract editor for all creation and editing paths, with working formatting.
- `extract-image-ingest`: focus-independent image paste, drag/drop ingest, and full-resolution embedding for extract images.
- `deck-manager-visibility`: every deck referenceable at card creation is visible and editable in Deck Manager.
- `document-category-editing`: category assignment/editing from Library and document surfaces with consistent downstream updates.

### Modified Capabilities

None. (The related prior specs — `mistral-ocr-integration`, `extract-reader-stability`, `queue-item-type-routing` — cover adjacent behaviors whose requirements do not change here; `fix-issue-44-bugs`' four specs live inside that unarchived change and are superseded in intent by the stricter requirements above, not modified in place.)
