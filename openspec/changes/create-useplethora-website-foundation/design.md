## Context

The Plethora repo is a Tauri 2 + Vite + React application (`package.json` name `plethora-tauri`). `vercel.json` at the repository root already deploys **`npm run build:pwa`** to `dist` with SPA rewrites and a Python transcript serverless function. Putting the marketing site in that project would either replace the PWA or create an unmaintainable dual-output build.

A sibling git directory `plethora-website` exists but is empty (`.git` only). This repo is **not** an npm/turbo monorepo. Hosting audit: marketing must not share the PWA Vercel project (`readsync.org` / `build:pwa`). OpenSpecs stay here. Implementation is `website/` in this repo (independent `package.json`, no workspaces required). The empty sibling MAY later receive a split deploy remote; it is not a second copy deck.

Astro 5 is the framework: static HTML by default, islands for the later interactive demo, content collections for MD pages, no SSR requirement for v1. Server output is allowed later only for signed checkout session creation — not in this change.

## Goals / Non-Goals

**Goals:**

- Installable, documented `website/` that `npm install && npm run build` produces a static `website/dist`.
- Canonical config modules matching `openspec/planning/useplethora-website-shared-contracts.md`.
- Layout chrome usable by B/E/D.
- Vercel settings as files in `website/` plus a human checklist to create a **second** Vercel project with Root Directory `website`.
- Safe defaults: `noindex`, downloads disabled, checkout disabled, analytics disabled.

**Non-Goals:**

- Deploying, `vercel link`, or printing secrets.
- Visual homepage, demo machine, legal text, screenshot scripts.
- Changing app entitlements or PWA hosting.
- npm workspaces migration of the Tauri app (optional later).

## Decisions

### D1 — Location `website/` in this repo, separate Vercel project

Keeps OpenSpec, brand SVGs, and marketing fixtures together. Independent `website/package.json` (no need to invent workspaces). Empty `plethora-website` is not the copy source of truth. **Never** change root `vercel.json` Root Directory to `website`.

### D2 — Astro 5 + TypeScript, React only as an island runtime

B can author mostly `.astro`. D will add a React (or Solid) island. Do not enable SSR in v1 (`output: 'static'`).

### D3 — Separate Vercel project

Root `vercel.json` remains the PWA. Website uses `website/vercel.json`. Document: `vercel project ls`, confirm name, set Root Directory. If the existing project is the PWA, **do not** change its root.

### D4 — Public env prefix

Astro uses `PUBLIC_*`. Defaults in repo: indexing `noindex`, all commercial flags false. Production flip is launch-day configuration, not a code rewrite.

### D5 — Do not import `src/` from the app

Duplicate entitlement *ids* as a const array in `website/src/config/entitlementIds.ts` generated by a comment “must match `src/types/entitlements.ts`”. Optional later: a test in F that diffs the two lists. Prevents pulling Tauri/Zustand into the site bundle.

### D6 — `www` → apex, HTTPS only

`https://www.useplethora.com/*` 308 to `https://useplethora.com/*`. Canonical origin `https://useplethora.com`.

### D7 — Security headers

`Content-Security-Policy` (allow self, data/blob for images, no unexpected third parties until analytics vendor chosen), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` camera/mic/geo off, `X-Frame-Options: DENY` (or CSP `frame-ancestors 'none'`).

### D8 — Stub routes

Create thin pages for E/B/D routes so sitemap and nav work. Bodies can be placeholders tagged `data-owner="E"` etc.

## Risks / Trade-offs

- **Wrong Vercel project linked:** mitigate with README verification steps; never script-link in CI without explicit project id env on the maintainer machine.
- **Astro vs Next:** Next is unnecessary SSR weight; Astro chosen.
- **Config drift from app entitlements:** F should add a parity test later.
- **Case-sensitive `openspec/` vs `OpenSpec/`:** website OpenSpecs live only in `openspec/`.

## Migration / Rollout

Additive. No user migration. Staging: preview deployments noindex. Production domain attach is a later ops step (F launch checklist).
