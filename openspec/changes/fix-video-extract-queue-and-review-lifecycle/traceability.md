## Feature-level acceptance sequence

| Step | User-visible result | Authoritative assertion |
|---|---|---|
| 1 | Create source video | Parent document row exists with known scheduling snapshot |
| 2 | Create titled extract, Add to Queue on | Extract row queued, NULL date, collection copied |
| 3 | Save | Dialog closes only on success; failure shows error and no row |
| 4 | Look at source panel | Extract appears immediately with title/time/status |
| 5 | Look at library Extracts | Extract appears in the video section |
| 6 | Open Queue | Extract appears exactly once in Due All/reading queue |
| 7 | Open extract | Correct source opens at `start_time`, bounded by `end_time` |
| 8 | Confirm playback | Seen persisted; review count still zero |
| 9 | Rate Good | One receipt, extract count +1, memory/date updated, parent snapshot unchanged |
| 10 | Observe queue | Extract leaves the due set; sibling segments/parent remain |
| 11 | Restart | Status, history, date, membership intact |
| 12 | Advance clock to due date | Extract eligible again |
| 13 | Rate again | Exactly one additional receipt/count |
| 14 | Remove from queue | Membership false; content/history intact; absent from queue |
| 15 | Re-add | Membership true; retained date reused; history intact |

No row is closed merely because a function or component exists. Every row above requires the named implementation and regression test.
