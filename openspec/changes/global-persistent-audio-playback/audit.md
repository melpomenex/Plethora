## Existing specs and overlapping plans

Read full existing `podcast-position-persistence` and `audio-edition-position-persistence` requirements/scenarios before drafting deltas; existing `audio-learning-actions` owns capture semantics and must remain intact. `openspec list --specs` inventory was consulted. The podcast spec currently lacks a Purpose section, so `openspec show ... --json --no-scenarios` reports that pre-existing formatting problem; raw spec is readable. To remove the archive blocker reported by strict validation, this proposal normalizes only this affected canonical spec to a title, Purpose and Requirements header; all existing requirement/scenario bodies are preserved. No future behavior is applied to the canonical spec.

`native-media-lock-screen-controls` and `fix-mobile-layout-and-android-media-controls` contain partly completed native integration plans; their source exists but device checkboxes do not prove runtime behavior. This change extends their actual modules and replaces ordinary-media forwarding ownership, without creating another integration track. `preserve-tab-state-on-switch`, `eliminate-long-running-memory-growth`, `unified-recording-ingestion-and-learning-studio`, `podcast-subscription-playback`, and `fix-reader-scroll-save-overhead` overlap shell/progress concerns; preserve their independent behavior and pre-existing edits.

## External constraints checked on 2026-10-23

- Android recommends putting the actual Player and MediaSession in a service for background playback: [Media3 background playback](https://developer.android.com/media/media3/session/background-playback).
- Target API 35+ focus requests require visible/top-app or foreground-service eligibility; use one focus owner: [Android audio focus](https://developer.android.com/media/optimize/audio-focus).
- Media-session notifications are exempt from Android 13 notification-permission changes: [notification permissions](https://developer.android.com/develop/ui/compose/notifications/notification-permission#media-sessions).
- Souvlaki requires an HWND on Windows; Linux uses D-Bus configuration: [PlatformConfig 0.8.3](https://docs.rs/souvlaki/0.8.3/souvlaki/struct.PlatformConfig.html).

These are constraints, not proof that Plethora passes them. Media3 remains pinned to the existing 1.8.0 family for implementation; do not silently upgrade unrelated artifacts.
