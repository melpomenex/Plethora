## Eight investigation targets: verdict

All eight are confirmed with qualifications: Blob persistence is not durable; memory grows with capture duration; lecture save flattens metadata; Inbox uses generic cards; TranscriptPanel disables extract; extract generation can save before approval; Apple capture differs; the surfaces are fragmented. These are source findings, not claims of reproduced device crashes. The focused lecture unit test passes because it does not establish disk/restart survival.

## Evidence limits and safe defaults

- No physical Android/iOS/macOS/Windows capture, codec matrix, cloud endpoint, diarization or crash recovery was exercised. Device/endpoint availability remains a release gate; unsupported adapters expose an honest blocker.
- Existing iOS live speech does not establish long-form on-device service reliability. Start with disk-first native capture and post-recording capability-gated STT; live captions remain optional.
- Existing cloud disclosure permits execution when no presenter is registered (`cloudAiDisclosure.ts:138`). Session workers require an independently validated durable authorization before any remote dispatch; no global behavior change is assumed.
- Baseline targeted tests: **116 passed, 1 failed in 7 suites**. Failure: `src/utils/__tests__/cardSourceNavigation.test.ts:335`, repeated quote expects `ambiguous`, gets `no-anchor`. This is an existing source-navigation contract mismatch, preserved for implementation triage. See validation.md for exact command and scope.
- Concurrent workspace activity: after the baseline/test audit, unrelated edits appeared in `src/lib/ai/diagnostics.ts`, `src/lib/ai/tasks/runTask.ts`, `src/lib/ai/tasks/types.ts` and new diagnostics/features directories. This proposal did not write those files. HEAD remained the recorded commit; verify their landed contracts before implementing task/readiness integration. The reported tests describe the earlier observed working-tree state, not an assertion about the concurrent edits.
