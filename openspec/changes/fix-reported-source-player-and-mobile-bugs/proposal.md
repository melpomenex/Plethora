## Why

Four user-reported problems, audited against the code. They are grouped because they are all promises the app visibly breaks, but they are not one defect class — one is a resolution ladder with a dead final rung, one is a settings key stranded in a type the runtime never loaded, and two are layout arithmetic on a 360 px screen.

| Report | What the audit found |
| --- | --- |
| "Source unavailable — the original document no longer exists" on a card whose document *does* exist | Flashcard Studio's whole-document mode (`contextSelection.ts:29`, `mode: "full"`) never sets `card.sourceContext`, so `FlashcardStudioModal.tsx:3606` skips writing `source_reference`; `seed.linkedExtractId` is also undefined, so `extract_id` is null. The card row is `{ document_id: <id>, extract_id: null, source_reference: null }`. `resolveCardSource` then falls past rungs 1–3 and returns `{ status: "unavailable", reason: "no-source" }` at `cardSourceNavigation.ts:503` **without ever consulting `item.document_id`**, and `openCardSource` returns at `:517` *before calling `openDocumentAtLocation`*. The "open the document at its stored reading position" branch at `:519-528` is therefore unreachable for exactly these cards. The message is a lie: the document is there. |
| Schedule view has no usable top bar to navigate back | Two compounding facts. (a) `ScheduleWorkspaceHeader` renders a bar but contains no back or close control — its only `X` clears the *date filter* (`ScheduleWorkspaceHeader.tsx:88`). (b) The phone shell's only way out is the segmented control in `MobileQueueView.tsx:591-633`, whose three labels are wrapped in `hidden xs:inline` (`:602, :619, :631`). Tailwind is v4 CSS-first with no `tailwind.config` and no `--breakpoint-xs` in `index.css`, so `xs:` is not a generated variant: all three labels are `display: none` at **every** width. `ReviewSession` and `ZenReviewMode` both render a real back button; `ScheduleView` alone does not. |
| SponsorBlock does not skip sponsorships | It does. The skip loop runs at `YouTubeViewer.tsx:790-866` and the segment fetch at `:534-543`, both **ungated**; CSP is fixed (`tauri.conf.json:36`); the Rust pre-cut path works. What is missing is everything around it: the `sponsorBlock` key exists only in a dead parallel `Settings` type (`types/settings.ts:342`, `config/defaultSettings.ts:251`, `settingsValidation.ts:311`) that the live zustand store (`settingsStore.ts:964`, 26 categories, no `sponsorBlock`) never had — `rg "settings.sponsorBlock"` returns **zero** runtime reads. So it cannot be turned off, categories cannot be chosen, the fetch has no timeout and no cache, `submitSegment`/`voteOnSegment` build a doubled `/api/api/...` URL (`:213, :244`), and the 342-line `SponsorBlockIntegration.tsx` is orphaned with zero importers and a no-op settings checkbox. The requirement at `reimplement-incrementum-features/specs/settings-management/spec.md:293` is unmet despite `tasks.md:200` marking it `[x]`. |
| Review queue draws off-screen to the left on a phone | `ReviewSession.tsx:936-938` renders the queue list as `absolute right-0 mt-2 w-80` with **no viewport clamp**. `right-0` anchors to the right edge of a `relative` wrapper that is the last child of a `flex-wrap justify-start` row (`:863`) after five preceding controls — so on a phone that wrapper can sit near x≈0 and the fixed 320 px panel lands almost entirely at negative x, under `z-50` and invisible. Secondary: `SwipeableItem` applies an **unclamped** `translateX(${state.offsetX}px)` (`:170-175`) from raw gesture `dx`, so a flick that loses its `touchend` strands the row off-screen left; `ZenReviewMode`'s dot row (`ZenReviewMode.tsx:703`) is `fixed right-4` with ~156 px of content and no overflow guard; and `ReviewQueueView`'s scroller (`:1276`) lacks `min-w-0` next to an always-open `w-80` inspector (`:1926`, default `true` at `:185`). |

## What Changes

- **"View source" always reaches the document when a document is known.** A new final rung in `resolveCardSource` treats a bare `item.document_id` as a coarse target, so the already-written "open at the document's stored reading position" branch becomes reachable. The `unavailable` message is reserved for the case it actually describes — the document row is gone — and the `no-source` case stops claiming the document "no longer exists".
- **The affordance is consistent across surfaces.** `CardContextMenu`'s `hasSource` gate (`CardContextMenu.tsx:121`) checks `extract_id || source_reference` and ignores `document_id`, so a whole-document card gets a "View source" button in the card strip and *nothing* in the context menu. Both surfaces derive availability from the same predicate, matching the Rust command's own rule (`get_card_source_context` requires only `document_id`).
- **Schedule is enterable and returnable from labelled controls on every shell.** The phone segmented control's three labels render; the workspace header gains a labelled back control that returns to the queue's default mode; and the date-filter `X` is no longer the only icon in the bar. Desktop keeps its existing Reading/Schedule/Review control row.
- **SponsorBlock becomes a real, configurable feature.** `sponsorBlock` moves into the live `settingsStore` with an enable toggle, per-category selection, an auto-skip toggle, skip notifications, and a cache duration; persist `version` goes 13 → 14 with a migration step. The fetch and the skip loop both become gated, the segment fetch gains a timeout and an in-memory cache keyed by video id, and the doubled `/api` URLs in the write paths are fixed. The orphaned `SponsorBlockIntegration.tsx` is deleted. The same gating applies to `LocalVideoPlayer` and `AudiobookViewer`, which carry the same ungated loops.
- **Queue surfaces are clamped to the viewport.** The `ReviewSession` queue list stops using a fixed `w-80` and is viewport-aware; `SwipeableItem` clamps its offset and force-resets on a lost `touchend`/`touchcancel`; the zen dot row is bounded; the desktop queue scroller gets `min-w-0`.
- **Dead code that misleads the next reader goes away.** The orphaned SponsorBlock component, and the three undefined-Tailwind-classes (`xs:`, `scrollbar-hide`, `pb-safe`) get either a real definition or a real replacement.

## Capabilities

### New Capabilities

- `card-source-fallback`: reaching a card's source document when no exact locator exists, the honest wording of each degradation, and one shared availability predicate across the card strip, the context menu, and the keyboard shortcut.
- `sponsorblock-segment-skipping`: fetching, caching, and skipping SponsorBlock segments, gated by user-configurable settings, consistently across the YouTube, local-video, and audiobook players.
- `mobile-review-queue-viewport`: review and queue surfaces on phone-sized viewports stay within the viewport and expose labelled navigation back out of a full-width sub-view.

### Modified Capabilities

- `schedule-workspace`: the workspace header SHALL expose a labelled back/close affordance, and the phone segmented control SHALL render readable labels, so Schedule can be left. The existing "Responsive Schedule behavior" requirement covers touch targets and content reflow but says nothing about enterability or a return route.

- **Mobile viewport**: `src/components/review/ReviewSession.tsx` (queue list), `src/components/mobile/SwipeableItem.tsx`, `src/hooks/useSwipeGestures.ts` (clamp, lost-touchend reset), `src/components/review/ZenReviewMode.tsx` (dot row), `src/components/review/ReviewQueueView.tsx` (`min-w-0`).
- **Spec bookkeeping**: the unmet requirement at `openspec/changes/reimplement-incrementum-features/specs/settings-management/spec.md:293` and its falsely-completed task `tasks.md:200` are satisfied by this change and should be noted there rather than duplicated.
- **No database migration.** The new setting lives in the zustand/localStorage store, matching every other user setting; the pre-cut metadata path is untouched apart from the data-dir constant.
- **i18n**: every new user-visible string must land in all six locales (`en`, `de`, `es`, `fr`, `ja`, `zh`) — the repo enforces placeholder parity by test.
