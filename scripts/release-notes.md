### Added

- **PDF rendering now uses pdf.js's `PDFPageView`** — The PDF viewer's hand-rolled canvas + text-layer DOM has been replaced with pdf.js's official `PDFPageView` component, which owns the page DOM, the `.textLayer`, and the `--scale-factor`/`--user-unit` CSS variables itself. This removes ~280 lines of defensive mount/cancel/`parentNode-is-null` glue code and fixes a whole class of text-selection bugs at the source: pdf.js now sets the DOM it expects, so spans are sized correctly and selection behaves the same as in Firefox's own pdf.js viewer. The persistent highlight layer is overlaid above the page (clicks pass through to the text layer), and OCR overlays, virtualization, search/TTS highlighting, and vim caret movement all continue to work against the pdf.js-managed text layer.

### Fixed & Improved

- **App no longer freezes on launch with a macOS keychain password prompt** — The OS keychain was accessed unconditionally on startup (sync room key, AI API keys, OAuth tokens), which on macOS triggered the system keychain unlock dialog and blocked the window indefinitely for users who never set a keychain password. Keychain access is now opt-in across all three storage backends (a single `INCREMENTUM_USE_KEYCHAIN=1` env var gates it) and defaults to the existing encrypted-on-disk fallback, so the app never prompts for a password unless explicitly enabled.
- **Faster database startup on large libraries** — The startup `PRAGMA integrity_check` (which scans the whole database) is now `PRAGMA quick_check`, which verifies the same structural integrity needed to detect corruption but skips the expensive table-vs-index cross-verification. On a ~100MB library this cut the pre-window blocking time from over a second to a fraction.
- **PDF text selection persists on release and no longer flickers** — The native-selection handler was mirroring the browser selection into React state on every `selectionchange` event during a drag, causing continuous re-renders (flicker) and clearing the selection on WKWebView's transient post-mouseup collapsed events (disappears on release). Selection state is now committed to React exactly once on mouseup, after the browser has finalized the range — the native highlight handles the visual during the drag.
