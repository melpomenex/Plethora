### Added

- **Compact View sort shortcuts** — The Compact View sidebar gains **Extracts** and **Flashcards** quick-sort buttons, visually distinct from the Signals filters above them (a sort icon and no count badge, so "sort by extract count" can't be confused with "filter to only docs with extracts"). Both feed the shared sort state, so switching to List or Grid view keeps the same ordering.

### Fixed & Improved

- **Documents-tab performance on large libraries** — Opening the Documents tab no longer triggers a full per-document sync pass on every activation. Document publishing now skips the write when a document's clock hasn't advanced since the last publish, and file registration keeps a per-session cache so already-registered documents aren't reprocessed on every tab switch; the manifest lookup is also indexed once per pass instead of scanning per document, and the remaining work is batched with idle yields so a large first-time pass no longer blocks scrolling. The legacy list-mode card rows and Compact View table rows are now virtualized (only rows near the viewport are mounted), so libraries of hundreds of documents scroll and sort without the per-row rendering cost that previously dominated.
- **Extract count signals stay correct** — The Compact View "Has extracts" filter and the EXTRACTS column now read a server-persisted count instead of an in-memory value that was clobbered on every reload/collection switch. Creating or deleting an extract updates the document's `extract_count` in the same transaction, and a one-shot migration backfills the correct count for existing documents.
- **Alt+P priority popup seeds the real priority** — The priority popup now seeds from a document's actual current priority, including an explicit value of **0** (the Lowest preset). Previously a document deliberately set to priority 0 was indistinguishable from one never touched, so the popup reseeded to the neutral midpoint (50) instead of 0. A new `priority_explicitly_set` flag, flipped on every priority commit, distinguishes "user set this" from "never touched" without altering the existing priority columns.
