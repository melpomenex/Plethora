### Added

- **Brave Search API key configuration in Settings** — A new "Brave Search API Key" section in Settings → AI Providers lets you paste your Brave Search key (with Save + Test Connection) so Document Q&A can run live web searches for grounded answers. The key is stored in the OS keychain, never displayed back, and the live settings page now surfaces the real backend error on a failed test instead of a generic "Connection failed". The legacy (unreachable) AI settings page that previously held this field has been superseded.

### Fixed & Improved

- **Eliminated full-table scans on the two hottest paths** — Every single review submission was loading the entire `learning_items` table and `.find()`-ing one row (the code literally said "This is inefficient but works for now"); each "postpone" action did the same again from the frontend over IPC. Both now use a real `WHERE id = ? LIMIT 1` primary-key lookup, so per-card cost is O(1) instead of O(N) regardless of library size.
- **The library grid no longer ships every document's full extracted text across IPC** — `list_documents` ran `SELECT *` including each document's `content` TEXT column (hundreds of KB to multiple MB per PDF/EPUB), fetched from ~38 call sites on load, navigation, and every collection switch. A new `list_documents_summary` query projects only the columns the grid needs (nulled-out `content`/`content_hash`/`metadata`), cutting the dominant heap/IPC amplification felt app-wide.
- **Vector / semantic search is no longer a brute-force scan + full sort on the main thread** — `find_similar` loaded every embedding, decoded each, computed cosine similarity for all N on a single tokio worker, then sorted all results before truncating to top-k. It now keeps a bounded heap (O(N log k)) inside `spawn_blocking`, and access-count updates are batched into a single transaction instead of one UPDATE per embedding row.
- **LLM token streaming no longer fires one IPC event + one React re-render per token** — Each streamed delta emitted a separate Tauri event, JSON serialization, store update, and re-render (a 2000-token response was ~2000 round-trips). The backend now coalesces deltas (flush at ~40ms / 256 chars / on completion) and the frontend debounces via `requestAnimationFrame`, eliminating the visible "typing jank" during AI responses.
- **Transcription progress/segment flooding fixed** — The engine fired progress callbacks many times per second (each a full store `set()` + re-render) and spawned a separate task per segment (2 DB queries + an emit each, thousands racing on the connection pool). Progress emits are now throttled (Δ≥1% and ≥50ms) and segments are persisted via a single channel-draining consumer doing batched multi-row INSERTs in one transaction.
- **Fixed O(N²) loops in the engaging scheduler and Anki importer** — The scheduler re-summed the entire already-scored list every iteration; the importer did a linear `.find()` over all notes for every card. Both now use incremental accumulators / a `HashMap` lookup, dropping to O(N) / O(cards+notes) with identical output. Anki's `batch_insert_review_log` was also upgraded from N single-row INSERTs to chunked multi-row INSERTs in a single transaction.
- **Halved peak memory on PDF/OCR import** — PDF text extraction cloned the entire 50–200 MB buffer for a blocking task while the original stayed resident; OCR materialized every page's image up front and held ~4× the image size transiently via base64 round-trips. The buffer is now `Arc`-shared, page images are extracted lazily (one at a time), and base64 is built in a single pre-sized buffer.
- **Blocking subprocess / runtime calls moved off async workers** — `yt-dlp` downloads ran `std::process::Command::output()` directly inside `async fn`s (pinning a tokio worker for minutes), and the MCP server created a brand-new tokio `Runtime` per tool call (risking a nested-runtime panic). Subprocess calls are now wrapped in `spawn_blocking`, and the MCP server reuses a single lazily-initialized runtime.
- **Cloud sync and RSS refresh are no longer strictly sequential** — Uploads/downloads awaited one at a time, and RSS discovery fetched each domain's feed in series (no `join_all` existed anywhere in the backend). Both now run with bounded concurrency (cap 8 via semaphore / `buffer_unordered`), and a new `bulk_create_rss_articles` backend command replaces the frontend's per-article `Promise.all` invoke fan-out (one IPC round-trip instead of N, with a graceful fallback for older backends). The RSS auto-refresh interval also pauses when the tab is hidden.
- **Initial bundle is meaningfully smaller / first paint faster** — All six i18n locale dictionaries (~29k lines total) and the full 5000-line built-in theme catalog were statically imported and evaluated at startup even though only one is used. Locales are now lazy-loaded (code-split per locale, English as the synchronous fallback) and the theme catalog loads on demand. Also removed the `vite.config.ts` `manualChunks` rule that was folding `React.lazy` tab chunks back into the main bundle, defeating code-splitting.
- **Fixed Brave Search always failing ("Connection failed")** — The backend sent `Accept-Encoding: gzip` but `reqwest` is built without the `gzip` feature, so Brave's compressed response was passed to `.json()` as binary garbage and parsing always failed. Removed the header so Brave returns plain JSON.
