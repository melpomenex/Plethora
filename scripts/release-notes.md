### Performance

- **Binary IPC for file reads** — PDF byte ranges and whole-document reads now cross the Rust↔WebView bridge as raw bytes (`ArrayBuffer`) instead of JSON number arrays / base64 strings. Each 512 KB PDF page-fetch previously serialized to ~1.8 MB of JSON text and re-parsed in the webview — the dominant cost of PDF paging on Android; whole-file reads paid a 33% base64 inflation plus an `atob` pass on desktop. Text consumers switched from `atob` to `TextDecoder`, which also fixes mojibake for non-ASCII characters in imported HTML. The Android 16 MiB inline-read guard is preserved.
- **Queue mutations apply locally instead of full reloads** — postpone/suspend/delete now patch the affected item in place instead of re-transferring the entire queue after every action (8 full-reload call sites removed; queue views reconcile with a fresh listing when refocused). This is the dominant queue win, and it removes flicker on every action. Also fixes a latent bug where smart-postponing a *document* was routed to the learning-item lookup and failed with NotFound.
- **Smaller, better-split startup bundle** — The entry chunk drops from 1,444 KB to 1,308 KB: the full 65-theme registry was being merged into the startup bundle by a static+dynamic dual import in `ThemeContext` (the intended lazy load was silently defeated); fallback themes now live in their own module. Settings went from one 961 KB chunk to a 43 KB shell with 17 per-section lazy chunks (the 511 KB handbook only loads if opened). The duplicated PDF.js worker build is gone (~1.06 MB saved; one worker asset serves the worker-port, workerSrc-fallback, and PWA paths). A `check-bundle-budget` script wired into `build:check` fails the build on size regressions.
- **Mobile queue is virtualized** — The mobile queue list previously mounted a DOM row for every item; above 20 items it now windows rows through the same virtual list as the desktop queue (preserving swipe gestures, pull-to-refresh, and the scroll-restore contract), keeping large queues smooth on Android.
- **Blocking work off the async runtime** — Document file reads use async I/O and CPU-bound PDF text extraction runs on the blocking thread pool in all four extraction paths (three ran synchronously on tokio workers), so a large import or extraction no longer stalls unrelated IPC commands. Whole-store zustand subscriptions in the queue/review/settings hot paths were converted to selectors, trimming unnecessary re-renders.

### Fixed & Improved

- **EPUB reader no longer snaps back while scrolling** — After jumping to a chapter via the table of contents, scrolling would yank the view back to the section start on every mobile viewport resize (address bar show/hide, keyboard). epub.js re-displays the current location CFI on resize; the viewer now suppresses that re-display while you're actively scrolling and corrects the layout with your live position once you stop.
- **"Cannot read properties of undefined (reading 'concat')" on marking an EPUB read** — Rating an EPUB document as read on mobile tore down the reader while epub.js was still generating page locations, and a queued step then read a destroyed array. The viewer now waits for location generation to settle before destroying the book, so the teardown is clean.
- **Queue loads on app open without tapping the Queue tab** — On a cold start where the Queue tab wasn't the foreground tab, the queue never loaded until you manually switched to it (stuck on "Loading…"). The queue is now hydrated at boot regardless of which tab is visible.
